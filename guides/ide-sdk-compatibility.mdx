Most tools connect to TokenLab by changing an API key and base URL. The exact setup depends on which API format the tool can use.

| API format | Base URL | Common clients |
| --- | --- | --- |
| OpenAI-compatible Chat Completions | `https://api.tokenlab.sh/v1` | OpenAI SDKs, many chat apps and frameworks |
| OpenAI Responses | `https://api.tokenlab.sh/v1` | Responses clients and tools built around Responses events |
| Anthropic Messages | `https://api.tokenlab.sh` | Anthropic SDKs and Claude-oriented tools |
| Gemini | `https://api.tokenlab.sh` | Gemini REST and SDK clients that allow a custom host |

The selected model must list the same format in `accepted_request_formats`. See [API formats](/guides/api-formats) for examples.

## Compatibility labels

| Label | Meaning |
| --- | --- |
| **Works** | The repository includes a TokenLab configuration that matches the tool's documented custom-provider options |
| **Works with limits** | Core requests work, but some tool-managed or vendor-specific features stay with the tool's own service |
| **Experimental** | The setup depends on an undocumented or changing custom-host option and may break after a tool update |

These labels describe the setup documented here, not every feature or plugin offered by a third-party product.

## What a custom API key does not replace

Some products mix model calls with features hosted by the product vendor. A TokenLab key can power the model requests exposed through BYOK settings, but it does not replace unrelated subscriptions, autocomplete services, account features, or proprietary extensions.

When a tool update changes its configuration, use the current integration page rather than copying an old environment-variable snippet from elsewhere.

## Before depending on a feature

- Confirm the tool allows a custom base URL for the format you need.
- Confirm the model lists that format in `accepted_request_formats`.
- Test streaming and tool calls if your workflow requires them.
- Keep the API key on a trusted machine or server.
- Record the Request ID when reporting a failure.
