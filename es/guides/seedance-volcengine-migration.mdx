---
title: "Migrar Seedance desde Volcengine"
description: "Migra tareas Seedance e integraciones de materiales con formato Volcengine a TokenLab con cambios mínimos."
---

Usa esta guía si tu aplicación ya envía solicitudes Seedance con formato Volcengine. Puedes conservar los nombres de Action, `Version=2024-01-01`, `content[]`, los cuerpos PascalCase de materiales y el sobre de respuesta de Volcengine. Solo deben cambiar el endpoint y la autenticación.

## Qué cambia

| Elemento | Cliente Volcengine existente | TokenLab |
| --- | --- | --- |
| URL base | `Volcengine API` | `https://api.tokenlab.sh/` |
| Autenticación | `AK/SK` | `Authorization: Bearer <TOKENLAB_API_KEY>` |
| Solicitud Action | `Action`, `Version` | `Action`, `Version` |
| Cuerpo de tarea | `content[]` | `content[]` |
| Cuerpo de material | `PascalCase` | `PascalCase` |
| Resultado asíncrono | `ID de tarea` | `cgt-...` + Sondeo |

Las solicitudes que solo contienen firma AK/SK devuelven `401 AuthenticationError`. Los clientes Action pueden usar `POST /?Action=...&Version=2024-01-01`; `POST /api/v3?Action=...&Version=2024-01-01` sigue disponible. Los clientes REST usan `/api/v3/contents/generations/tasks`.

## Formato de solicitud y ciclo de vida de tareas

Si tu integración ya envía solicitudes Seedance estilo Volc, puedes usar el endpoint compatible en vez de transformar el body para `/v1/videos/generations`. Envía tu API key de TokenLab como `Authorization: Bearer ...`, usa `POST /api/v3/contents/generations/tasks` para creación REST o `/api/v3?Action=CreateContentsGenerationsTasks&Version=2024-01-01` para solicitudes Action. La creación devuelve un ID `cgt-...`; los estados usan `queued`, `running`, `succeeded`, `failed`, `cancelled` o `expired`.

Este endpoint acepta elementos `content[]` como `text`, `image_url`, `video_url`, `audio_url` y `draft_task`. `callback_url` recibe el mismo objeto de consulta en cada cambio a `queued`, `running`, `succeeded`, `failed` o `expired`; `succeeded` y `failed` se reintentan hasta tres veces tras cinco segundos. Conserva el sondeo como recuperación.

No reutilices el struct de `/v1/tasks/{id}` para v3. v1 usa `pending`, `processing`, `completed` y `failed`; v3 usa `queued`, `running`, `succeeded`, `failed`, `cancelled` y `expired`. En v3, `duration` es una cadena y `error` solo aparece al fallar.

Para recuperarte tras una desconexión, envía un `Idempotency-Key` único en la creación REST. El mismo body y key devuelven el mismo ID `cgt-...`; un body diferente con la misma clave devuelve `409`.

## Actions de tareas

| Action | Elemento | JSON |
| --- | --- | --- |
| `CreateContentsGenerationsTasks` | Crear una tarea de video | `model`, `content[]` |
| `GetContentsGenerationsTask` | Obtener una tarea | `TaskId` |
| `ListContentsGenerationsTasks` | Listar tareas | Filtros, paginación |
| `DeleteContentsGenerationsTasks` | Cancelar o eliminar una tarea | `TaskId` |

## Ejemplo REST mínimo

```bash
curl 'https://api.tokenlab.sh/api/v3/contents/generations/tasks' \
  -H "Authorization: Bearer $TOKENLAB_API_KEY" \
  -H "Idempotency-Key: $CLIENT_JOB_ID" \
  -H "Content-Type: application/json" \
  -d '{
    "model":"seedance-2.0",
    "content":[
      {"type":"text","text":"A cinematic product reveal"},
      {"type":"image_url","role":"reference_image","image_url":{"url":"https://example.com/reference.png"}}
    ],
    "ratio":"16:9",
    "duration":5,
    "resolution":"720p"
  }'
```

## Lista de comprobación de migración

1. Cambia el host de la API a `https://api.tokenlab.sh`.
2. Sustituye la firma AK/SK por una clave API Bearer de TokenLab.
3. Conserva Action, versión y mayúsculas del cuerpo existentes.
4. Usa el mismo `ProjectName` en solicitudes relacionadas de materiales y verificación.
5. Guarda los ID de tarea, grupo y material devueltos por TokenLab.
6. Verifica creación, polling, listado y errores antes de mover tráfico de producción.
