<Note>
Esta guía es para usuarios de **OpenClaw autohospedado** que desean conectar TokenLab como su proveedor de IA.
</Note>

## Recomendado: instala el plugin

Para la ejecución estándar de agentes en OpenClaw, instala el plugin de proveedor de TokenLab:

```bash
openclaw plugins install @tokenlabai/openclaw-provider
openclaw onboard --tokenlab-api-key "$TOKENLAB_API_KEY"
```

El plugin obtiene el catálogo activo de modelos de chat de TokenLab y conserva 18 modelos de respaldo para el descubrimiento sin conexión. Los modelos usan el formato `tokenlab/<model-id>`.

[Paquete npm](https://www.npmjs.com/package/@tokenlabai/openclaw-provider) · [Ficha en ClawHub](https://clawhub.ai/tokenlabai/plugins/openclaw-provider) · [Código fuente](https://github.com/hedging8563/tokenlab-openclaw-provider)

## Configuración manual del proveedor

Usa las entradas manuales de `models.providers` que aparecen a continuación solo cuando necesites rutas independientes para **Responses API**, **Claude nativo**, **Gemini nativo** o **MiniMax nativo**.

Si eliges la configuración manual, configurar únicamente `tokenlab` es suficiente. Añade los otros providers solo cuando necesites explícitamente el comportamiento de **Responses API**, **Claude nativo**, **Gemini nativo** o **MiniMax nativo**.

| Proveedor | OpenClaw `api` | Ideal para | baseUrl |
|----------|----------------|------------|---------|
| `tokenlab` | `openai-completions` | GPT, DeepSeek, Qwen y la mayoría de las llamadas compatibles con OpenAI | `https://api.tokenlab.sh/v1` |
| `tokenlab-responses` | `openai-responses` | Flujos de trabajo de OpenAI Responses que esperan la semántica de `/v1/responses` | `https://api.tokenlab.sh/v1` |
| `tokenlab-claude` | `anthropic-messages` | API nativa de Claude Messages | `https://api.tokenlab.sh` |
| `tokenlab-gemini` | `google-generative-ai` | Formato nativo de la API de Gemini | `https://api.tokenlab.sh` |
| `tokenlab-minimax` | `anthropic-messages` | Enrutamiento nativo de MiniMax | `https://api.tokenlab.sh` |

<Warning>
Usa el sufijo `/v1` solo para `openai-completions` y `openai-responses`.

Los providers nativos como `anthropic-messages` y `google-generative-ai` deben usar `https://api.tokenlab.sh` sin `/v1`, de lo contrario OpenClaw puede construir una ruta upstream incorrecta.
</Warning>

## Requisitos previos

- Una instancia de OpenClaw autohospedada
- Una TokenLab API Key — [Get one here](https://tokenlab.sh/dashboard)

## Configuración

Edita tu configuración de OpenClaw:

- **Autohospedado**: `~/.openclaw/openclaw.json`

Agrega los providers de TokenLab bajo `models.providers`:

```json5
{
  agents: {
    defaults: {
      model: {
        primary: "tokenlab-claude/claude-sonnet-4-6"
      }
    }
  },
  models: {
    mode: "merge",
    providers: {
      tokenlab: {
        api: "openai-completions",
        baseUrl: "https://api.tokenlab.sh/v1",
        apiKey: "sk-your-tokenlab-key",
        models: [
          { id: "gpt-4o", name: "GPT-4o" },
          { id: "deepseek-r1", name: "DeepSeek R1" },
          { id: "qwen3-coder-flash", name: "Qwen 3 Coder Flash" }
        ]
      },
      "tokenlab-responses": {
        api: "openai-responses",
        baseUrl: "https://api.tokenlab.sh/v1",
        apiKey: "sk-your-tokenlab-key",
        models: [
          { id: "gpt-4o", name: "GPT-4o (Responses)" },
          { id: "gpt-5.2", name: "GPT-5.2 (Responses)" }
        ]
      },
      "tokenlab-claude": {
        api: "anthropic-messages",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "sk-your-tokenlab-key",
        models: [
          { id: "claude-sonnet-4-6", name: "Claude Sonnet 4.6" },
          { id: "claude-opus-4-6", name: "Claude Opus 4.6" }
        ]
      },
      "tokenlab-gemini": {
        api: "google-generative-ai",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "sk-your-tokenlab-key",
        models: [
          { id: "gemini-3.5-flash", name: "Gemini 3.5 Flash" },
          { id: "gemini-2.5-pro", name: "Gemini 2.5 Pro" }
        ]
      },
      "tokenlab-minimax": {
        api: "anthropic-messages",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "sk-your-tokenlab-key",
        models: [
          { id: "minimax-m3", name: "MiniMax M3" }
        ]
      }
    }
  }
}
```

<Info>
Los 5 providers usan la **misma API Key**. Solo necesitas una cuenta de TokenLab.
</Info>

<Info>
Los arrays `models` de arriba solo muestran ejemplos comunes. Añade más IDs de modelos a cada provider según sea necesario.
</Info>

## Uso de modelos

OpenClaw sigue referenciando modelos con el formato `provider/model`:

```json5
{
  agents: {
    defaults: {
      model: {
        primary: "tokenlab-gemini/gemini-3.5-flash"
      }
    }
  }
}
```

### Ejemplos de modelos

| Proveedor | Referencia del modelo | Descripción |
|----------|-----------------------|-------------|
| `tokenlab` | `tokenlab/gpt-4o` | Ruta compatible con OpenAI |
| `tokenlab` | `tokenlab/deepseek-r1` | Modelo de razonamiento DeepSeek |
| `tokenlab-responses` | `tokenlab-responses/gpt-4o` | Ruta de Responses API |
| `tokenlab-claude` | `tokenlab-claude/claude-sonnet-4-6` | Ruta nativa de Claude Messages |
| `tokenlab-gemini` | `tokenlab-gemini/gemini-3.5-flash` | Ruta nativa de Gemini |
| `tokenlab-minimax` | `tokenlab-minimax/minimax-m3` | Ruta nativa de MiniMax |

Explora todos los modelos disponibles en [tokenlab.sh/models](https://tokenlab.sh/es/models).

## Cuándo usar cada proveedor

- `tokenlab`: elección predeterminada para la mayoría de los casos de uso generales de agentes y chat.
- `tokenlab-responses`: úsalo cuando tu flujo de trabajo en OpenClaw dependa explícitamente de la semántica de OpenAI Responses.
- `tokenlab-claude`: úsalo cuando quieras el comportamiento nativo de Messages de Claude.
- `tokenlab-gemini`: úsalo cuando necesites el formato de request/response nativo de Gemini o integraciones existentes al estilo Gemini.
- `tokenlab-minimax`: úsalo cuando quieras MiniMax en su ruta nativa.

Si no necesitas el comportamiento nativo de Gemini, aún puedes llamar a modelos de Gemini a través de `tokenlab/gemini-*` en la ruta compatible con OpenAI.

## Errores comunes

<AccordionGroup>
  <Accordion title="Aún usando el antiguo array top-level providers">
    La documentación actual de OpenClaw usa `models.providers`. Si mantienes el formato anterior del array top-level `providers`, OpenClaw puede ignorar la configuración o no resolver los prefijos de provider como se espera.
  </Accordion>
  <Accordion title="Olvidar /v1 en tokenlab-responses">
    `openai-responses` se mapea a la ruta `/v1/responses` de TokenLab, por lo que `tokenlab-responses` debe usar `https://api.tokenlab.sh/v1`.
  </Accordion>
  <Accordion title="Agregar /v1 a tokenlab-claude, tokenlab-gemini o tokenlab-minimax">
    `anthropic-messages` y `google-generative-ai` deben usar `https://api.tokenlab.sh` sin `/v1`. Agregar `/v1` puede producir rutas de solicitud incorrectas.
  </Accordion>
  <Accordion title="¿OpenClaw aún soporta Gemini nativo?">
    Sí. La documentación actual de OpenClaw todavía incluye el provider integrado `google` y también soporta providers personalizados usando `api: "google-generative-ai"`. Así que `tokenlab-gemini` sigue siendo una ruta Gemini nativa válida para los usuarios de OpenClaw.
  </Accordion>
</AccordionGroup>

## Verificar la configuración

Después de guardar la configuración, reinicia tu instancia de OpenClaw y prueba con un mensaje simple. Si ves una respuesta, el provider está configurado correctamente.

```bash
# Autoalojado: reinicia el servicio
systemctl --user restart openclaw    # Linux
launchctl stop cc.tokenlab.openclaw && launchctl start cc.tokenlab.openclaw  # macOS
```
