## Descripción general

Dify funciona bien con TokenLab a través de su flujo de proveedor de modelos compatible con OpenAI.

Esta es una ruta de integración orientada a chat-completions. No debe interpretarse como una garantía de que Dify expone las mismas respuestas o comportamiento de WebSocket que las integraciones dedicadas de Codex.

Para las versiones actuales de Dify, la ruta más segura suele ser:
- elegir el proveedor **OpenAI** integrado
- configurar tu API key de TokenLab
- establecer una URL base personalizada de `https://api.tokenlab.sh/v1`

<Note>
Algunas versiones antiguas de Dify exponen esto como `OpenAI-API-compatible` en lugar del proveedor `OpenAI` integrado con un campo de URL base personalizada. Si tu interfaz de Dify se ve diferente, utiliza el flujo de proveedor personalizado compatible con OpenAI más cercano disponible en esa versión.
</Note>

<Note>
**Tipo**: Framework o Plataforma

**Ruta principal**: Ruta de chat compatible con OpenAI

**Nivel de soporte**: Soportado con límites de alcance
</Note>

## Requisitos previos

- Cuenta de TokenLab con acceso a la API
- Dify Cloud o Dify autohospedado

## Pasos de configuración

### Paso 1: Obtén tu API Key

1. Inicia sesión en el [TokenLab Dashboard](https://tokenlab.sh/dashboard)
2. Abre [API Keys](https://tokenlab.sh/dashboard/api)
3. Crea o copia una API key que comience con `sk-`

### Paso 2: Configura el proveedor

<Steps>
  <Step title="Abrir proveedores de modelos">
    En Dify, ve a **Settings** → **Model Providers**
  </Step>
  <Step title="Seleccionar OpenAI">
    Abre la configuración del proveedor **OpenAI**. Si tu versión de Dify no ofrece una URL base personalizada aquí, utiliza la opción de proveedor personalizado compatible con OpenAI expuesta por esa versión.
  </Step>
  <Step title="Ingresar la configuración de TokenLab">
    Utiliza estos valores:

    | Campo | Valor |
    |-------|-------|
    | API Key | `sk-your-tokenlab-key` |
    | API Base URL / Custom Base URL | `https://api.tokenlab.sh/v1` |
  </Step>
  <Step title="Agregar modelos">
    Agrega los modelos que deseas utilizar, por ejemplo:
    - `gpt-5.4`
    - `gpt-5.4-mini`
    - `claude-sonnet-5`
    - `claude-opus-4-8`
    - `gemini-3.5-flash`
    - `gemini-3.1-flash-lite`
    - `deepseek-v4-flash`
  </Step>
</Steps>

### Paso 3: Probar la conexión

1. Elige un modelo como `gpt-5-mini` o `gpt-4o`
2. Envía un prompt de prueba
3. Confirma que Dify recibe una respuesta válida

## Embeddings para bases de conocimiento

Para RAG y la indexación de bases de conocimiento, agrega un modelo de embedding como:
- `text-embedding-3-small`
- `text-embedding-3-large`

Luego, configúralo como el modelo de embedding predeterminado en la base de conocimiento relevante o en la configuración de la aplicación.

## Roles de modelo recomendados

| Caso de uso | Modelos sugeridos |
|----------|------------------|
| Chat predeterminado | `gpt-5.4-mini`, `gpt-5.4`, `claude-sonnet-5` |
| Razonamiento profundo | `gpt-5.5`, `gpt-5.4`, `claude-opus-4-8`, `deepseek-v4-pro` |
| Rápido/económico | `gpt-5.4-mini`, `gemini-3.5-flash`, `deepseek-v4-flash` |
| Embeddings | `text-embedding-3-small`, `text-embedding-3-large` |

## Mejores prácticas

<AccordionGroup>
  <Accordion title="Comienza con el proveedor OpenAI integrado">
    En las versiones más recientes de Dify, el proveedor OpenAI integrado con una URL base personalizada suele ser la configuración más limpia para TokenLab.
  </Accordion>

  <Accordion title="Usa modelos más económicos para iterar">
    Usa `gpt-5.4-mini`, `gemini-3.5-flash` o `deepseek-v4-flash` mientras iteras, luego cambia los flujos de trabajo más pesados a modelos más potentes solo cuando sea necesario.
  </Accordion>

  <Accordion title="Recuerda que Dify suele estar orientado a chat-completions">
    La mayoría de los flujos de Dify utilizan un comportamiento de chat compatible con OpenAI. Si necesitas respuestas específicas de Codex o comportamiento de WebSocket, utiliza las integraciones dedicadas de Codex en lugar de Dify.
  </Accordion>
</AccordionGroup>

## Solución de problemas

<AccordionGroup>
  <Accordion title="Error de conexión">
    - Verifica que la URL base sea exactamente `https://api.tokenlab.sh/v1`
    - Elimina las barras diagonales finales si Dify las duplica
    - Confirma que el servidor de Dify pueda acceder a TokenLab a través de la internet pública
  </Accordion>

  <Accordion title="401 No autorizado">
    - Verifica nuevamente la API key
    - Confirma que la clave esté activa en el dashboard de TokenLab
    - Asegúrate de que el valor pegado en Dify no contenga espacios adicionales ni saltos de línea
  </Accordion>

  <Accordion title="Modelo no encontrado">
    - Verifica el nombre del modelo exactamente
    - Vuelve a agregar la entrada del modelo si la interfaz del proveedor almacenó en caché un valor anterior
    - Verifica la disponibilidad actual del modelo en la documentación o el dashboard de TokenLab
  </Accordion>
</AccordionGroup>
