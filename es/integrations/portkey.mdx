## Descripción general

Portkey Gateway puede enrutar solicitudes a TokenLab como proveedor upstream. La opción predeterminada más segura son las chat completions compatibles con OpenAI; utiliza Responses cuando tu versión de Portkey exponga esa ruta para TokenLab.

<Note>
**Tipo**: AI Gateway

**Rutas principales**: Chat completions compatibles con OpenAI y Responses

**Nivel de soporte**: Ruta soportada
</Note>

## Valores del proveedor

| Campo | Valor |
|-------|-------|
| Provider | `tokenlab` |
| Base URL | `https://api.tokenlab.sh/v1` |
| API key | `sk-your-tokenlab-key` |
| Modelo predeterminado | `gpt-5.4-mini` |

## Chat Completions

Utiliza TokenLab para solicitudes de chat compatibles con OpenAI:

```bash
curl https://your-portkey-gateway.example/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "x-portkey-provider: tokenlab" \
  -H "Authorization: Bearer sk-your-tokenlab-key" \
  -d '{
    "model": "gpt-5.4-mini",
    "messages": [{"role": "user", "content": "Say hello from TokenLab."}]
  }'
```

## Responses

Si tu compilación de Portkey enruta Responses de TokenLab, utiliza `gpt-5.5`, `gpt-5.4` o `gpt-5.4-mini` con `/v1/responses`.

## Nota sobre el endpoint nativo

TokenLab también expone endpoints compatibles con Anthropic Messages y Gemini directamente. La posibilidad de utilizarlos a través de Portkey depende del proveedor de Portkey y del soporte de endpoints en tu versión desplegada.
