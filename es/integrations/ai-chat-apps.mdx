## Descripción general

La mayoría de las aplicaciones de chat con IA generales se conectan a TokenLab a través de la ruta de chat estándar compatible con OpenAI.

En la práctica, esto significa:
- use `https://api.tokenlab.sh/v1` como la URL base a menos que la aplicación solicite explícitamente una URL de endpoint completa
- use su API key de TokenLab como la API key al estilo OpenAI
- elija modelos que la aplicación pueda usar en un flujo de trabajo de chat estándar

<Note>
Las aplicaciones de chat generales suelen estar **orientadas a chat-completions**, no a clientes WebSocket de Codex Responses. Para Codex CLI/App, Cursor u otras herramientas de programación que requieran un comportamiento específico de Responses, utilice las guías de integración dedicadas en su lugar.
</Note>

<Note>
**Tipo**: Aplicación de chat

**Ruta principal**: chat-completions compatible con OpenAI

**Nivel de soporte**: Ruta soportada
</Note>

## Aplicaciones compatibles

| Aplicación | Plataforma | Notas |
|-------------|----------|-------|
| Open WebUI | Web, Autoalojado | Opción popular autoalojada con conexiones compatibles con OpenAI |
| LibreChat | Web, Autoalojado | Espacio de trabajo de chat multiproveedor con endpoints de OpenAI personalizados |
| LobeChat | Web, Escritorio, Autoalojado | Fuerte soporte para proveedores personalizados |
| Cherry Studio | Windows, macOS, Linux | Buen flujo de proveedor compatible con OpenAI |
| Chatbox | Windows, macOS, Linux | Configuración sencilla compatible con OpenAI |
| DeepChat | Windows, macOS, Linux | Cliente de escritorio con ajustes de proveedor compatibles con OpenAI |
| Jan | Escritorio, Autoalojado | Aplicación local con proveedores remotos compatibles con OpenAI |
| TypingMind | Web, Escritorio | Utiliza un estilo de endpoint personalizado |
| NextChat | Web, Autoalojado | Cliente ligero estilo ChatGPT con sobrescritura de URL base |
| ChatWise | Windows, macOS | Patrón estándar de proveedor personalizado |

## Valores de conexión predeterminados

| Campo | Valor |
|-------|-------|
| Base URL | `https://api.tokenlab.sh/v1` |
| API Key | `sk-your-tokenlab-key` |
| Tipo de API | Compatible con OpenAI |

Si una aplicación solicita una **URL de endpoint completa** en lugar de una URL base, utilice:
- Chat Completions: `https://api.tokenlab.sh/v1/chat/completions`

## Ejemplos de configuración de aplicaciones

<Tabs>
  <Tab title="LobeChat">
    **LobeChat autoalojado**

    ```bash
    OPENAI_API_KEY=sk-your-tokenlab-key
    OPENAI_PROXY_URL=https://api.tokenlab.sh/v1
    ```

    **LobeChat Cloud**
    1. Abra **Settings** → **AI Service Provider**
    2. Seleccione **OpenAI**
    3. Ingrese su API key de TokenLab
    4. Establezca el endpoint personalizado en `https://api.tokenlab.sh/v1`
  </Tab>

  <Tab title="Cherry Studio">
    1. Abra **Settings** → **Model Provider**
    2. Añada un proveedor **OpenAI-compatible**
    3. Ingrese:
       - **Name**: TokenLab
       - **API Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
    4. Añada los modelos que desea utilizar
  </Tab>

  <Tab title="Chatbox">
    1. Abra **Settings** → **AI Model**
    2. Elija **OpenAI API Compatible**
    3. Ingrese:
       - **API Host**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
       - **Model**: `gpt-5.4-mini` o `claude-sonnet-5`
  </Tab>

  <Tab title="TypingMind">
    1. Abra **Settings**
    2. Elija **Custom Endpoint**
    3. Ingrese:
       - **Endpoint URL**: `https://api.tokenlab.sh/v1/chat/completions`
       - **API Key**: `sk-your-tokenlab-key`
    4. Configure los modelos que desea exponer
  </Tab>

  <Tab title="Open WebUI">
    1. Abra **Admin Settings** → **Connections**
    2. Añada una conexión **OpenAI-compatible**
    3. Ingrese:
       - **Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
    4. Guarde y seleccione los modelos que desea exponer
  </Tab>

  <Tab title="DeepChat">
    1. Abra **Settings** -> **Model Provider**
    2. Añada un proveedor compatible con OpenAI
    3. Ingrese:
       - **Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
       - **Model**: `gpt-5.4-mini`
    4. Guarde y realice un chat de prueba
  </Tab>

  <Tab title="Jan">
    1. Abra **Settings** -> **Providers**
    2. Añada un proveedor remoto compatible con OpenAI
    3. Ingrese:
       - **Provider name**: TokenLab
       - **Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
    4. Seleccione `gpt-5.4-mini` u otro modelo de TokenLab
  </Tab>

  <Tab title="LibreChat">
    Añada un endpoint compatible con OpenAI en la configuración de su proveedor de LibreChat y apúntelo a:

    ```yaml
    customEndpoints:
      - name: TokenLab
        apiKey: '${OPENAI_API_KEY}'
        baseURL: 'https://api.tokenlab.sh/v1'
        models:
          default: ['gpt-5.4-mini', 'gpt-5.4', 'claude-sonnet-5']
          fetch: false
    ```
  </Tab>
</Tabs>

## Consejos

<AccordionGroup>
  <Accordion title="Prefiera la URL base cuando la aplicación lo soporte">
    La mayoría de las aplicaciones son más fáciles de configurar y menos propensas a errores cuando se proporciona `https://api.tokenlab.sh/v1` como URL base en lugar de una URL de endpoint completa.
  </Accordion>

  <Accordion title="Use modelos más pequeños primero">
    Comience con `gpt-5.4-mini` o `deepseek-v4-flash` para el chat diario, luego pase a `gpt-5.4` o `claude-opus-4-8` para tareas de razonamiento más complejas.
  </Accordion>

  <Accordion title="Mantenga las herramientas de programación separadas">
    Las aplicaciones de chat generales y los agentes de programación a menudo necesitan un comportamiento de endpoint diferente. Mantenga las herramientas estilo Codex/Cursor en sus páginas de integración dedicadas.
  </Accordion>
</AccordionGroup>

## Solución de problemas

<AccordionGroup>
  <Accordion title="Error de conexión">
    - Verifique que la URL base sea exactamente `https://api.tokenlab.sh/v1`
    - Elimine las barras diagonales finales si la aplicación añade rutas automáticamente
    - Si la aplicación requiere una URL de endpoint completa, use `https://api.tokenlab.sh/v1/chat/completions`
  </Accordion>

  <Accordion title="401 No autorizado">
    - Verifique dos veces su API key
    - Confirme que la clave esté activa en el panel de control de TokenLab
    - Asegúrese de que no haya espacios adicionales ni saltos de línea
  </Accordion>

  <Accordion title="Modelo no disponible">
    - Verifique el nombre del modelo exactamente
    - Pruebe con un valor predeterminado ampliamente compatible como `gpt-5.4-mini`, `deepseek-v4-flash` o `claude-sonnet-5`
    - Compruebe la disponibilidad actual en la documentación o el panel de control de TokenLab
  </Accordion>
</AccordionGroup>
