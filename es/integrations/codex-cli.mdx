## Visión general

Codex CLI se conecta a TokenLab mediante `/v1/responses`. El modelo elegido debe incluir `openai_responses` en `tokenlab.accepted_request_formats`; las funciones pueden variar según el modelo.

La compactación remota de Codex CLI es compatible en `POST /v1/responses/compact`. Codex envía el `model` de la sesión actual en `body.model` para `/compact` y auto-compactación, así que el modelo que quieras usar para compactar debe estar disponible en la ruta Responses. No configures `/v1/compact`.

## Requisitos del sistema

Sigue la [guía CLI oficial](https://learn.chatgpt.com/docs/codex/cli) para macOS, Linux o Windows. Windows nativo y WSL son entornos distintos; consulta la [guía Windows](https://learn.chatgpt.com/docs/windows/windows-sandbox). npm es una opción, no un requisito de los binarios nativos.

## Instalación

```bash
npm install -g @openai/codex@0.149.0
```

Verificar la instalación:

```bash
codex --version
```

## Configuración

### Paso 1: Establecer la clave de API

Sigue los pasos de terminal de [inicio rápido](/es/quickstart) para macOS, Linux, WSL o Windows PowerShell y define `TOKENLAB_API_KEY` sin dejar la clave en el historial. Inicia Codex desde esa terminal. Para uso persistente, utiliza un gestor local de secretos; no añadas la clave en texto plano al perfil del shell.

### Paso 2: Configurar tokenlab.config.toml

Con Codex **0.149.0**, usa un archivo `tokenlab.config.toml` independiente dentro del `CODEX_HOME` activo (normalmente `~/.codex`). Créalo solo si el nombre está libre o respalda el perfil TokenLab existente antes de editarlo. `codex --profile tokenlab` lo carga explícitamente sin cambiar `config.toml`, `auth.json`, cuentas ni permisos. No uses la tabla antigua `[profiles.tokenlab]`. Inicia sin ese perfil para volver a tu configuración habitual. Consulta la [configuración oficial de perfiles](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles).

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"

[model_providers.tokenlab]
env_key = "TOKENLAB_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000
```

Este modo WebSocket es un puente Responses-over-WebSocket para clientes Codex. Solo acepta eventos oficiales `response.create`; `stream` es implícito y `background` y `response.cancel` no están disponibles en este transporte. No es la API OpenAI Realtime y no acepta `session.update`, `conversation.item.*`, `input_audio_buffer.*`, audio binario ni sobres Realtime anidados `response.create.response`.

<Note>
Crea el archivo de configuración elegido si no existe. Tras editarlo, inicia una nueva sesión con el comando correspondiente de abajo.
</Note>

Codex actual usa `wire_api = "responses"`, no `chat/completions`. Omite `requires_openai_auth` o usa false para que el proveedor utilice `env_key`.

<Note>
Las solicitudes Responses no se convierten a Chat Completions. Los campos opcionales y futuros dependen del modelo elegido.
</Note>

## Uso básico

**Iniciar modo interactivo:**

```bash
codex --profile tokenlab
```

**Comando directo:**

```bash
codex --profile tokenlab "Fix the bug in main.py line 42"
```

**Especificar modelo:**

```bash
codex --profile tokenlab -m gpt-5.6-sol "Build a REST API server"
```

## Elegir un modelo

Elige un modelo cuyo `tokenlab.accepted_request_formats` incluya actualmente `openai_responses`. Compara modelos con tus tareas y consulta precios en la [página de modelos](https://tokenlab.sh/es/models).

## Comandos interactivos

| Comando | Descripción |
|---------|-------------|
| `/help` | Mostrar ayuda |
| `/exit` or `Ctrl+C` | Salir |
| `/clear` | Borrar conversación |
| `/status` | Mostrar el modelo activo, los permisos y el uso de tokens |
| `/model <name>` | Cambiar modelo |

## Verificar configuración

Comprueba solo si la variable de entorno está definida, sin imprimir su valor. Esta comprobación no valida la clave:

```bash
if [ -n "${TOKENLAB_API_KEY:-}" ]; then
  printf '%s\n' 'TOKENLAB_API_KEY is set'
else
  printf '%s\n' 'TOKENLAB_API_KEY is not set'
fi
```

Inicia Codex y ejecuta `/status` para comprobar el modelo activo y los permisos. Si usas un perfil, inicia ese mismo perfil. Consulta el [comando oficial de estado](https://learn.chatgpt.com/docs/developer-commands?surface=cli#inspect-the-session-with-status).

Cuando quieras enviar una solicitud real, ejecuta el siguiente comando. Utiliza tu saldo de TokenLab. Comprueba la respuesta y su registro en [Solicitudes](https://tokenlab.sh/dashboard/runs?section=requests). Una variable definida o un inicio correcto no demuestra por sí solo que una solicitud haya finalizado correctamente.

```bash
codex --profile tokenlab "Reply only with OK. Do not use tools or modify files."
```

## Casos de uso comunes

**Revisión de código:**

```bash
git diff | codex --profile tokenlab "Review these code changes"
```

**Generar mensajes de commit:**

```bash
git diff --staged | codex --profile tokenlab "Generate a commit message for these changes"
```

**Corregir errores:**

```bash
codex --profile tokenlab "Fix the TypeScript errors in src/components/"
```

**Explicar código:**

```bash
cat main.py | codex --profile tokenlab "Explain what this code does"
```

## Solución de problemas

<AccordionGroup>
  <Accordion title="Error de conexión">
    - Verifica que `base_url` en tokenlab.config.toml sea exactamente `https://api.tokenlab.sh/v1`
    - Comprueba la conectividad de red
    - Asegúrate de que no haya interferencia de proxy
  </Accordion>

  <Accordion title="Autenticación fallida">
    Después de actualizar a Codex 0.149.0 o una versión posterior, pueden aparecer los errores `API_KEY_REQUIRED` o `401 Unauthorized` si un proveedor personalizado depende únicamente de `auth.json` y `requires_openai_auth` no está definido o está en `false`. Esta guía usa `env_key` para leer la clave de `TOKENLAB_API_KEY` y no depende de `auth.json`. Mantén `requires_openai_auth` sin definir o en `false`; esta configuración no requiere cambiarlo a `true` ni sobrescribir `auth.json`.

    - Verifica que la configuración o el perfil que realmente utilizas incluya `env_key = "TOKENLAB_API_KEY"`. Si guardaste la configuración en `tokenlab.config.toml`, inicia Codex con `codex --profile tokenlab`
    - Verifica que `TOKENLAB_API_KEY` esté definida en el terminal desde el que inicias Codex. Después de establecer la variable, reinicia Codex desde ese terminal
    - Comprueba que la clave comience con `sk-`
    - Asegúrate de que la clave esté activa en el panel de TokenLab
  </Accordion>

  <Accordion title="Modelo no encontrado">
    - Revisa que el nombre del modelo coincida exactamente
    - Verifica la disponibilidad del modelo en [tokenlab.sh/en/models](https://tokenlab.sh/es/models)
  </Accordion>

  <Accordion title="Campo nativo de Responses rechazado">
    - Algunos campos solo están disponibles en `/v1/responses` cuando TokenLab puede garantizar ese comportamiento para el modelo y la ruta seleccionados
    - Si ves `unsupported_request_field`, elimina ese campo o cambia a un flujo de trabajo que no dependa de él
  </Accordion>

  <Accordion title="/compact o auto-compactación falla">
    - Codex CLI llama a `POST /v1/responses/compact`, no a `/v1/compact`
    - La solicitud de compactación usa el `model` de la sesión actual, por lo que ese modelo debe estar disponible en la ruta Responses
    - Mantén `wire_api = "responses"` y `base_url = "https://api.tokenlab.sh/v1"`
  </Accordion>
</AccordionGroup>
