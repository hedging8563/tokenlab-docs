## Resumen

Usa este endpoint para sesiones en tiempo real como reconocimiento de voz en streaming, síntesis de voz, traducción de voz o modelos multimodales en tiempo real. Una solicitud `GET` normal devuelve los metadatos del endpoint, mientras que una solicitud de actualización a WebSocket abre una sesión en tiempo real para el modelo seleccionado.

## Superficie admitida

TokenLab expone un endpoint WebSocket en tiempo real en `GET /v1/realtime` para comprobaciones de metadatos y upgrades WebSocket. Trátalo como un WebSocket subset: reenvía eventos de modelos realtime compatibles y no admite superficies auxiliares REST de OpenAI Realtime como creación de sesiones, `client_secrets`, API de control de llamadas `Calls` ni legacy beta session APIs.

En apps web o móviles, mantén las claves API de larga duración en tu servidor. Este endpoint no emite Realtime client secrets de corta duración.

<Note>Los agentes deben descubrir modelos con soporte realtime en `/v1/models` antes de abrir el socket.</Note>

## Conexión

<ParamField query="model" type="string" required>
  ID del modelo en tiempo real. Usa un modelo cuyos detalles indiquen compatibilidad en tiempo real.
</ParamField>

<ParamField header="Authorization" type="string" required>
  Clave API Bearer. Los clientes WebSocket deben enviar `Authorization: Bearer sk-your-api-key` durante el upgrade.
</ParamField>

<RequestExample>
```javascript JavaScript
import WebSocket from 'ws';

const socket = new WebSocket('wss://api.tokenlab.sh/v1/realtime?model=gpt-realtime', {
  headers: { Authorization: 'Bearer sk-your-api-key' }
});

socket.on('open', () => {
  socket.send(JSON.stringify({
    type: 'session.update',
    session: { modalities: ['text', 'audio'] }
  }));
});

socket.on('message', (data) => {
  console.log('realtime event', data.toString());
});
```

```bash cURL
curl "https://api.tokenlab.sh/v1/realtime" \
  -H "Authorization: Bearer sk-your-api-key"
```
</RequestExample>

## Mensajes

TokenLab transmite los mensajes WebSocket entre tu cliente y el modelo en tiempo real seleccionado. Usa el formato de eventos documentado para ese modelo e incluye `model` en la cadena de consulta en lugar de en cada evento.

## Facturación y cierre

Las sesiones se cobran del saldo de tu clave API: TokenLab reserva una estimación al inicio, luego liquida el uso real al finalizar y reembolsa la diferencia.

Cierra el socket del cliente cuando la sesión haya terminado. Si el servicio cierra la sesión primero, TokenLab envía a tu cliente un evento/código de cierre seguro cuando es posible.
