## Resumen

Estos endpoints son para equipos que ya usan la forma de tarea Seedance estilo Volc. La autenticación usa tu API key Bearer de TokenLab. El ID devuelto empieza con `cgt-`; consulta el estado hasta que `status` sea `succeeded`, `failed`, `cancelled` o `expired`.

<Warning>
No reutilices el enum ni el struct de respuesta de v1. `/v1/tasks/{id}` usa `pending`, `processing`, `completed` y `failed`; este endpoint usa el enum v3 indicado arriba. En v3, `duration` es una cadena cuando aparece y `error` solo aparece si la tarea falla.
</Warning>

Ver también [Modelos de video Seedance 2.0](/es/guides/seedance-2-video) y [Generación de video](/es/guides/video-generation).

## Forma de respuesta

La respuesta usa `queued`, `running`, `succeeded`, `failed`, `cancelled` o `expired`. Las tareas exitosas devuelven `content.video_url`; opcionalmente aparecen `content.last_frame_url`, campos oficiales de generación y `usage`. `error` solo se incluye al fallar. No se añaden campos TokenLab como `progress`, `return_last_frame`, `watermark`, `priority` o `camera_fixed`.

## Ejemplo

```bash
curl https://api.tokenlab.sh/api/v3/contents/generations/tasks/cgt-20260102030405-a1b2c \
  -H "Authorization: Bearer $TOKENLAB_API_KEY"
```
