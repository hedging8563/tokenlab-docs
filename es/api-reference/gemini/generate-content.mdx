---
title: "Generar Contenido"
openapi: "/openapi/es.json POST /v1beta/models/{model}:generateContent"
description: "Genera contenido utilizando el formato de la API de Google Gemini"
---

Usa los formatos de solicitud y respuesta de Gemini con un modelo devuelto por Gemini Models API. Se aceptan nombres ProtoJSON lowerCamelCase y sus equivalentes proto snake_case. Los campos opcionales y valores admitidos dependen del modelo elegido.

## Parámetros de Ruta

<ParamField path="model" type="string" required>
  Nombre del modelo (por ejemplo, `gemini-2.5-pro`, `gemini-3.5-flash`).
</ParamField>

## Parámetros de Consulta

<ParamField query="key" type="string">
  Clave API (alternativa a la autenticación por encabezado).
</ParamField>

## Autenticación

Los endpoints de Gemini admiten múltiples métodos de autenticación:
- Parámetro de consulta `?key=YOUR_API_KEY`
- Encabezado `x-goog-api-key: YOUR_API_KEY`
- Encabezado `Authorization: Bearer YOUR_API_KEY`

## Cuerpo de la Solicitud

<ParamField body="contents" type="array" required>
  Contenido de conversación con `parts` y un `role` opcional. Los medios usan `inlineData` / `inline_data` o `fileData` / `file_data`. Los ID de Files y Cache creados por TokenLab solo pueden usarse en el Workspace al que pertenecen.
</ParamField>

<ParamField body="systemInstruction" type="object">
  Instrucción del sistema para el modelo.
</ParamField>

<ParamField body="generationConfig" type="object">
  Ajustes de generación como `temperature`, `topP`, `topK`, `maxOutputTokens`, `stopSequences`, `candidateCount`, `responseModalities`, `responseMimeType`, `responseSchema` y `thinkingConfig`. También se aceptan los nombres snake_case equivalentes. Los valores y combinaciones dependen del modelo.
</ParamField>

<ParamField body="safetySettings" type="array">
  Configuración de filtros de seguridad.
</ParamField>

## Respuesta

<ResponseField name="candidates" type="array">
  Candidatos de contenido generado.
</ResponseField>

<ResponseField name="usageMetadata" type="object">
  Información de uso de tokens.
</ResponseField>

    api_key="sk-your-api-key",
    transport="rest",
    client_options={"api_endpoint": "api.tokenlab.sh"}

## Ejemplos de entrada multimodal

Para solicitudes multimodales de Gemini, coloca los medios dentro de `contents[].parts[]` usando bytes inline o referencias de archivo basadas en URL.

Categorías multimedia compatibles actualmente en los detalles del modelo de Gemini:
- imagen
- audio
- video

Para medios inline, usa `inlineData` o `inline_data` y pasa los bytes del archivo codificados en Base64.

Para medios mediante URL, usa `fileData` o `file_data` y pasa una URL pública `https`.

### Ejemplo de entrada de imagen

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "Describe esta imagen." },
        {
          "inlineData": {
            "mimeType": "image/jpeg",
            "data": "/9j/4AAQSkZJRgABAQ..."
          }
        }
      ]
    }
  ]
}
```

### Ejemplo de entrada de audio

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "Transcribe y resume este audio." },
        {
          "file_data": {
            "mime_type": "audio/mpeg",
            "file_uri": "https://example.com/sample.mp3"
          }
        }
      ]
    }
  ]
}
```

### Ejemplo de entrada de video

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        { "text": "Describe brevemente este video." },
        {
          "fileData": {
            "mimeType": "video/mp4",
            "fileUri": "https://example.com/sample.mp4"
          }
        }
      ]
    }
  ]
}
```
