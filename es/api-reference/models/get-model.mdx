---
title: "Obtener un modelo"
openapi: "GET /v1/models/{model}"
description: "Obtenga las capacidades, precios y formatos de API de un modelo"
---

## Parámetro de ruta

<ParamField path="model" type="string" required>
  ID del modelo, como `gpt-5.6-terra` o `claude-sonnet-4-6`.
</ParamField>

## Respuesta

<ResponseField name="id" type="string">ID del modelo.</ResponseField>
<ResponseField name="object" type="string">Siempre `model`.</ResponseField>
<ResponseField name="owned_by" type="string">Creador del modelo.</ResponseField>
<ResponseField name="tokenlab" type="object">
  Información del modelo TokenLab, incluyendo capacidades, precios, unidades de facturación, límites de contexto, formatos de API aceptados, operaciones y estado del ciclo de vida.
</ResponseField>

Los campos comunes de `tokenlab` incluyen:

- `capabilities`: capacidades de texto, imagen, video, audio y otras.
- `pricing`: precios públicos actuales.
- `max_input_tokens` y `max_output_tokens`: límites de contexto y de salida.
- `accepted_request_formats`: formatos de API admitidos.
- `supported_operations`: operaciones como texto a imagen o imagen a video.
- `lifecycle`: disponibilidad, fecha de lanzamiento, fecha de obsolescencia o modelo de reemplazo.

Algunos modelos de medios también incluyen un estado de recomendación y tiempo de actualización. Las recomendaciones pueden cambiar según la disponibilidad y el rendimiento, por lo que no debe codificar su orden de forma rígida (hard-code).

## Ejemplo

```bash
curl "https://api.tokenlab.sh/v1/models/gpt-5.6-terra"
```

```json
{
  "id": "gpt-5.6-terra",
  "object": "model",
  "owned_by": "openai",
  "tokenlab": {
    "category": "chat",
    "capabilities": ["coding", "json-mode", "prompt-cache", "reasoning", "tool-use", "vision"],
    "accepted_request_formats": ["openai_chat_completions", "openai_responses"]
  }
}
```

Un modelo desconocido devuelve `404 model_not_found`.
