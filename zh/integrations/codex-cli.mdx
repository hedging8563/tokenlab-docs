## 概述




Codex CLI 可以通过 `/v1/responses` 连接 TokenLab。所选模型的 `accepted_request_formats` 必须包含 `responses`，具体功能仍可能因模型而异。

远程压缩使用 `POST /v1/responses/compact`。Codex 会把当前会话模型放在 `body.model` 中，因此这个模型也必须支持 Responses。不要配置 `/v1/compact`。

## 系统要求

- **OS**：macOS、Linux（官方支持）、Windows 通过 WSL
- **Node.js**：版本 18+
- **npm**：版本 10.x.x 或更高

## 安装

```bash
npm install -g @openai/codex
```

验证安装：

```bash
codex --version
```

## 配置

### 第 1 步：设置 API 密钥

**临时（当前会话）：**

```bash
export OPENAI_API_KEY="sk-your-tokenlab-key"
```

**永久配置：**

添加到 `~/.bashrc`、`~/.zshrc` 或 `~/.bash_profile`：

```bash
export OPENAI_API_KEY="sk-your-tokenlab-key"
```

然后重新加载：

```bash
source ~/.zshrc  # or source ~/.bashrc
```

### 第 2 步：配置 config.toml

编辑 `~/.codex/config.toml`：

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"
plan_mode_reasoning_effort = "xhigh"
model_context_window = 258000
model_auto_compact_token_limit = 232200
sandbox_mode = "danger-full-access"
approval_policy = "never"

personality = "friendly"
service_tier = "fast"

[model_providers.tokenlab]
env_key = "OPENAI_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000

[features]
fast_mode = true
```

此 WebSocket 模式是面向 Codex 客户端的 Responses-over-WebSocket 桥接层。它只接受官方 `response.create` 事件；`stream` 是隐含行为，该 transport 不提供 `background` 或 `response.cancel`。它不是 OpenAI Realtime API，也不接受 `session.update`、`conversation.item.*`、`input_audio_buffer.*`、二进制音频或嵌套的 Realtime `response.create.response` 信封。

<Note>
如果配置文件不存在，请运行 `codex` 一次以生成该文件，然后编辑该文件。在更改 `config.toml` 后需完全重启 Codex，以便重新加载新的提供者设置。
</Note>

<Warning>
Codex 正在弃用对自定义提供者的 `chat/completions` 支持。对于 TokenLab，请保持 `wire_api = "responses"`，除非你有意使用较旧的兼容路径。
</Warning>

<Note>
未知的 Responses 字段可能会继续发送给模型服务，但不保证受支持。TokenLab 不会把 Responses 请求自动改成 Chat Completions。
</Note>

## 基本用法

**启动交互模式：**

```bash
codex
```

**直接命令：**

```bash
codex "Fix the bug in main.py line 42"
```

**指定模型：**

```bash
codex -m gpt-5.6-sol "Build a REST API server"
```

## 选择模型

所选模型的 `accepted_request_formats` 必须包含 `responses`。请用自己的编程任务比较候选模型，当前价格以[模型页](https://tokenlab.sh/zh/models)为准。

## 交互命令

| Command | 说明 |
|---------|------|
| `/help` | 显示帮助 |
| `/exit` 或 `Ctrl+C` | 退出 |
| `/clear` | 清除会话 |
| `/config` | 查看配置 |
| `/model <name>` | 切换模型 |
| `/tokens` | 查看 token 使用情况 |

## 验证配置

```bash
# Check environment variable
echo $OPENAI_API_KEY

# Test API connection
codex "Hello, Codex!"

# View configuration
cat ~/.codex/config.toml
```

## 故障排除

<AccordionGroup>
  <Accordion title="连接错误">
    - 验证 `base_url` 在 config.toml 中是否为准确的 `https://api.tokenlab.sh/v1`
    - 检查网络连接
    - 确保没有代理干扰
  </Accordion>

  <Accordion title="身份验证失败">
    - 验证 `env_key = "OPENAI_API_KEY"` 是否存在于 `~/.codex/config.toml`
    - 验证已设置 `OPENAI_API_KEY` 环境变量
    - 检查密钥是否以 `sk-` 开头
    - 确保密钥在 TokenLab Console中处于激活状态
  </Accordion>

  <Accordion title="模型未找到">
    - 检查模型名称是否完全匹配
    - 验证模型可用性： [tokenlab.sh/en/models](https://tokenlab.sh/zh/models)
  </Accordion>

  <Accordion title="Responses 原生字段被拒绝">
    - `/v1/responses` 的可选字段是否可用，取决于所选模型
    - 如果看到 `unsupported_request_field`，请删除该字段，或改用不需要它的功能
  </Accordion>

  <Accordion title="/compact 或自动压缩失败">
    - Codex CLI 调用 `POST /v1/responses/compact`，不是 `/v1/compact`
    - 压缩请求使用当前会话的 `model`，因此该模型必须在 Responses 路径上可用
    - 保持 `wire_api = "responses"` 和 `base_url = "https://api.tokenlab.sh/v1"`
  </Accordion>
</AccordionGroup>
