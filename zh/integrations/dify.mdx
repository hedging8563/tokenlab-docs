## 概述

使用模型提供商插件 **OpenAI-API-compatible** 将 Dify 连接到 TokenLab。将模型类型设为 **LLM**、**Completion mode** 设为 **Chat**、**API Type** 设为 **Chat Completions API**。本指南使用 Chat Completions。


## 前置要求

- 拥有 API 访问权限的 TokenLab 账户
- Dify Cloud 或自托管 Dify

## 配置步骤

### 第 1 步：获取你的 API 密钥

1. 登录 [TokenLab Console](https://tokenlab.sh/dashboard)
2. 打开 [API 密钥](https://tokenlab.sh/dashboard/api)
3. 创建或复制一个以 `sk-` 开头的 API 密钥

### 第 2 步：配置提供商

<Steps>
  <Step title="打开模型提供商">
    在 Dify 中，前往 **设置 (Settings)** → **模型提供商 (Model Providers)**
  </Step>
  <Step title="选择 OpenAI-API-compatible">
    打开 **OpenAI-API-compatible**。如果没有显示，请先从 Dify Marketplace 安装该模型提供商插件。选择 **Add model**，输入 TokenLab 设置。
  </Step>
  <Step title="输入 TokenLab 设置">
    使用以下值：

    | 字段 | 值 |
    |-------|-------|
    | API 密钥 | `sk-your-tokenlab-key` |
    | Model type | LLM |
    | Completion mode | Chat |
    | API Type | Chat Completions API |
    | API Base URL | `https://api.tokenlab.sh/v1` |
  </Step>
  <Step title="添加模型">
    添加你想要使用的模型，例如：
    - `gpt-5.4`
    - `gpt-5.4-mini`
    - `claude-sonnet-5`
    - `claude-opus-4-8`
    - `gemini-3.5-flash`
    - `gemini-3.1-flash-lite`
    - `deepseek-v4-flash`
  </Step>
</Steps>

### 第 3 步：测试连接

1. 选择已添加的模型，例如 `gpt-5.4-mini`。
2. 发送一条测试提示词 (prompt)
3. 确认 Dify 收到了有效的响应

## 用于知识库的 Embeddings

对于 RAG 和知识库索引，请添加一个 embedding 模型，例如：
- `text-embedding-3-small`
- `text-embedding-3-large`

然后将其设置为相关知识库或应用程序设置中的默认 embedding 模型。

## 选择模型

请从[模型页](https://tokenlab.sh/zh/models)复制当前聊天和 Embeddings 模型 ID。Dify 需要分别配置聊天与 Embeddings，而且每个模型都必须支持对应组件使用的 API。

## 配置说明

<AccordionGroup>
  <Accordion title="以 OpenAI 插件作为备选">
    独立的 **OpenAI** 插件可用于其目录支持的模型。将自定义 Base URL 设为 `https://api.tokenlab.sh/v1`，并将 **API Protocol** 设为 **Chat Completions**；默认值可能是 Responses。它不是 OpenAI-API-compatible 的旧名称，也不接受所有自定义模型 ID。
  </Accordion>

  <Accordion title="用自己的 Dify 应用比较模型">
    使用相同的代表性输入测试候选模型，再到 Usage 比较输出质量和最终费用。
  </Accordion>

  <Accordion title="此设置使用 Chat Completions">
    此设置请保持 **Completion mode = Chat** 和 **API Type = Chat Completions API**。Responses 是独立的 API 选项；本指南不配置该选项或 WebSocket 连接。
  </Accordion>
</AccordionGroup>

## 故障排除

<AccordionGroup>
  <Accordion title="连接错误">
    - 验证 base URL 是否完全为 `https://api.tokenlab.sh/v1`
    - 如果 Dify 重复添加了斜杠，请删除末尾的斜杠
    - 确认 Dify 服务器可以通过公共互联网访问 TokenLab
  </Accordion>

  <Accordion title="401 未授权">
    - 仔细检查 API 密钥
    - 确认该 key 在 TokenLab dashboard 中处于激活状态
    - 确保粘贴到 Dify 中的值不包含多余的空格或换行符
  </Accordion>

  <Accordion title="模型未找到 (Model Not Found)">
    - 准确核对模型名称
    - 如果提供商 UI 缓存了旧值，请重新添加模型条目
    - 在 TokenLab 文档或 dashboard 中检查当前模型的可用性
  </Accordion>
</AccordionGroup>
