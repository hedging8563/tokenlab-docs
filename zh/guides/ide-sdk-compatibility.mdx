大多数工具只需更换 API 密钥和地址就能连接 TokenLab。具体配置取决于工具使用哪种 API 格式。

| API 格式 | Base URL | 常见客户端 |
| --- | --- | --- |
| Chat Completions (OpenAI 兼容) | `https://api.tokenlab.sh/v1` | OpenAI SDK、许多聊天应用和框架 |
| OpenAI Responses | `https://api.tokenlab.sh/v1` | Responses 客户端和依赖 Responses 事件的工具 |
| Anthropic Messages | `https://api.tokenlab.sh` | Anthropic SDK 和 Claude 工具 |
| Gemini | `https://api.tokenlab.sh` | 允许自定义地址的 Gemini REST 或 SDK 客户端 |

所选模型的 `accepted_request_formats` 必须包含同一种格式。流式输出和工具调用还取决于模型能力与客户端支持。配置示例见[选择 API 格式](/zh/guides/api-formats)。

## 状态说明

| 状态 | 含义 |
| --- | --- |
| **可用** | 链接页面中的 TokenLab 配置使用客户端公开支持的设置选项 |
| **有部分限制** | 配置适用于特定功能或认证方式；厂商其他服务仍有各自的使用要求 |

这些状态描述链接页面中的配置方式。具体功能是否可用，还取决于所选模型和客户端版本。

## 流式响应中的用量

Chat Completions 流接受 `stream_options: { include_usage: true }`，会在流结束前追加一个用量块。Responses API 不公开 `include_usage`；Responses 流在终止事件中返回用量。

## 自定义 API 密钥不能替代什么

有些产品既调用模型，也提供自己的在线功能。TokenLab API 密钥可以用于 BYOK 设置开放的模型请求，但不能替代第三方产品的订阅、补全服务、账户功能或专有扩展。

工具升级后如果配置方式变化，请以当前集成页面为准，不要继续复制旧的环境变量片段。

## 使用前确认

- 工具允许为所需格式填写自定义 Base URL。
- 模型的 `accepted_request_formats` 包含该格式。
- 功能依赖流式输出或工具调用时，使用真实请求验证。
- API 密钥只保存在可信设备或服务端。
- 报告问题时保留请求 ID。
