## 交给我的 Agent 做

把这段任务交给电脑上已经可用的 Agent：

```text
阅读此教程，帮我将 OpenClaw 接入 TokenLab：
https://docs.tokenlab.sh/zh/guides/tokenlab-provider
先检查已安装版本和实际配置。
保留已有账户、提供商、权限及无关设置。
备份本机文件并展示修改内容。
让我在本机输入所需 API Key，不要在聊天里索取、打印或粘贴密钥。
先验证配置能否加载；真实请求测试的费用须单独说明后再运行。
```

<Note>
本页适用于**自托管 OpenClaw**。安装 TokenLab 插件即可开始使用；只有需要指定 API 格式时，才需要手动配置。
</Note>

## 安装插件

可选：安装已发布的提供商插件 **0.1.0**，通过下文所述的同一 Gateway 环境提供 `TOKENLAB_API_KEY`，并仅为会话选择模型。插件的入门向导会改变默认模型，因此本指南不运行 `openclaw onboard`。保留原插件条目与权限，在发送请求前检查插件加载和模型列表。

检查安装器请求的能力，并按客户端提示确认。不要授予无关权限或改变已有插件的权限。

```bash
openclaw plugins install @tokenlabai/openclaw-provider@0.1.0
openclaw plugins list
openclaw models list --provider tokenlab
```

```text
/model tokenlab/claude-sonnet-5 -s
/model default -s
```

[npm](https://www.npmjs.com/package/@tokenlabai/openclaw-provider/v/0.1.0) · [GitHub](https://github.com/hedging8563/tokenlab-openclaw-provider)

## 手动配置

OpenClaw 需要分别使用 Responses、Claude Messages、Gemini 或 MiniMax 格式时，可以在 `models.providers` 中手动添加。普通聊天只配置 `tokenlab` 即可。

| 提供者 | OpenClaw `api` | 适用场景 | baseUrl |
|----------|----------------|----------|---------|
| `tokenlab` | `openai-completions` | GPT、DeepSeek、Qwen 以及大多数与 OpenAI 兼容的调用 | `https://api.tokenlab.sh/v1` |
| `tokenlab-responses` | `openai-responses` | 使用 OpenAI Responses 格式 | `https://api.tokenlab.sh/v1` |
| `tokenlab-claude` | `anthropic-messages` | Claude 原生 Messages API | `https://api.tokenlab.sh` |
| `tokenlab-gemini` | `google-generative-ai` | 原生 Gemini API 格式 | `https://api.tokenlab.sh` |
| `tokenlab-minimax` | `anthropic-messages` | 使用 MiniMax Messages 格式 | `https://api.tokenlab.sh` |

<Warning>
仅对 `openai-completions` 和 `openai-responses` 使用 `/v1` 后缀。

`anthropic-messages` 和 `google-generative-ai` 使用 `https://api.tokenlab.sh`（不带 `/v1`），否则 OpenClaw 会拼出错误的请求地址。
</Warning>

## 前提条件

- 一个自托管的 OpenClaw 实例
- OpenClaw **2026.9.4** 要求 Node.js `>=24.16.0 <25 || >=26.1.0`（[版本要求](https://github.com/openclaw/openclaw/blob/v2026.9.4/package.json)）。使用其他 OpenClaw 版本时，请核对对应版本的要求。
- 一枚 TokenLab API 密钥 — [打开 Console](https://tokenlab.sh/dashboard/api?tab=keys)

## 配置

编辑你的 OpenClaw 配置：

- **自托管**: `~/.openclaw/openclaw.json`

在 `models.providers` 下添加 TokenLab 提供者：

使用运行中 Gateway 对应的 profile、`OPENCLAW_STATE_DIR` 和 `OPENCLAW_CONFIG_PATH`，合并前备份实际配置。将 `TOKENLAB_API_KEY` 放入该实例可信的全局 `.env` 或服务环境；仅在终端 export 或项目 `.env` 中设置，后台 Gateway 可能读不到。参见[环境变量说明](https://docs.openclaw.ai/help/environment)。

先备份当前配置。仅添加 TokenLab 条目，保留已有提供商、账户、默认模型和权限。如果名称已被占用，另选名称并同步修改命令。撤销时仅移除本次添加的条目，或恢复其原备份。

```json5
{
  models: {
    mode: "merge",
    providers: {
      tokenlab: {
        api: "openai-completions",
        baseUrl: "https://api.tokenlab.sh/v1",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gpt-5.6-terra", name: "GPT-5.6 Terra" },
          { id: "deepseek-reasoner", name: "DeepSeek Reasoner" },
          { id: "qwen3-coder-flash", name: "Qwen 3 Coder Flash" }
        ]
      },
      "tokenlab-responses": {
        api: "openai-responses",
        baseUrl: "https://api.tokenlab.sh/v1",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gpt-5.6-terra", name: "GPT-5.6 Terra (Responses)" },
          { id: "gpt-5.2", name: "GPT-5.2 (Responses)" }
        ]
      },
      "tokenlab-claude": {
        api: "anthropic-messages",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "claude-sonnet-5", name: "Claude Sonnet 5" },
          { id: "claude-opus-5", name: "Claude Opus 5" }
        ]
      },
      "tokenlab-gemini": {
        api: "google-generative-ai",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gemini-3.5-flash", name: "Gemini 3.5 Flash" },
          { id: "gemini-2.5-pro", name: "Gemini 2.5 Pro" }
        ]
      },
      "tokenlab-minimax": {
        api: "anthropic-messages",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "minimax-m3", name: "MiniMax M3" }
        ]
      }
    }
  }
}
```

<Info>
五项配置都使用**同一枚 TokenLab API 密钥**。
</Info>

<Info>
上面的 `models` 只是示例。请从[模型页](https://tokenlab.sh/zh/models)选择当前可用的模型 ID。
</Info>

## 使用模型

OpenClaw 仍使用 `provider/model` 格式引用模型：

在 **OpenClaw 2026.9.4** 中使用 `-s` 仅为当前会话选择模型，保留 `agents.defaults.model`、Agent 默认设置与权限。运行 `/model default -s` 可让本会话恢复使用已配置的默认模型。

```text
/model tokenlab-claude/claude-sonnet-5 -s
/model default -s
```

### 模型示例

| 提供者 | 模型引用 | API 格式 |
|----------|-----------------|-------------|
| `tokenlab` | `tokenlab/gpt-5.6-terra` | OpenAI 兼容 |
| `tokenlab-responses` | `tokenlab-responses/gpt-5.6-terra` | Responses |
| `tokenlab-claude` | `tokenlab-claude/claude-sonnet-5` | Claude Messages |
| `tokenlab-gemini` | `tokenlab-gemini/gemini-3.5-flash` | Gemini |
| `tokenlab-minimax` | `tokenlab-minimax/minimax-m3` | MiniMax Messages |

在 [tokenlab.sh/models](https://tokenlab.sh/zh/models) 浏览所有可用模型。

## 何时使用哪个提供者

- `tokenlab`：适合大多数聊天和 Agent 功能。
- `tokenlab-responses`：OpenClaw 功能依赖 OpenAI Responses 时使用。
- `tokenlab-claude`：需要 Claude Messages 字段时使用。
- `tokenlab-gemini`：已有 Gemini 格式配置，或需要 Gemini 字段时使用。
- `tokenlab-minimax`：需要 MiniMax Messages 格式时使用。

不需要 Gemini 专属字段时，也可以通过 `tokenlab/gemini-*` 使用 OpenAI 兼容格式。

## 常见错误

<AccordionGroup>
  <Accordion title="仍然使用旧的顶级 providers 数组">
    当前的 OpenClaw 文档使用 `models.providers`。如果你继续使用旧的顶级 `providers` 数组格式，OpenClaw 可能会忽略配置或无法按预期解析提供者前缀。
  </Accordion>
  <Accordion title="在 tokenlab-responses 上忘记添加 /v1">
    `openai-responses` 映射到 TokenLab 的 `/v1/responses` 路径，因此 `tokenlab-responses` 必须使用 `https://api.tokenlab.sh/v1`。
  </Accordion>
  <Accordion title="在 tokenlab-claude、tokenlab-gemini 或 tokenlab-minimax 添加 /v1">
    `anthropic-messages` 和 `google-generative-ai` 应使用 `https://api.tokenlab.sh`（不带 `/v1`）。添加 `/v1` 会导致请求路径错误。
  </Accordion>
  <Accordion title="OpenClaw 仍然支持原生 Gemini 吗？">
    可以。OpenClaw 支持使用 `api: "google-generative-ai"` 的自定义提供者，因此可以配置 `tokenlab-gemini`。
  </Accordion>
</AccordionGroup>

## 验证设置

重启同一个实例，再检查所选模型和提供商。不带 `--probe` 的 `models status` 不是模型请求测试；真实 `--probe` 或聊天消息可能消耗 token。应核对真实回复和对应 TokenLab 请求记录后再确认接入成功。恢复时选回原模型，仅移除本次添加的 TokenLab 项目。

```bash
openclaw gateway restart
openclaw models status
```
