Gunakan panduan ini bila aplikasi sudah mengirim request Seedance bergaya Volcengine. Nama Action, `Version=2024-01-01`, `content[]`, body material PascalCase, dan envelope respons Volcengine dapat dipertahankan. Hanya endpoint dan autentikasi yang harus berubah.

## Yang berubah

| Bagian | Klien Volcengine saat ini | TokenLab |
| --- | --- | --- |
| URL dasar | `Volcengine API` | `https://api.tokenlab.sh/` |
| Autentikasi | `AK/SK` | `Authorization: Bearer <TOKENLAB_API_KEY>` |
| Request Action | `Action`, `Version` | `Action`, `Version` |
| Body task | `content[]` | `content[]` |
| Body material | `PascalCase` | `PascalCase` |
| Hasil asinkron | `ID task` | `cgt-...` + Polling |

Request yang hanya berisi tanda tangan AK/SK mengembalikan `401 AuthenticationError`. Klien Action dapat memakai `POST /?Action=...&Version=2024-01-01`; `POST /api/v3?Action=...&Version=2024-01-01` tetap tersedia. Klien REST memakai `/api/v3/contents/generations/tasks`.

## Bentuk request dan siklus hidup task

Jika integrasi Anda sudah mengirim permintaan Seedance bergaya Volc, gunakan endpoint kompatibel ini tanpa mengubah body menjadi format `/v1/videos/generations`. Kirim TokenLab API key sebagai `Authorization: Bearer ...`, gunakan `POST /api/v3/contents/generations/tasks` untuk pembuatan REST, atau `/api/v3?Action=CreateContentsGenerationsTasks&Version=2024-01-01` untuk permintaan Action. Respons pembuatan mengembalikan ID tugas `cgt-...`; respons status menggunakan `queued`, `running`, `succeeded`, `failed`, `cancelled`, atau `expired`.

Endpoint ini menerima item `content[]` seperti `text`, `image_url`, `video_url`, `audio_url`, dan `draft_task`. `callback_url` menerima objek query yang sama pada setiap perubahan ke `queued`, `running`, `succeeded`, `failed`, atau `expired`; `succeeded` dan `failed` dicoba ulang hingga tiga kali setelah lima detik. Pertahankan polling sebagai jalur pemulihan.

Jangan gunakan struct `/v1/tasks/{id}` untuk v3. v1 memakai `pending`, `processing`, `completed`, dan `failed`; v3 memakai `queued`, `running`, `succeeded`, `failed`, `cancelled`, dan `expired`. Pada v3, `duration` berupa string dan `error` hanya muncul ketika gagal.

Untuk memulihkan setelah koneksi terputus, kirim `Idempotency-Key` unik pada create REST. Body dan key yang sama mengembalikan ID `cgt-...` yang sama; body berbeda dengan key yang sama mengembalikan `409`.

## Action task

| Action | Bagian | JSON |
| --- | --- | --- |
| `CreateContentsGenerationsTasks` | Membuat task video | `model`, `content[]` |
| `GetContentsGenerationsTask` | Mengambil satu task | `TaskId` |
| `ListContentsGenerationsTasks` | Mencantumkan task | Filter, paginasi |
| `DeleteContentsGenerationsTasks` | Membatalkan atau menghapus task | `TaskId` |

## Contoh REST minimal

```bash
curl 'https://api.tokenlab.sh/api/v3/contents/generations/tasks' \
  -H "Authorization: Bearer $TOKENLAB_API_KEY" \
  -H "Idempotency-Key: $CLIENT_JOB_ID" \
  -H "Content-Type: application/json" \
  -d '{
    "model":"seedance-2.0",
    "content":[
      {"type":"text","text":"A cinematic product reveal"},
      {"type":"image_url","role":"reference_image","image_url":{"url":"https://example.com/reference.png"}}
    ],
    "ratio":"16:9",
    "duration":5,
    "resolution":"720p"
  }'
```

Material orang asli juga memerlukan [Buat sesi verifikasi visual](/id/api-reference/video/create-visual-validation-session) dan [Ambil hasil verifikasi visual](/id/api-reference/video/get-visual-validation-result) sebelum upload.

## Checklist migrasi

1. Ganti host API dengan `https://api.tokenlab.sh`.
2. Ganti tanda tangan AK/SK dengan TokenLab Bearer API Key.
3. Pertahankan Action, versi, dan kapitalisasi body.
4. Gunakan `ProjectName` yang sama pada request material dan verifikasi terkait.
5. Simpan ID task, grup, dan material yang dikembalikan TokenLab.
6. Validasi create, polling, list, dan error sebelum memindahkan traffic produksi.
