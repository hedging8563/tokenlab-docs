## Gambaran Umum

Portkey Gateway dapat merutekan permintaan ke TokenLab sebagai penyedia upstream. Default yang paling aman adalah chat completions yang kompatibel dengan OpenAI; gunakan Responses jika versi Portkey Anda mengekspos jalur tersebut untuk TokenLab.

<Note>
**Tipe**: AI Gateway

**Jalur Utama**: Chat completions yang kompatibel dengan OpenAI dan Responses

**Tingkat Dukungan**: Jalur didukung
</Note>

## Nilai Penyedia

| Kolom | Nilai |
|-------|-------|
| Provider | `tokenlab` |
| Base URL | `https://api.tokenlab.sh/v1` |
| API key | `sk-your-tokenlab-key` |
| Model bawaan | `gpt-5.4-mini` |

## Chat Completions

Gunakan TokenLab untuk permintaan chat yang kompatibel dengan OpenAI:

```bash
curl https://your-portkey-gateway.example/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "x-portkey-provider: tokenlab" \
  -H "Authorization: Bearer sk-your-tokenlab-key" \
  -d '{
    "model": "gpt-5.4-mini",
    "messages": [{"role": "user", "content": "Say hello from TokenLab."}]
  }'
```

## Responses

Jika build Portkey Anda merutekan Responses TokenLab, gunakan `gpt-5.5`, `gpt-5.4`, atau `gpt-5.4-mini` dengan `/v1/responses`.

## Catatan Endpoint Native

TokenLab juga mengekspos endpoint Anthropic Messages dan yang kompatibel dengan Gemini secara langsung. Apakah endpoint tersebut dapat digunakan melalui Portkey bergantung pada dukungan penyedia dan endpoint Portkey di versi yang Anda gunakan.
