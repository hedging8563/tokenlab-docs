## Visão geral

Estes endpoints são para equipes que já usam o formato de tarefa Seedance no estilo Volc. A autenticação usa sua API key Bearer da TokenLab. O ID retornado começa com `cgt-`; consulte o status até que `status` seja `succeeded`, `failed`, `cancelled` ou `expired`.

<Warning>
Não reutilize o enum nem a struct de resposta v1. `/v1/tasks/{id}` usa `pending`, `processing`, `completed` e `failed`; este endpoint usa o enum v3 acima. No v3, `duration` é uma string quando presente e `error` só aparece em falhas.
</Warning>

Veja também [Modelos de vídeo Seedance 2.0](/pt/guides/seedance-2-video) e [Geração de vídeo](/pt/guides/video-generation).

## Formato da resposta

A resposta usa `queued`, `running`, `succeeded`, `failed`, `cancelled` ou `expired`. Tarefas bem-sucedidas retornam `content.video_url`; `content.last_frame_url`, campos oficiais de geração e `usage` podem aparecer. `error` só é incluído em falhas. Campos TokenLab como `progress`, `return_last_frame`, `watermark`, `priority` ou `camera_fixed` não são adicionados.

## Exemplo

```bash
curl https://api.tokenlab.sh/api/v3/contents/generations/tasks/cgt-20260102030405-a1b2c \
  -H "Authorization: Bearer $TOKENLAB_API_KEY"
```
