---
title: "Recuperar arquivo"
openapi: "GET /v1/files/{file_id}"
description: "Recupera metadados de um único arquivo enviado."
---

## Visão geral

Este endpoint serve principalmente aos objetos de arquivo da API de Batch compatível com OpenAI da TokenLab.

Quando a requisição entra no modo de compatibilidade com Anthropic Files, a mesma rota também pode retornar metadados de arquivo no estilo Anthropic para o workspace vinculado.


Sem cabeçalhos Anthropic, esta rota pode retornar um objeto de arquivo de lote ou um objeto de arquivo de imagem/referência da TokenLab.
## Notas

- Arquivos de entrada do lote devem usar `purpose=batch`.
- `completion_window` é atualmente `24h`.
- A ordenação da saída não é garantida; sempre combine pelo `custom_id`.
- Streaming não é suportado dentro de itens de lote.

## Exemplo

<RequestExample>
```bash cURL
curl -X GET "https://api.tokenlab.sh/v1/files/file_abc123" \
  -H "Authorization: Bearer sk-your-api-key"
```
</RequestExample>

## Solicitação / Resposta

Use o painel OpenAPI interativo acima para ver o esquema exato.

## Dicas operacionais

- Use `custom_id` para reconciliação downstream idempotente.
- Espere `output_file_id` e `error_file_id` apenas depois que o worker finalizar o lote.
- A precificação do lote pode ser diferente da precificação síncrona porque as regras de desconto `isBatchRequest=true` se aplicam.

## Exemplo de resposta

<ResponseExample>
```json 200 OK
{
  "id": "file_abc123",
  "object": "file",
  "bytes": 32768,
  "created_at": 1706000000,
  "filename": "batch-input.jsonl",
  "purpose": "batch"
}
```
</ResponseExample>

## Campos importantes

<ResponseField name="id" type="string">Identificador de arquivo usado por APIs relacionadas.</ResponseField>
<ResponseField name="filename" type="string">Nome original ou gerado do arquivo.</ResponseField>
<ResponseField name="purpose" type="string">Finalidade do arquivo usada pelo fluxo proprietário, como `batch`, `batch_output`, `user_data` ou `vision`.</ResponseField>
