---
title: "Obter um Modelo"
openapi: "GET /v1/models/{model}"
description: "Obtenha as capacidades, preços e formatos de API de um modelo"
---

## Parâmetro de Caminho

<ParamField path="model" type="string" required>
  ID do modelo, como `gpt-5.4` ou `claude-sonnet-4-6`.
</ParamField>

## Resposta

<ResponseField name="id" type="string">ID do modelo.</ResponseField>
<ResponseField name="object" type="string">Sempre `model`.</ResponseField>
<ResponseField name="owned_by" type="string">Criador do modelo.</ResponseField>
<ResponseField name="tokenlab" type="object">
  Informações do modelo TokenLab, incluindo capacidades, preços, unidades de cobrança, limites de contexto, formatos de API aceitos, operações e status do ciclo de vida.
</ResponseField>

Campos comuns de `tokenlab` incluem:

- `capabilities`: texto, imagem, vídeo, áudio e outras capacidades.
- `pricing`: preços públicos atuais.
- `max_input_tokens` e `max_output_tokens`: limites de contexto e de saída.
- `accepted_request_formats`: formatos de API suportados.
- `supported_operations`: operações como texto-para-imagem ou imagem-para-vídeo.
- `lifecycle`: disponibilidade, data de lançamento, data de descontinuação ou modelo de substituição.

Alguns modelos de mídia também incluem um status de recomendação e horário de atualização. As recomendações podem mudar com a disponibilidade e o desempenho, portanto, não codifique (hard-code) a ordem delas.

## Exemplo

```bash
curl "https://api.tokenlab.sh/v1/models/gpt-5.4"
```

```json
{
  "id": "gpt-5.6-terra",
  "object": "model",
  "owned_by": "openai",
  "tokenlab": {
    "category": "chat",
    "capabilities": ["text"],
    "accepted_request_formats": ["responses", "chat_completions"]
  }
}
```

Um modelo desconhecido retorna `404 model_not_found`.
