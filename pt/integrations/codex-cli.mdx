## Visão geral



<Note>
**Tipo**: Ferramenta de Codificação

**Caminho Primário**: OpenAI Responses (caminho opcional avançado)

**Confiança de Suporte**: Suportado com limites de modelo/caminho
</Note>

OpenAI Codex é uma ferramenta de linha de comando (CLI) open-source que atua como um agente de codificação leve, capaz de ler, modificar e executar código no terminal. É construída sobre modelos GPT e otimizada para geração de código.

Para TokenLab, o Codex CLI pode usar `/v1/responses`, mas você deve tratá-lo como um caminho de compatibilidade avançado. Algumas funcionalidades exclusivas do Responses não são garantidas em todos os modelos e rotas.

A compactação remota do Codex CLI é compatível em `POST /v1/responses/compact`. O Codex envia o `model` da sessão atual em `body.model` para `/compact` e auto-compactação, então o modelo usado para compactar deve estar disponível no caminho Responses. Não configure `/v1/compact`.

## Requisitos do Sistema

Siga o [guia CLI oficial](https://learn.chatgpt.com/docs/codex/cli) para macOS, Linux ou Windows. Windows nativo e WSL são ambientes separados; veja o [guia Windows](https://learn.chatgpt.com/docs/windows/windows-sandbox). npm é uma opção, não um requisito dos binários nativos.

```bash
npm install -g @openai/codex
```

## Configuração

### Passo 1: Definir Chave de API

**Temporário (sessão atual):**

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

**Configuração permanente:**

Adicione em `~/.bashrc`, `~/.zshrc`, ou `~/.bash_profile`:

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

Em seguida recarregue:

```bash
source ~/.zshrc  # or source ~/.bashrc
```

### Passo 2: Configure config.toml

Mescle estas configurações no arquivo de usuário `~/.codex/config.toml`; não substitua o arquivo inteiro. Preserve os outros provedores, contas, configurações de sandbox e regras de aprovação. As configurações do provedor e de autenticação pertencem à configuração do usuário, não ao `.codex/config.toml` de um projeto. Consulte o [guia oficial de configuração](https://learn.chatgpt.com/docs/config-file/config-advanced#custom-model-providers).

Para manter o provedor padrão, a partir do Codex 0.134.0 salve o exemplo em `~/.codex/tokenlab.config.toml` e inicie `codex --profile tokenlab`. Use o diretório real se personalizou `CODEX_HOME`. Não crie a antiga tabela `[profiles.tokenlab]`, sobrescreva `auth.json`, saia da conta ou altere permissões. Inicie sem esse perfil para restaurar.

Em cada grupo de comandos abaixo, escolha **Perfil TokenLab** para `tokenlab.config.toml`. Use **TokenLab padrão** somente após mesclar as configurações em `config.toml`. O comando `codex` sozinho usa a configuração padrão; ele não mantém o perfil escolhido em uma sessão anterior.

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"

[model_providers.tokenlab]
env_key = "TOKENLAB_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000
```

Este modo WebSocket é uma ponte Responses-over-WebSocket para clientes Codex. Ele aceita somente eventos oficiais `response.create`; `stream` é implícito, e `background` e `response.cancel` não estão disponíveis nesse transporte. Não é a API OpenAI Realtime e não aceita `session.update`, `conversation.item.*`, `input_audio_buffer.*`, áudio binário nem envelopes Realtime aninhados `response.create.response`.

<Note>
Crie o arquivo de configuração escolhido se ele não existir. Após editá-lo, inicie uma nova sessão com o comando correspondente abaixo.
</Note>

O Codex atual usa `wire_api = "responses"`, não `chat/completions`. Omita `requires_openai_auth` ou use false para que este provedor utilize `env_key`.

<Note>
O TokenLab encaminha campos Responses desconhecidos em best-effort sem rebaixar silenciosamente a requisição para Chat Completions. O upstream selecionado decide se o campo ou a combinação é compatível.
</Note>

## Modelos Recomendados

| Modelo | Melhor para |
|-------|----------|
| `gpt-5.6-sol` | Melhor escolha padrão para codificação e raciocínio |
| `gpt-5-mini` | Alternativa mais rápida e barata para fluxos de trabalho de codificação |
| `claude-sonnet-4-6` | Revisão de código, documentação |

## Comandos Interativos

| Comando | Descrição |
|---------|-------------|
| `/help` | Exibir ajuda |
| `/exit` or `Ctrl+C` | Sair |
| `/clear` | Limpar conversa |
| `/status` | Mostrar o modelo ativo, as permissões e o uso de tokens |
| `/model <name>` | Trocar modelo |

## Verificar Configuração

Verifique apenas se a variável de ambiente está definida, sem exibir seu valor. Essa verificação não valida a chave:

```bash
if [ -n "${TOKENLAB_API_KEY:-}" ]; then
  printf '%s\n' 'TOKENLAB_API_KEY is set'
else
  printf '%s\n' 'TOKENLAB_API_KEY is not set'
fi
```

Inicie o Codex e execute `/status` para conferir o modelo ativo e as permissões. Se usar um perfil, inicie esse mesmo perfil. Consulte o [comando oficial de status](https://learn.chatgpt.com/docs/developer-commands?surface=cli#inspect-the-session-with-status).

Quando estiver pronto para enviar uma requisição real, execute o comando abaixo. Ele usa seu saldo TokenLab. Confira a resposta e o registro correspondente em [Requisições](https://tokenlab.sh/dashboard/runs?section=requests). Uma variável definida ou uma inicialização bem-sucedida, por si só, não comprova o sucesso de uma requisição.

```bash Perfil TokenLab
codex --profile tokenlab "Reply only with OK. Do not use tools or modify files."
```

```bash TokenLab padrão
codex "Reply only with OK. Do not use tools or modify files."
```

## Solução de Problemas

<AccordionGroup>
  <Accordion title="Erro de Conexão">
    - Verifique se `base_url` em `config.toml` está exatamente `https://api.tokenlab.sh/v1`
    - Verifique a conectividade de rede
    - Certifique-se de que nenhum proxy esteja interferindo
  </Accordion>

  <Accordion title="Autenticação Falhou">
    - Verifique se `env_key = "TOKENLAB_API_KEY"` está presente em `~/.codex/tokenlab.config.toml` / `~/.codex/config.toml`
    - Verifique se a variável de ambiente `TOKENLAB_API_KEY` está definida
    - Verifique se a chave começa com `sk-`
    - Certifique-se de que a chave está ativa no painel do TokenLab
  </Accordion>

  <Accordion title="Modelo Não Encontrado">
    - Verifique se o nome do modelo corresponde exatamente
    - Verifique a disponibilidade do modelo em [tokenlab.sh/en/models](https://tokenlab.sh/pt/models)
  </Accordion>

  <Accordion title="Campo nativo do Responses rejeitado">
    - Alguns campos estão disponíveis apenas em `/v1/responses` quando a TokenLab pode garantir esse comportamento para o modelo e a rota selecionados
    - Se você vir `unsupported_request_field`, remova esse campo ou mude para um fluxo de trabalho que não dependa dele
  </Accordion>

  <Accordion title="/compact ou auto-compactação falha">
    - O Codex CLI chama `POST /v1/responses/compact`, não `/v1/compact`
    - A solicitação de compactação usa o `model` da sessão atual, portanto esse modelo deve estar disponível no caminho Responses
    - Mantenha `wire_api = "responses"` e `base_url = "https://api.tokenlab.sh/v1"`
  </Accordion>
</AccordionGroup>
