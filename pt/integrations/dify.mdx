## Visão Geral

Use o plugin de provedor de modelos **OpenAI-API-compatible** para conectar o Dify ao TokenLab. Defina o tipo de modelo como **LLM**, **Completion mode** como **Chat** e **API Type** como **Chat Completions API**. Este guia usa Chat Completions.

<Note>
**Tipo**: Framework ou Plataforma

**Caminho Principal**: Caminho de chat compatível com OpenAI

**Nível de Suporte**: Suportado com limitações de escopo
</Note>

## Pré-requisitos

- Conta no TokenLab com acesso à API
- Dify Cloud ou Dify auto-hospedado

## Etapas de Configuração

### Etapa 1: Obtenha sua Chave de API

1. Faça login no [TokenLab Dashboard](https://tokenlab.sh/dashboard)
2. Abra [API Keys](https://tokenlab.sh/dashboard/api)
3. Crie ou copie uma chave de API que comece com `sk-`

### Etapa 2: Configurar o Provedor

<Steps>
  <Step title="Abrir Provedores de Modelo">
    No Dify, vá para **Settings** → **Model Providers**
  </Step>
  <Step title="Selecionar OpenAI-API-compatible">
    Abra **OpenAI-API-compatible**. Se ele não estiver disponível, instale esse plugin de provedor de modelos pelo Dify Marketplace. Escolha **Add model** para inserir as configurações do TokenLab.
  </Step>
  <Step title="Inserir Configurações do TokenLab">
    Use estes valores:

    | Campo | Valor |
    |-------|-------|
    | API Key | `sk-your-tokenlab-key` |
    | Model type | LLM |
    | Completion mode | Chat |
    | API Type | Chat Completions API |
    | API Base URL | `https://api.tokenlab.sh/v1` |
  </Step>
  <Step title="Adicionar Modelos">
    Adicione os modelos que deseja usar, por exemplo:
    - `gpt-5.4`
    - `gpt-5.4-mini`
    - `claude-sonnet-5`
    - `claude-opus-4-8`
    - `gemini-3.5-flash`
    - `gemini-3.1-flash-lite`
    - `deepseek-v4-flash`
  </Step>
</Steps>

### Etapa 3: Testar Conexão

1. Selecione um modelo que você adicionou, como `gpt-5.4-mini`.
2. Envie um prompt de teste
3. Confirme se o Dify recebe uma resposta válida

## Embeddings para Bases de Conhecimento

Para RAG e indexação de bases de conhecimento, adicione um modelo de embedding como:
- `text-embedding-3-small`
- `text-embedding-3-large`

Em seguida, defina-o como o modelo de embedding padrão nas configurações da base de conhecimento ou do aplicativo relevante.

## Funções de Modelo Recomendadas

| Caso de Uso | Modelos Sugeridos |
|----------|------------------|
| Chat padrão | `gpt-5.4-mini`, `gpt-5.4`, `claude-sonnet-5` |
| Raciocínio profundo | `gpt-5.5`, `gpt-5.4`, `claude-opus-4-8`, `deepseek-v4-pro` |
| Rápido/econômico | `gpt-5.4-mini`, `gemini-3.5-flash`, `deepseek-v4-flash` |
| Embeddings | `text-embedding-3-small`, `text-embedding-3-large` |

## Melhores Práticas

<AccordionGroup>
  <Accordion title="Plugin OpenAI como alternativa">
    O plugin separado **OpenAI** pode ser usado com modelos compatíveis com seu catálogo. Defina sua URL base personalizada como `https://api.tokenlab.sh/v1` e **API Protocol** como **Chat Completions**; o padrão pode ser Responses. Ele não é um nome antigo de OpenAI-API-compatible e não aceita qualquer ID de modelo personalizado.
  </Accordion>

  <Accordion title="Use modelos mais baratos para iteração">
    Use `gpt-5.4-mini`, `gemini-3.5-flash` ou `deepseek-v4-flash` durante a iteração e, em seguida, alterne fluxos de trabalho mais pesados para modelos mais robustos apenas quando necessário.
  </Accordion>

  <Accordion title="Esta configuração usa Chat Completions">
    Mantenha **Completion mode = Chat** e **API Type = Chat Completions API** nesta configuração. Responses é uma opção de API separada; este guia não configura essa opção nem conexões WebSocket.
  </Accordion>
</AccordionGroup>

## Solução de Problemas

<AccordionGroup>
  <Accordion title="Erro de Conexão">
    - Verifique se a URL base é exatamente `https://api.tokenlab.sh/v1`
    - Remova barras finais se o Dify duplicá-las
    - Confirme se o servidor Dify consegue alcançar o TokenLab pela internet pública
  </Accordion>

  <Accordion title="401 Não autorizado">
    - Verifique novamente a chave de API
    - Confirme se a chave está ativa no dashboard do TokenLab
    - Certifique-se de que o valor colado no Dify não contenha espaços extras ou quebras de linha
  </Accordion>

  <Accordion title="Modelo Não Encontrado">
    - Verifique o nome do modelo exatamente
    - Adicione novamente a entrada do modelo se a interface do provedor tiver armazenado um valor antigo em cache
    - Verifique a disponibilidade atual do modelo na documentação ou no dashboard do TokenLab
  </Accordion>
</AccordionGroup>
