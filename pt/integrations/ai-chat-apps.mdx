## Visão Geral

A maioria dos aplicativos de chat com IA em geral se conecta ao TokenLab através do caminho de chat padrão compatível com OpenAI.

Na prática, isso significa:
- use `https://api.tokenlab.sh/v1` como a URL base, a menos que o aplicativo solicite explicitamente uma URL de endpoint completa
- use sua chave de API do TokenLab como a chave de API no estilo OpenAI
- escolha modelos que o aplicativo possa usar em um fluxo de trabalho de chat padrão

<Note>
Aplicativos de chat em geral são geralmente **orientados a chat-completions**, não clientes WebSocket de Respostas Codex. Para o Codex CLI/App, Cursor ou outras ferramentas de codificação que precisam de comportamento específico de Respostas, use os guias de integração dedicados.
</Note>

<Note>
**Tipo**: Aplicativo de Chat

**Caminho Principal**: chat-completions compatível com OpenAI

**Confiança de Suporte**: Caminho suportado
</Note>

## Aplicações Suportadas

| Aplicação | Plataforma | Notas |
|-------------|----------|-------|
| Open WebUI | Web, Auto-hospedado | Escolha popular auto-hospedada com conexões compatíveis com OpenAI |
| LibreChat | Web, Auto-hospedado | Workspace de chat multi-provedor com endpoints OpenAI personalizados |
| LobeChat | Web, Desktop, Auto-hospedado | Forte suporte a provedores personalizados |
| Cherry Studio | Windows, macOS, Linux | Bom fluxo de provedor compatível com OpenAI |
| Chatbox | Windows, macOS, Linux | Configuração simples compatível com OpenAI |
| DeepChat | Windows, macOS, Linux | Cliente desktop com configurações de provedor compatíveis com OpenAI |
| Jan | Desktop, Auto-hospedado | Aplicativo local-first com provedores remotos compatíveis com OpenAI |
| TypingMind | Web, Desktop | Usa um estilo de endpoint personalizado |
| NextChat | Web, Auto-hospedado | Cliente leve estilo ChatGPT com substituições de URL base |
| ChatWise | Windows, macOS | Padrão de provedor personalizado padrão |

## Valores de Conexão Padrão

| Campo | Valor |
|-------|-------|
| Base URL | `https://api.tokenlab.sh/v1` |
| API Key | `sk-your-tokenlab-key` |
| Tipo de API | Compatível com OpenAI |

Se um aplicativo solicitar uma **URL de endpoint completa** em vez de uma URL base, use:
- Chat Completions: `https://api.tokenlab.sh/v1/chat/completions`

## Exemplos de Configuração de Aplicativos

<Tabs>
  <Tab title="LobeChat">
    **LobeChat Auto-hospedado**

    ```bash
    OPENAI_API_KEY=sk-your-tokenlab-key
    OPENAI_PROXY_URL=https://api.tokenlab.sh/v1
    ```

    **LobeChat Cloud**
    1. Abra **Settings** → **AI Service Provider**
    2. Selecione **OpenAI**
    3. Insira sua chave de API do TokenLab
    4. Defina o endpoint personalizado como `https://api.tokenlab.sh/v1`
  </Tab>

  <Tab title="Cherry Studio">
    1. Abra **Settings** → **Model Provider**
    2. Adicione um provedor **OpenAI-compatible**
    3. Insira:
       - **Name**: TokenLab
       - **API Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
    4. Adicione os modelos que deseja usar
  </Tab>

  <Tab title="Chatbox">
    1. Abra **Settings** → **AI Model**
    2. Escolha **OpenAI API Compatible**
    3. Insira:
       - **API Host**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
       - **Model**: `gpt-5.4-mini` ou `claude-sonnet-5`
  </Tab>

  <Tab title="TypingMind">
    1. Abra **Settings**
    2. Escolha **Custom Endpoint**
    3. Insira:
       - **Endpoint URL**: `https://api.tokenlab.sh/v1/chat/completions`
       - **API Key**: `sk-your-tokenlab-key`
    4. Configure os modelos que deseja expor
  </Tab>

  <Tab title="Open WebUI">
    1. Abra **Admin Settings** → **Connections**
    2. Adicione uma conexão **OpenAI-compatible**
    3. Insira:
       - **Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
    4. Salve e selecione os modelos que deseja expor
  </Tab>

  <Tab title="DeepChat">
    1. Abra **Settings** -> **Model Provider**
    2. Adicione um provedor compatível com OpenAI
    3. Insira:
       - **Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
       - **Model**: `gpt-5.4-mini`
    4. Salve e execute um chat de teste
  </Tab>

  <Tab title="Jan">
    1. Abra **Settings** -> **Providers**
    2. Adicione um provedor remoto compatível com OpenAI
    3. Insira:
       - **Provider name**: TokenLab
       - **Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
    4. Selecione `gpt-5.4-mini` ou outro modelo do TokenLab
  </Tab>

  <Tab title="LibreChat">
    Adicione um endpoint compatível com OpenAI na configuração do seu provedor LibreChat e aponte para:

    ```yaml
    customEndpoints:
      - name: TokenLab
        apiKey: '${OPENAI_API_KEY}'
        baseURL: 'https://api.tokenlab.sh/v1'
        models:
          default: ['gpt-5.4-mini', 'gpt-5.4', 'claude-sonnet-5']
          fetch: false
    ```
  </Tab>
</Tabs>

## Dicas

<AccordionGroup>
  <Accordion title="Prefira a URL base quando o aplicativo suportar">
    A maioria dos aplicativos é mais fácil de configurar e menos frágil quando você fornece `https://api.tokenlab.sh/v1` como URL base em vez de uma URL de endpoint completa.
  </Accordion>

  <Accordion title="Use modelos menores primeiro">
    Comece com `gpt-5.4-mini` ou `deepseek-v4-flash` para o chat diário, depois mova tarefas de raciocínio mais pesadas para `gpt-5.4` ou `claude-opus-4-8`.
  </Accordion>

  <Accordion title="Mantenha as ferramentas de codificação separadas">
    Aplicativos de chat em geral e agentes de codificação frequentemente precisam de comportamentos de endpoint diferentes. Mantenha ferramentas estilo Codex/Cursor em suas páginas de integração dedicadas.
  </Accordion>
</AccordionGroup>

## Solução de Problemas

<AccordionGroup>
  <Accordion title="Erro de Conexão">
    - Verifique se a URL base é exatamente `https://api.tokenlab.sh/v1`
    - Remova barras finais se o aplicativo adicionar caminhos automaticamente
    - Se o aplicativo solicitar uma URL de endpoint completa, use `https://api.tokenlab.sh/v1/chat/completions`
  </Accordion>

  <Accordion title="401 Não autorizado">
    - Verifique novamente sua chave de API
    - Confirme se a chave está ativa no painel do TokenLab
    - Certifique-se de que não haja espaços extras ou quebras de linha
  </Accordion>

  <Accordion title="Modelo Não Disponível">
    - Verifique o nome do modelo exatamente
    - Tente um padrão amplamente suportado como `gpt-5.4-mini`, `deepseek-v4-flash` ou `claude-sonnet-5`
    - Verifique a disponibilidade atual na documentação ou no painel do TokenLab
  </Accordion>
</AccordionGroup>
