## Visão Geral

O Portkey Gateway pode rotear solicitações para o TokenLab como um provedor upstream. O padrão mais seguro são as conclusões de chat compatíveis com OpenAI; use Responses quando sua versão do Portkey expuser esse caminho para o TokenLab.

<Note>
**Tipo**: AI Gateway

**Caminhos Principais**: Conclusões de chat compatíveis com OpenAI e Responses

**Nível de Suporte**: Caminho suportado
</Note>

## Valores do Provedor

| Campo | Valor |
|-------|-------|
| Provider | `tokenlab` |
| Base URL | `https://api.tokenlab.sh/v1` |
| API key | `sk-your-tokenlab-key` |
| Modelo padrão | `gpt-5.4-mini` |

## Conclusões de Chat (Chat Completions)

Use o TokenLab para solicitações de chat compatíveis com OpenAI:

```bash
curl https://your-portkey-gateway.example/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "x-portkey-provider: tokenlab" \
  -H "Authorization: Bearer sk-your-tokenlab-key" \
  -d '{
    "model": "gpt-5.4-mini",
    "messages": [{"role": "user", "content": "Say hello from TokenLab."}]
  }'
```

## Respostas (Responses)

Se a sua versão do Portkey roteia Responses do TokenLab, use `gpt-5.5`, `gpt-5.4` ou `gpt-5.4-mini` com `/v1/responses`.

## Nota sobre Endpoint Nativo

O TokenLab também expõe endpoints compatíveis com Anthropic Messages e Gemini diretamente. Se eles podem ser usados através do Portkey, isso depende do provedor Portkey e do suporte ao endpoint na sua versão implantada.
