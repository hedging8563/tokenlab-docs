## Visão Geral

Configure o TokenLab no Portkey como um host personalizado compatível com OpenAI. Use Responses apenas quando sua versão do Portkey oferecer suporte a um endpoint Responses personalizado.

<Note>
**Tipo**: AI Gateway

**Caminhos Principais**: Conclusões de chat compatíveis com OpenAI e Responses

**Nível de Suporte**: Caminho suportado
</Note>

## Valores do Provedor

| Campo | Valor |
|-------|-------|
| Provider | `openai` |
| Custom Host | `https://api.tokenlab.sh/v1` |
| API key | `sk-your-tokenlab-key` |
| Modelo | Um ID de modelo do TokenLab disponível atualmente |

## Conclusões de Chat (Chat Completions)

Use o TokenLab para solicitações de chat compatíveis com OpenAI:

O exemplo requer um Portkey Gateway auto-hospedado em execução. Substitua a URL do gateway pela URL do seu ambiente. Para Portkey Cloud, envie também sua chave de API do Portkey em `x-portkey-api-key`. Consulte o [guia de configuração do Portkey](https://portkey.ai/docs/api-reference/inference-api/headers).

```bash
curl https://your-portkey-gateway.example/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "x-portkey-provider: openai" \
  -H "x-portkey-custom-host: https://api.tokenlab.sh/v1" \
  -H "Authorization: Bearer sk-your-tokenlab-key" \
  -d '{
    "model": "gpt-5.6-luna",
    "messages": [{"role": "user", "content": "Say hello from TokenLab."}]
  }'
```

## Respostas (Responses)

Se sua versão do Portkey oferecer suporte a uma URL Responses personalizada, escolha um modelo disponível compatível com Responses na [página de modelos](https://tokenlab.sh/pt/models) e use `/v1/responses`.

## Nota sobre Endpoint Nativo

Anthropic Messages e Gemini só podem ser usados por meio do Portkey se sua versão do Portkey oferecer suporte a URLs personalizadas para esses formatos.
