## Confier la configuration à mon agent

Copiez cette tâche dans un agent déjà opérationnel sur votre ordinateur :

```text
Lis ce guide et aide-moi à connecter OpenClaw à TokenLab :
https://docs.tokenlab.sh/fr/guides/tokenlab-provider
Vérifie d’abord ma version installée et la configuration active.
Préserve les comptes, les fournisseurs, les permissions et les autres réglages existants.
Sauvegarde les fichiers locaux et présente les modifications proposées.
Laisse-moi saisir localement les clés API nécessaires ; ne les demande, ne les affiche et ne les colle jamais dans le chat.
Vérifie d’abord que la configuration se charge correctement.
Explique séparément le coût de tout test utilisant une requête payante avant de l’exécuter.
```

<Note>
Ce guide s'adresse aux utilisateurs d'**OpenClaw auto-hébergé** qui souhaitent connecter TokenLab comme fournisseur IA.
</Note>

## Recommandé : installer le plugin

Facultatif : installez le plugin publié **0.1.0**. Fournissez `TOKENLAB_API_KEY` dans l’environnement Gateway décrit ci-dessous et sélectionnez le modèle pour la session uniquement. L’assistant modifie le modèle par défaut ; ce guide n’exécute donc pas `openclaw onboard`. Conservez les plugins et permissions existants et vérifiez le chargement et la liste des modèles avant tout appel.

Examinez les capacités demandées par l’installateur et suivez ses confirmations. N’accordez pas de permissions sans rapport et ne modifiez pas celles des plugins existants.

```bash
openclaw plugins install @tokenlabai/openclaw-provider@0.1.0
openclaw plugins list
openclaw models list --provider tokenlab
```

## Configuration manuelle du fournisseur

Utilisez les entrées `models.providers` ci-dessous uniquement si vous avez explicitement besoin de routes distinctes pour **Responses API**, **Claude native**, **Gemini native** ou **MiniMax native**.

Si vous choisissez la configuration manuelle, la configuration de `tokenlab` seule suffit. Ajoutez les autres fournisseurs uniquement lorsque vous avez explicitement besoin du comportement **Responses API**, **Claude natif**, **Gemini natif**, ou **MiniMax natif**.

| Fournisseur | OpenClaw `api` | Idéal pour | baseUrl |
|----------|----------------|------------|---------|
| `tokenlab` | `openai-completions` | GPT, DeepSeek, Qwen et la plupart des appels compatibles OpenAI | `https://api.tokenlab.sh/v1` |
| `tokenlab-responses` | `openai-responses` | Workflows OpenAI Responses qui s'attendent à la sémantique `/v1/responses` | `https://api.tokenlab.sh/v1` |
| `tokenlab-claude` | `anthropic-messages` | API Messages native de Claude | `https://api.tokenlab.sh` |
| `tokenlab-gemini` | `google-generative-ai` | Format API Gemini natif | `https://api.tokenlab.sh` |
| `tokenlab-minimax` | `anthropic-messages` | Routage MiniMax natif | `https://api.tokenlab.sh` |

<Warning>
N'utilisez le suffixe `/v1` que pour `openai-completions` et `openai-responses`.

Les fournisseurs natifs tels que `anthropic-messages` et `google-generative-ai` doivent utiliser `https://api.tokenlab.sh` sans `/v1`, sinon OpenClaw peut construire un chemin upstream incorrect.
</Warning>

## Prérequis

- Une instance OpenClaw auto-hébergée
- OpenClaw **2026.9.4** nécessite Node.js `>=24.16.0 <25 || >=26.1.0` ([versions requises](https://github.com/openclaw/openclaw/blob/v2026.9.4/package.json)). Pour une autre version d'OpenClaw, vérifiez ses exigences.
- Une clé API TokenLab — [Get one here](https://tokenlab.sh/dashboard/api?tab=keys)

## Configuration

Modifiez votre configuration OpenClaw :

- **Auto-hébergé** : `~/.openclaw/openclaw.json`

Ajoutez les fournisseurs TokenLab sous `models.providers` :

Utilisez le même profil, `OPENCLAW_STATE_DIR` et `OPENCLAW_CONFIG_PATH` que la passerelle active, puis sauvegardez sa configuration. Placez `TOKENLAB_API_KEY` dans son `.env` global de confiance ou son environnement de service. Un export du terminal ou un `.env` de projet peut être invisible en arrière-plan. Voir [l’environnement](https://docs.openclaw.ai/help/environment).

Sauvegardez la configuration active. Ajoutez uniquement l’entrée TokenLab et conservez les fournisseurs, comptes, modèle par défaut et permissions existants. Si le nom est déjà utilisé, choisissez-en un autre et adaptez les commandes. Pour annuler, retirez uniquement votre entrée ou restaurez sa sauvegarde précédente.

```json5
{
  models: {
    mode: "merge",
    providers: {
      tokenlab: {
        api: "openai-completions",
        baseUrl: "https://api.tokenlab.sh/v1",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gpt-5.6-terra", name: "GPT-5.6 Terra" },
          { id: "deepseek-reasoner", name: "DeepSeek Reasoner" },
          { id: "qwen3-coder-flash", name: "Qwen 3 Coder Flash" }
        ]
      },
      "tokenlab-responses": {
        api: "openai-responses",
        baseUrl: "https://api.tokenlab.sh/v1",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gpt-5.6-terra", name: "GPT-5.6 Terra (Responses)" },
          { id: "gpt-5.2", name: "GPT-5.2 (Responses)" }
        ]
      },
      "tokenlab-claude": {
        api: "anthropic-messages",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "claude-sonnet-5", name: "Claude Sonnet 5" },
          { id: "claude-opus-5", name: "Claude Opus 5" }
        ]
      },
      "tokenlab-gemini": {
        api: "google-generative-ai",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gemini-3.5-flash", name: "Gemini 3.5 Flash" },
          { id: "gemini-2.5-pro", name: "Gemini 2.5 Pro" }
        ]
      },
      "tokenlab-minimax": {
        api: "anthropic-messages",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "minimax-m3", name: "MiniMax M3" }
        ]
      }
    }
  }
}
```

<Info>
Les 5 fournisseurs utilisent la **même clé API**. Vous n'avez besoin que d'un seul compte TokenLab.
</Info>

<Info>
Les tableaux `models` ci‑dessus montrent uniquement des exemples courants. Ajoutez d'autres IDs de modèle pour chaque fournisseur selon vos besoins.
</Info>

## Utilisation des modèles

OpenClaw référence toujours les modèles avec le format `provider/model` :

Avec **OpenClaw 2026.9.4**, sélectionnez le modèle uniquement pour la session actuelle avec `-s`. Conservez `agents.defaults.model`, les valeurs par défaut de l’agent et les permissions. `/model default -s` rétablit le modèle configuré par défaut pour cette session.

```text
/model tokenlab-claude/claude-sonnet-5 -s
/model default -s
```

### Exemples de modèles

| Fournisseur | Référence du modèle | Description |
|----------|---------------------|-------------|
| `tokenlab` | `tokenlab/gpt-5.6-terra` | Route compatible OpenAI |
| `tokenlab-responses` | `tokenlab-responses/gpt-5.6-terra` | Route Responses API |
| `tokenlab-claude` | `tokenlab-claude/claude-sonnet-5` | Route native Claude Messages |
| `tokenlab-gemini` | `tokenlab-gemini/gemini-3.5-flash` | Route native Gemini |
| `tokenlab-minimax` | `tokenlab-minimax/minimax-m3` | Route native MiniMax |

Parcourez tous les modèles disponibles sur [tokenlab.sh/models](https://tokenlab.sh/fr/models).

## Quand utiliser quel fournisseur

- `tokenlab` : choix par défaut pour la plupart des cas d'utilisation généraux d'agents et de chat.
- `tokenlab-responses` : utilisez-le lorsque votre workflow OpenClaw dépend explicitement de la sémantique OpenAI Responses.
- `tokenlab-claude` : utilisez-le lorsque vous souhaitez le comportement Messages natif de Claude.
- `tokenlab-gemini` : utilisez-le lorsque vous avez besoin du format de requête/réponse natif Gemini ou pour des intégrations existantes de type Gemini.
- `tokenlab-minimax` : utilisez-le lorsque vous voulez MiniMax sur sa route native.

Si vous n'avez pas besoin du comportement Gemini natif, vous pouvez toujours appeler les modèles Gemini via `tokenlab/gemini-*` sur la route compatible OpenAI.

## Erreurs courantes

<AccordionGroup>
  <Accordion title="Vous utilisez encore l'ancien tableau `providers` au niveau supérieur">
    La documentation actuelle d'OpenClaw utilise `models.providers`. Si vous conservez l'ancien format du tableau `providers` au niveau supérieur, OpenClaw peut ignorer la configuration ou échouer à résoudre les préfixes des fournisseurs comme prévu.
  </Accordion>
  <Accordion title="Oublier `/v1` sur `tokenlab-responses`">
    `openai-responses` mappe vers le chemin `/v1/responses` de TokenLab, donc `tokenlab-responses` doit utiliser `https://api.tokenlab.sh/v1`.
  </Accordion>
  <Accordion title="Ajouter `/v1` à `tokenlab-claude`, `tokenlab-gemini` ou `tokenlab-minimax`">
    `anthropic-messages` et `google-generative-ai` doivent utiliser `https://api.tokenlab.sh` sans `/v1`. L'ajout de `/v1` peut produire des chemins de requête incorrects.
  </Accordion>
  <Accordion title="OpenClaw prend-il toujours en charge Gemini natif ?">
    Oui. La documentation actuelle d'OpenClaw inclut toujours le fournisseur intégré `google` et prend également en charge les fournisseurs personnalisés utilisant `api: "google-generative-ai"`. Ainsi, `tokenlab-gemini` reste une route Gemini native valide pour les utilisateurs d'OpenClaw.
  </Accordion>
</AccordionGroup>

## Vérifier la configuration

Redémarrez la même instance et vérifiez modèle et fournisseur. `models status` sans `--probe` ne teste pas un appel au modèle. Les sondes réelles et messages peuvent consommer des tokens. Comparez réponse et requête TokenLab. Pour restaurer, choisissez l’ancien modèle et retirez seulement les entrées ajoutées.

```bash
openclaw gateway restart
openclaw models status
```
