La plupart des outils se connectent à TokenLab en modifiant la clé API et l’URL de base. La configuration exacte dépend du format d’API utilisé par l’outil.

| Format d’API | URL de base | Clients courants |
| --- | --- | --- |
| Chat Completions (Compatible OpenAI) | `https://api.tokenlab.sh/v1` | SDK OpenAI, nombreuses applications de chat et frameworks |
| OpenAI Responses | `https://api.tokenlab.sh/v1` | Clients Responses et outils utilisant les événements Responses |
| Anthropic Messages | `https://api.tokenlab.sh` | SDK Anthropic et outils pour Claude |
| Gemini | `https://api.tokenlab.sh` | Clients REST et SDK Gemini permettant un hôte personnalisé |

Le modèle choisi doit inclure le même format dans `accepted_request_formats`. Le streaming et les appels d’outils dépendent aussi des capacités du modèle et du client. Consultez les exemples dans [Formats d’API](/fr/guides/api-formats).

## Indicateurs de compatibilité

| Indicateur | Signification |
| --- | --- |
| **Compatible** | La configuration TokenLab de la page liée utilise les options documentées du client |
| **Compatible avec limites** | La configuration concerne certaines fonctions ou méthodes d’authentification ; les autres services du fournisseur conservent leurs propres conditions |

Ces indicateurs décrivent la configuration de la page liée. Les fonctions disponibles dépendent aussi du modèle choisi et de la version du client.

## Consommation dans les réponses en streaming

Les flux Chat Completions acceptent `stream_options: { include_usage: true }`, qui ajoute un dernier bloc de consommation avant la fermeture du flux. L’API Responses ne propose pas `include_usage` ; ses flux indiquent la consommation dans l’événement final.

## Ce qu’une clé API personnalisée ne remplace pas

Certains produits associent les appels au modèle à des fonctions hébergées par leur fournisseur. Une clé TokenLab peut servir aux requêtes de modèle proposées par les réglages BYOK, mais ne remplace pas les autres abonnements, services d’autocomplétion, fonctions de compte ou extensions propriétaires.

Si une mise à jour modifie la configuration d’un outil, consultez la page d’intégration actuelle plutôt que de recopier un ancien exemple de variables d’environnement.

## Avant d’utiliser une fonction

- Vérifiez que l’outil accepte une URL de base personnalisée pour le format nécessaire.
- Vérifiez que le modèle inclut ce format dans `accepted_request_formats`.
- Essayez le streaming et les appels d’outils si votre workflow en dépend.
- Conservez la clé API sur un appareil ou un serveur de confiance.
- Notez l’ID de requête lorsque vous signalez un échec.
