---

## Paramètre de chemin

<ParamField path="model" type="string" required>
  ID du modèle, tel que `gpt-5.6-terra` ou `claude-sonnet-4-6`.
</ParamField>

## Réponse

<ResponseField name="id" type="string">ID du modèle.</ResponseField>
<ResponseField name="object" type="string">Toujours `model`.</ResponseField>
<ResponseField name="owned_by" type="string">Créateur du modèle.</ResponseField>
<ResponseField name="tokenlab" type="object">
  Informations sur le modèle TokenLab, incluant les capacités, les prix, les unités de facturation, les limites de contexte, les formats d'API acceptés, les opérations et le statut du cycle de vie.
</ResponseField>

Les champs `tokenlab` courants incluent :

- `capabilities` : capacités textuelles, d'image, vidéo, audio et autres.
- `pricing` : prix publics actuels.
- `max_input_tokens` et `max_output_tokens` : limites de contexte et de sortie.
- `accepted_request_formats` : formats d'API pris en charge.
- `supported_operations` : opérations telles que la conversion de texte en image ou d'image en vidéo.
- `lifecycle` : disponibilité, date de sortie, date de dépréciation ou modèle de remplacement.

Certains modèles multimédias incluent également un statut de recommandation et une heure de mise à jour. Les recommandations peuvent changer en fonction de la disponibilité et des performances, il ne faut donc pas coder leur ordre en dur.

## Exemple

```bash
curl "https://api.tokenlab.sh/v1/models/gpt-5.6-terra"
```

```json
{
  "id": "gpt-5.6-terra",
  "object": "model",
  "owned_by": "openai",
  "tokenlab": {
    "category": "chat",
    "capabilities": ["coding", "json-mode", "prompt-cache", "reasoning", "tool-use", "vision"],
    "accepted_request_formats": ["openai_chat_completions", "openai_responses"]
  }
}
```

Un modèle inconnu renvoie `404 model_not_found`.
