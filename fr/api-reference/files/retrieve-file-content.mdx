## Aperçu

Ce point de terminaison sert principalement la récupération du contenu des fichiers de l’API Batch compatible avec OpenAI de TokenLab.

Lorsque la requête active le mode de compatibilité Anthropic Files, la même route peut aussi relayer le contenu d’origine du fichier stocké pour l’espace de travail lié.


Sans en-têtes Anthropic, cette route télécharge le contenu des fichiers de lot ou proxifie le contenu d’un fichier image/référence lié lorsque le fournisseur le permet.
## Remarques

- Les fichiers d'entrée de lot doivent utiliser `purpose=batch`.
- Utilisez `purpose=batch_output` pour vous concentrer sur les fichiers de sortie générés.
- `completion_window` est actuellement `24h`.
- L'ordre de sortie n'est pas garanti ; il faut toujours faire correspondre par `custom_id`.
- Le streaming n'est pas pris en charge à l'intérieur des éléments de lot.

## Exemple

<RequestExample>
```bash cURL
curl -X GET "https://api.tokenlab.sh/v1/files/file_abc123/content" \
  -H "Authorization: Bearer sk-your-api-key" \
  --output batch-output.jsonl
```
</RequestExample>

## Requête / Réponse

Utilisez le panneau OpenAPI interactif ci-dessus pour le schéma exact.

## Conseils opérationnels

- Utilisez `custom_id` pour la réconciliation idempotente en aval.
- Attendez-vous à recevoir `output_file_id` et `error_file_id` uniquement après que le travailleur finalise le lot.

## Types de contenu

Le contenu des fichiers batch est renvoyé en JSONL ou en texte brut. Le contenu des références d'image créées par TokenLab peut être transmis comme contenu binaire lorsque le fournisseur de fichiers sous-jacent prend en charge la récupération du contenu.

## Champs importants

<ResponseField name="body" type="binary|string">Contenu du fichier. Enregistrez-le ou analysez-le selon `Content-Type` ; analysez le JSONL ligne par ligne.</ResponseField>
<ResponseField name="custom_id" type="string">ID permettant d’associer un élément d’entrée du lot à son résultat.</ResponseField>
