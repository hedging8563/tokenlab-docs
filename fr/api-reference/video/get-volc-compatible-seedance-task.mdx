## Aperçu

Ces points de terminaison s’adressent aux équipes qui utilisent déjà la structure de tâche Seedance de style Volc. L’authentification utilise votre clé API TokenLab Bearer. L’ID de tâche retourné commence par `cgt-`; interrogez le statut jusqu’à ce que `status` devienne `succeeded`, `failed`, `cancelled` ou `expired`.

<Warning>
Ne réutilisez ni l’énumération ni la structure de réponse v1. `/v1/tasks/{id}` utilise `pending`, `processing`, `completed` et `failed` ; ce point de terminaison utilise l’énumération v3 ci-dessus. En v3, `duration` est une chaîne lorsqu’il est présent et `error` n’apparaît qu’en cas d’échec.
</Warning>

Voir aussi [Modèles vidéo Seedance 2.0](/fr/guides/seedance-2-video) et [Génération vidéo](/fr/guides/video-generation).

## Format de réponse

La réponse utilise `queued`, `running`, `succeeded`, `failed`, `cancelled` ou `expired`. Une tâche réussie retourne `content.video_url`; `content.last_frame_url`, les champs officiels de génération et `usage` peuvent aussi apparaître. `error` n’est présent qu’en cas d’échec. Aucun champ TokenLab tel que `progress`, `return_last_frame`, `watermark`, `priority` ou `camera_fixed` n’est ajouté.

## Exemple

```bash
curl https://api.tokenlab.sh/api/v3/contents/generations/tasks/cgt-20260102030405-a1b2c \
  -H "Authorization: Bearer $TOKENLAB_API_KEY"
```
