## Aperçu

OpenAI Codex est un outil en ligne de commande open-source (CLI) qui sert d'agent de codage léger, capable de lire, modifier et exécuter du code dans le terminal. Il est construit sur des modèles GPT et optimisé pour la génération de code.

Pour TokenLab, Codex CLI peut utiliser `/v1/responses`, mais vous devez le considérer comme un chemin de compatibilité avancé. Certaines fonctionnalités spécifiques à Responses ne sont pas garanties sur tous les modèles et chemins routés.

La compaction distante de Codex CLI est prise en charge sur `POST /v1/responses/compact`. Codex envoie le `model` de la session courante dans `body.model` pour `/compact` et l'auto-compactage, donc le modèle utilisé pour compacter doit être disponible sur le chemin Responses. Ne configurez pas `/v1/compact`.

## Configuration requise

Suivez le [guide CLI officiel](https://learn.chatgpt.com/docs/codex/cli) pour macOS, Linux ou Windows. Windows natif et WSL sont distincts ; voir le [guide Windows](https://learn.chatgpt.com/docs/windows/windows-sandbox). npm est une option, pas un prérequis des binaires natifs.

## Installation

```bash
npm install -g @openai/codex
```

Vérifier l'installation :

```bash
codex --version
```

## Configuration

### Étape 1 : Définir la clé API

**Temporaire (session en cours) :**

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

**Configuration permanente :**

Ajouter à `~/.bashrc`, `~/.zshrc` ou `~/.bash_profile` :

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

Puis rechargez :

```bash
source ~/.zshrc  # or source ~/.bashrc
```

### Étape 2 : Configurer config.toml

Intégrez ces paramètres dans votre fichier utilisateur `~/.codex/config.toml` sans remplacer tout le fichier. Conservez vos autres fournisseurs, comptes, paramètres de sandbox et règles d’approbation. Les paramètres du fournisseur et de l’authentification doivent figurer dans la configuration utilisateur, pas dans le fichier `.codex/config.toml` d’un projet. Consultez le [guide officiel de configuration](https://learn.chatgpt.com/docs/config-file/config-advanced#custom-model-providers).

Pour conserver le fournisseur par défaut, dès Codex 0.134.0, enregistrez cet exemple dans `~/.codex/tokenlab.config.toml` et lancez `codex --profile tokenlab`. Utilisez le véritable `CODEX_HOME` s’il est personnalisé. Ne créez pas d’ancienne table `[profiles.tokenlab]`, ne remplacez pas `auth.json` et ne modifiez ni connexion ni autorisations. Relancez sans ce profil pour revenir en arrière.

Dans chaque groupe de commandes ci-dessous, choisissez **Profil TokenLab** pour `tokenlab.config.toml`. Utilisez **TokenLab par défaut** uniquement après avoir intégré les paramètres dans `config.toml`. La commande `codex` seule utilise la configuration par défaut, sans reprendre le profil choisi dans une session précédente.

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"

[model_providers.tokenlab]
env_key = "TOKENLAB_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000
```

Ce mode WebSocket est un pont Responses-over-WebSocket pour les clients Codex. Il n’accepte que les événements officiels `response.create` ; `stream` est implicite, et `background` ainsi que `response.cancel` ne sont pas disponibles sur ce transport. Ce n’est pas l’API OpenAI Realtime et il n’accepte pas `session.update`, `conversation.item.*`, `input_audio_buffer.*`, l’audio binaire ni les enveloppes Realtime imbriquées `response.create.response`.

<Note>
Créez le fichier de configuration choisi s’il n’existe pas. Après modification, démarrez une nouvelle session avec la commande correspondante ci-dessous.
</Note>

Codex utilise actuellement `wire_api = "responses"`, pas `chat/completions`. Omettez `requires_openai_auth` ou utilisez false pour que ce fournisseur lise `env_key`.

<Note>
TokenLab transmet au mieux les champs Responses inconnus sans rétrograder silencieusement la requête vers Chat Completions. L’upstream sélectionné décide si le champ ou la combinaison est pris en charge.
</Note>

## Utilisation de base

**Démarrer le mode interactif :**

<CodeGroup>
```bash Profil TokenLab
codex --profile tokenlab
```

```bash TokenLab par défaut
codex
```
</CodeGroup>

**Commande directe :**

<CodeGroup>
```bash Profil TokenLab
codex --profile tokenlab "Fix the bug in main.py line 42"
```

```bash TokenLab par défaut
codex "Fix the bug in main.py line 42"
```
</CodeGroup>

**Spécifier le modèle :**

<CodeGroup>
```bash Profil TokenLab
codex --profile tokenlab -m gpt-5.6-sol "Build a REST API server"
```

```bash TokenLab par défaut
codex -m gpt-5.6-sol "Build a REST API server"
```
</CodeGroup>

## Modèles recommandés

| Modèle | Idéal pour |
|-------|------------|
| `gpt-5.6-sol` | Choix par défaut optimal pour le codage et le raisonnement |
| `gpt-5-mini` | Solution de repli plus rapide et moins coûteuse pour les flux de travail de codage |
| `claude-sonnet-4-6` | Revue de code, documentation |

## Commandes interactives

| Commande | Description |
|---------|-------------|
| `/help` | Afficher l'aide |
| `/exit` or `Ctrl+C` | Quitter |
| `/clear` | Effacer la conversation |
| `/status` | Afficher le modèle actif, les permissions et les tokens utilisés |
| `/model <name>` | Changer de modèle |

## Vérifier la configuration

Vérifiez uniquement si la variable d’environnement est définie, sans afficher sa valeur. Cette vérification ne valide pas la clé :

```bash
if [ -n "${TOKENLAB_API_KEY:-}" ]; then
  printf '%s\n' 'TOKENLAB_API_KEY is set'
else
  printf '%s\n' 'TOKENLAB_API_KEY is not set'
fi
```

Lancez Codex et exécutez `/status` pour vérifier le modèle actif et les permissions. Si vous utilisez un profil, lancez ce même profil. Consultez la [commande officielle de statut](https://learn.chatgpt.com/docs/developer-commands?surface=cli#inspect-the-session-with-status).

Lorsque vous souhaitez envoyer une vraie requête, exécutez la commande ci-dessous. Elle utilise votre solde TokenLab. Vérifiez la réponse et l’entrée correspondante dans [Requêtes](https://tokenlab.sh/dashboard/runs?section=requests). Une variable définie ou un démarrage réussi ne prouve pas à lui seul qu’une requête a abouti.

<CodeGroup>
```bash Profil TokenLab
codex --profile tokenlab "Reply only with OK. Do not use tools or modify files."
```

```bash TokenLab par défaut
codex "Reply only with OK. Do not use tools or modify files."
```
</CodeGroup>

## Dépannage

<AccordionGroup>
  <Accordion title="Erreur de connexion">
    - Vérifiez que `base_url` dans config.toml est exactement `https://api.tokenlab.sh/v1`
    - Vérifiez la connectivité réseau
    - Assurez-vous qu'aucun proxy n'interfère
  </Accordion>

  <Accordion title="Échec d'authentification">
    Après une mise à niveau vers Codex 0.149.0 ou une version ultérieure, les erreurs `API_KEY_REQUIRED` ou `401 Unauthorized` peuvent apparaître si un fournisseur personnalisé utilise uniquement `auth.json` alors que `requires_openai_auth` est absent ou défini sur `false`. Ce guide utilise `env_key` pour lire la clé depuis `TOKENLAB_API_KEY` et ne dépend pas d’`auth.json`. Laissez `requires_openai_auth` absent ou défini sur `false` ; cette configuration ne nécessite ni de le passer à `true` ni de remplacer `auth.json`.

    - Vérifiez que la configuration ou le profil réellement utilisé contient `env_key = "TOKENLAB_API_KEY"`. Si vous avez enregistré les paramètres dans `tokenlab.config.toml`, lancez `codex --profile tokenlab`
    - Vérifiez que `TOKENLAB_API_KEY` est définie dans le terminal depuis lequel vous lancez Codex. Après avoir défini cette variable, redémarrez Codex depuis ce terminal
    - Vérifiez que la clé commence par `sk-`
    - Assurez-vous que la clé est active dans le tableau de bord TokenLab
  </Accordion>

  <Accordion title="Modèle introuvable">
    - Vérifiez que le nom du modèle correspond exactement
    - Vérifiez la disponibilité du modèle sur [tokenlab.sh/en/models](https://tokenlab.sh/fr/models)
  </Accordion>

  <Accordion title="Champ natif Responses rejeté">
    - Certains champs ne sont disponibles que sur `/v1/responses` lorsque TokenLab peut garantir ce comportement pour le modèle et le chemin sélectionnés
    - Si vous voyez `unsupported_request_field`, supprimez ce champ ou passez à un flux de travail qui n'en dépend pas
  </Accordion>

  <Accordion title="/compact ou l'auto-compactage échoue">
    - Codex CLI appelle `POST /v1/responses/compact`, pas `/v1/compact`
    - La requête de compaction utilise le `model` de la session courante, ce modèle doit donc être disponible sur le chemin Responses
    - Conservez `wire_api = "responses"` et `base_url = "https://api.tokenlab.sh/v1"`
  </Accordion>
</AccordionGroup>
