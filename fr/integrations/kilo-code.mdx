## Aperçu

<Note>
**Type** : agent de code IDE et CLI

**Chemin principal** : Chat Completions compatible OpenAI

**Support** : chemin officiel de fournisseur personnalisé
</Note>

[Kilo Code](https://kilo.ai/docs/ai-providers/openai-compatible) prend en charge les fournisseurs compatibles OpenAI dans l'extension VS Code et la CLI.

## Installation et interface

Installez le canal préversion de **Kilo Code** dans VS Code ou la CLI :

```bash
npm install -g @kilocode/cli
kilo --version
```

Ouvrez **Settings → Providers → Custom provider**.

| Champ | Valeur |
|---|---|
| Provider ID | `tokenlab` |
| Display name | `TokenLab` |
| Provider API | **OpenAI Compatible** |
| Base URL | `https://api.tokenlab.sh/v1` |
| API key | Votre clé API TokenLab |
| Model | `kimi-k3` |

Kilo détecte les modèles via `/v1/models`. Après enregistrement, choisissez `tokenlab/kimi-k3`.

## Configuration CLI

Placez la clé dans une variable d'environnement et modifiez le fichier global approuvé `~/.config/kilo/kilo.jsonc` :

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

```jsonc
{
  "$schema": "https://app.kilo.ai/config.json",
  "model": "openai-compatible/kimi-k3",
  "provider": {
    "openai-compatible": {
      "options": {
        "apiKey": "{env:TOKENLAB_API_KEY}",
        "baseURL": "https://api.tokenlab.sh/v1"
      },
      "models": {
        "kimi-k3": {
          "name": "Kimi K3",
          "tool_call": true,
          "reasoning": true,
          "limit": { "context": 1048576, "output": 131072 }
        }
      }
    }
  }
}
```

Redémarrez Kilo puis exécutez `kilo models`. `{env:...}` n'est résolu que dans une configuration globale ou administrée approuvée. N'écrivez pas la vraie clé dans une configuration de projet susceptible d'être versionnée.
