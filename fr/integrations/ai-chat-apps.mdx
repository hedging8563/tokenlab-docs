## Aperçu

La plupart des applications de chat IA générales se connectent à TokenLab via le chemin de chat standard compatible avec OpenAI.

En pratique, cela signifie :
- utilisez `https://api.tokenlab.sh/v1` comme URL de base, sauf si l'application demande explicitement une URL de point de terminaison complète
- utilisez votre clé API TokenLab comme clé API de style OpenAI
- choisissez les modèles que l'application peut utiliser dans un flux de travail de chat standard

<Note>
Les applications de chat générales sont généralement **orientées chat-completions**, et non des clients WebSocket pour les réponses Codex. Pour Codex CLI/App, Cursor ou d'autres outils de codage nécessitant un comportement spécifique aux réponses, utilisez plutôt les guides d'intégration dédiés.
</Note>

<Note>
**Type** : Application de chat

**Chemin principal** : chat-completions compatible OpenAI

**Niveau de support** : Chemin pris en charge
</Note>

## Applications prises en charge

| Application | Plateforme | Notes |
|-------------|----------|-------|
| Open WebUI | Web, Auto-hébergé | Choix populaire auto-hébergé avec connexions compatibles OpenAI |
| LibreChat | Web, Auto-hébergé | Espace de travail de chat multi-fournisseurs avec points de terminaison OpenAI personnalisés |
| LobeChat | Web, Bureau, Auto-hébergé | Support robuste des fournisseurs personnalisés |
| Cherry Studio | Windows, macOS, Linux | Bon flux de fournisseur compatible OpenAI |
| Chatbox | Windows, macOS, Linux | Configuration simple compatible OpenAI |
| DeepChat | Windows, macOS, Linux | Client de bureau avec paramètres de fournisseur compatibles OpenAI |
| Jan | Bureau, Auto-hébergé | Application locale avec fournisseurs distants compatibles OpenAI |
| TypingMind | Web, Bureau | Utilise un style de point de terminaison personnalisé |
| NextChat | Web, Auto-hébergé | Client léger de style ChatGPT avec remplacement de l'URL de base |
| ChatWise | Windows, macOS | Modèle de fournisseur personnalisé standard |

## Valeurs de connexion par défaut

| Champ | Valeur |
|-------|-------|
| URL de base | `https://api.tokenlab.sh/v1` |
| Clé API | `sk-your-tokenlab-key` |
| Type d'API | Compatible OpenAI |

Si une application demande une **URL de point de terminaison complète** au lieu d'une URL de base, utilisez :
- Chat Completions : `https://api.tokenlab.sh/v1/chat/completions`

## Exemples de configurations d'applications

<Tabs>
  <Tab title="LobeChat">
    **LobeChat auto-hébergé**

    ```bash
    OPENAI_API_KEY=sk-your-tokenlab-key
    OPENAI_PROXY_URL=https://api.tokenlab.sh/v1
    ```

    **LobeChat Cloud**
    1. Ouvrez **Settings** → **AI Service Provider**
    2. Sélectionnez **OpenAI**
    3. Entrez votre clé API TokenLab
    4. Définissez le point de terminaison personnalisé sur `https://api.tokenlab.sh/v1`
  </Tab>

  <Tab title="Cherry Studio">
    1. Ouvrez **Settings** → **Model Provider**
    2. Ajoutez un fournisseur **OpenAI-compatible**
    3. Entrez :
       - **Name** : TokenLab
       - **API Base URL** : `https://api.tokenlab.sh/v1`
       - **API Key** : `sk-your-tokenlab-key`
    4. Ajoutez les modèles que vous souhaitez utiliser
  </Tab>

  <Tab title="Chatbox">
    1. Ouvrez **Settings** → **AI Model**
    2. Choisissez **OpenAI API Compatible**
    3. Entrez :
       - **API Host** : `https://api.tokenlab.sh/v1`
       - **API Key** : `sk-your-tokenlab-key`
       - **Model** : `gpt-5.4-mini` ou `claude-sonnet-5`
  </Tab>

  <Tab title="TypingMind">
    1. Ouvrez **Settings**
    2. Choisissez **Custom Endpoint**
    3. Entrez :
       - **Endpoint URL** : `https://api.tokenlab.sh/v1/chat/completions`
       - **API Key** : `sk-your-tokenlab-key`
    4. Configurez les modèles que vous souhaitez exposer
  </Tab>

  <Tab title="Open WebUI">
    1. Ouvrez **Admin Settings** → **Connections**
    2. Ajoutez une connexion **OpenAI-compatible**
    3. Entrez :
       - **Base URL** : `https://api.tokenlab.sh/v1`
       - **API Key** : `sk-your-tokenlab-key`
    4. Enregistrez et sélectionnez les modèles que vous souhaitez exposer
  </Tab>

  <Tab title="DeepChat">
    1. Ouvrez **Settings** -> **Model Provider**
    2. Ajoutez un fournisseur compatible OpenAI
    3. Entrez :
       - **Base URL** : `https://api.tokenlab.sh/v1`
       - **API Key** : `sk-your-tokenlab-key`
       - **Model** : `gpt-5.4-mini`
    4. Enregistrez et effectuez un test de chat
  </Tab>

  <Tab title="Jan">
    1. Ouvrez **Settings** -> **Providers**
    2. Ajoutez un fournisseur distant compatible OpenAI
    3. Entrez :
       - **Provider name** : TokenLab
       - **Base URL** : `https://api.tokenlab.sh/v1`
       - **API Key** : `sk-your-tokenlab-key`
    4. Sélectionnez `gpt-5.4-mini` ou un autre modèle TokenLab
  </Tab>

  <Tab title="LibreChat">
    Ajoutez un point de terminaison compatible OpenAI dans votre configuration de fournisseur LibreChat et pointez-le vers :

    ```yaml
    customEndpoints:
      - name: TokenLab
        apiKey: '${OPENAI_API_KEY}'
        baseURL: 'https://api.tokenlab.sh/v1'
        models:
          default: ['gpt-5.4-mini', 'gpt-5.4', 'claude-sonnet-5']
          fetch: false
    ```
  </Tab>
</Tabs>

## Conseils

<AccordionGroup>
  <Accordion title="Privilégiez l'URL de base lorsque l'application le permet">
    La plupart des applications sont plus faciles à configurer et moins fragiles lorsque vous fournissez `https://api.tokenlab.sh/v1` comme URL de base au lieu d'une URL de point de terminaison complète.
  </Accordion>

  <Accordion title="Utilisez d'abord des modèles plus petits">
    Commencez avec `gpt-5.4-mini` ou `deepseek-v4-flash` pour le chat quotidien, puis passez aux tâches de raisonnement plus lourdes avec `gpt-5.4` ou `claude-opus-4-8`.
  </Accordion>

  <Accordion title="Gardez les outils de codage séparés">
    Les applications de chat générales et les agents de codage nécessitent souvent un comportement de point de terminaison différent. Gardez les outils de type Codex/Cursor sur leurs pages d'intégration dédiées.
  </Accordion>
</AccordionGroup>

## Dépannage

<AccordionGroup>
  <Accordion title="Erreur de connexion">
    - Vérifiez que l'URL de base est exactement `https://api.tokenlab.sh/v1`
    - Supprimez les barres obliques finales si l'application ajoute automatiquement des chemins
    - Si l'application demande une URL de point de terminaison complète, utilisez `https://api.tokenlab.sh/v1/chat/completions`
  </Accordion>

  <Accordion title="401 Non autorisé">
    - Vérifiez à nouveau votre clé API
    - Confirmez que la clé est active dans le tableau de bord TokenLab
    - Assurez-vous qu'il n'y a pas d'espaces ou de sauts de ligne supplémentaires
  </Accordion>

  <Accordion title="Modèle non disponible">
    - Vérifiez exactement le nom du modèle
    - Essayez une valeur par défaut largement prise en charge comme `gpt-5.4-mini`, `deepseek-v4-flash` ou `claude-sonnet-5`
    - Vérifiez la disponibilité actuelle dans la documentation ou le tableau de bord TokenLab
  </Accordion>
</AccordionGroup>
