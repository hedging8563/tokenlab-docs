## Vue d’ensemble

OpenCode est un assistant de codage IA open-source qui s’exécute dans votre terminal. Il prend en charge plusieurs fournisseurs de LLM et peut être configuré pour utiliser l’API de TokenLab afin d’accéder à plus de 300 modèles.

## Installation

[OpenCode](https://opencode.ai/docs/)

```bash
npm install -g opencode-ai@1.18.31
```

Vérifiez l’installation :

```bash
opencode --version
```

## Configuration

### Étape 1 : Définir les variables d’environnement

Définissez `TOKENLAB_API_KEY` avec les étapes du [démarrage rapide](/fr/quickstart) pour macOS, Linux, WSL ou Windows PowerShell, sans placer la clé dans l’historique. Lancez OpenCode depuis ce terminal. Pour un usage permanent, utilisez un gestionnaire local de secrets plutôt qu’une clé en clair dans le profil du shell.

### Étape 2 : Configurer OpenCode

La configuration ci-dessous a été vérifiée avec **OpenCode 1.18.31**. Les autres versions nécessitent une vérification distincte selon leur documentation officielle.

Enregistrez cette configuration dans un fichier distinct `~/.config/opencode/tokenlab.jsonc`. Si `XDG_CONFIG_HOME` est défini, utilisez `opencode/tokenlab.jsonc` dans ce répertoire. Conservez les fichiers habituels `opencode.json` / `opencode.jsonc`, les comptes, le modèle par défaut et les autorisations. Ce fichier ne se charge que pour un lancement qui le sélectionne avec `OPENCODE_CONFIG`. Si le fichier ou le nom du fournisseur est déjà utilisé, choisissez un autre nom et adaptez les commandes.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "tokenlab": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "TokenLab",
      "options": {
        "baseURL": "https://api.tokenlab.sh/v1",
        "apiKey": "{env:TOKENLAB_API_KEY}"
      },
      "models": {
        "gpt-5.6-terra": {
          "name": "GPT-5.6 Terra"
        },
        "gpt-5.6-luna": {
          "name": "GPT-5.6 Luna"
        }
      }
    }
  }
}
```

<Note>
Cette configuration envoie des Chat Completions avec `@ai-sdk/openai-compatible`. Vérifiez dans les détails actuels du modèle la prise en charge de Chat Completions et des outils nécessaires. Cet exemple ne prouve pas la compatibilité avec d’autres protocoles ou versions.
</Note>

Facultatif : l’[assistant de configuration réversible pour OpenCode](https://github.com/hedging8563/tokenlab-skills/blob/247bb17c53754c8288d2d5cb00824fbd9f32899b/skills/tokenlab-api-integration/references/opencode_setup.md) permet de prévisualiser, appliquer et restaurer le fichier original avec Python 3.11+. Le plugin TokenLab Skills **0.1.2** contient ces scripts ; un Skill autonome convient aussi après sa mise à jour vers une version qui les inclut. Pour un plugin ou un Skill autonome déjà installé, suivez les [instructions de mise à jour du README](https://github.com/hedging8563/tokenlab-skills/blob/247bb17c53754c8288d2d5cb00824fbd9f32899b/README.md#update-an-existing-installation) et vérifiez la présence du script. La configuration manuelle de cette page reste utilisable sans cet assistant.

## Utilisation de base

Définissez la clé selon le démarrage rapide, puis chargez ce fichier et sélectionnez explicitement le modèle pour ce lancement uniquement. Adaptez les chemins et noms personnalisés. Conservez les réglages existants de `OPENCODE_CONFIG` ou `OPENCODE_CONFIG_CONTENT` dans un environnement de lancement séparé ; les réglages de projet ou gérés peuvent rester prioritaires.

<CodeGroup>
```bash macOS / Linux / WSL
OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode models tokenlab
OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode --model tokenlab/gpt-5.6-terra
```

```powershell Windows PowerShell
$tokenlabConfigRoot = if ($env:XDG_CONFIG_HOME) { $env:XDG_CONFIG_HOME } else { Join-Path $HOME '.config' }
$previousConfig = $env:OPENCODE_CONFIG
try {
  $env:OPENCODE_CONFIG = Join-Path $tokenlabConfigRoot 'opencode/tokenlab.jsonc'
  opencode models tokenlab
  opencode --model tokenlab/gpt-5.6-terra
} finally {
  if ($null -eq $previousConfig) {
    Remove-Item Env:OPENCODE_CONFIG -ErrorAction SilentlyContinue
  } else {
    $env:OPENCODE_CONFIG = $previousConfig
  }
}
```
</CodeGroup>

La liste des modèles vérifie le chargement local, pas la validité de la clé ni la réussite d’un appel réel. Un prompt utilise le solde TokenLab et OpenCode peut envoyer des requêtes auxiliaires facturées séparément, comme la génération d’un titre. Vérifiez la réponse et les [enregistrements correspondants](https://tokenlab.sh/dashboard/runs?section=requests).

Lancez sans ce fichier pour retrouver votre configuration habituelle. N’ajoutez pas `OPENCODE_CONFIG` au profil du shell pour suivre ce guide. Pour annuler la configuration manuelle, supprimez uniquement le fichier distinct que vous avez créé, ou restaurez sa sauvegarde s’il existait déjà.

## Modèles disponibles

| Modèle | Idéal pour |
|-------|----------|
| `gpt-5.6-terra` | Tâches complexes, architecture du code |
| `gpt-5.6-luna` | Corrections rapides, requêtes simples |
| `claude-sonnet-4-6` | Revue de code, documentation |
| `claude-opus-4-6` | Raisonnement complexe |
| `gemini-3.5-flash` | Réponses rapides |

## Commandes courantes

**Analyser du code :**

```bash
OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode run --model tokenlab/gpt-5.6-terra "What does this function do?" < src/utils.ts
```

**Générer du code :**

```bash
OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode run --model tokenlab/gpt-5.6-terra "Create a REST API with Express"
```

**Examiner les modifications :**

```bash
git diff | OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode run --model tokenlab/gpt-5.6-terra "Review these changes"
```

**Corriger les erreurs :**

```bash
OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode run --model tokenlab/gpt-5.6-terra "Fix the TypeScript errors in this project"
```

## Commandes interactives

| Commande | Description |
|---------|-------------|
| `/help` | Afficher les commandes disponibles |
| `/models` | Basculer vers un autre modèle |
| `/clear` | Effacer l’historique de la conversation |
| `/exit` | Quitter OpenCode |

## Dépannage

<AccordionGroup>
  <Accordion title="Erreur de connexion">
    - Vérifiez que `options.baseURL` est défini sur `https://api.tokenlab.sh/v1`
    - Vérifiez la connectivité réseau
    - Essayez `curl https://api.tokenlab.sh/v1/models` pour tester
  </Accordion>

  <Accordion title="Échec de l’authentification">
    - Vérifiez que la variable d’environnement `TOKENLAB_API_KEY` est définie
    - Vérifiez que `options.apiKey` référence `{env:TOKENLAB_API_KEY}` ou une autre source secrète valide
    - Vérifiez que la clé commence par `sk-`
    - Assurez-vous que la clé est active dans le tableau de bord TokenLab
  </Accordion>

  <Accordion title="Modèle introuvable">
    - Vérifiez que le nom du modèle dans la configuration correspond exactement
    - Vérifiez la disponibilité du modèle sur [tokenlab.sh/en/models](https://tokenlab.sh/fr/models)
  </Accordion>
</AccordionGroup>
