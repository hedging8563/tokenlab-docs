## Vue d’ensemble

Gemini CLI **0.60.0** documente `GOOGLE_GEMINI_BASE_URL` pour l’authentification par clé API. Utilisez le point d’accès Gemini natif de TokenLab avec un modèle actuel prenant en charge `gemini_generate_content`. Voir la [configuration officielle](https://geminicli.com/docs/reference/configuration/) et l’[authentification](https://geminicli.com/docs/get-started/authentication/). Cette configuration ne fait pas passer un abonnement Google par TokenLab.

## Installation

```bash
npm install -g @google/gemini-cli@0.60.0
gemini --version
```

## Configuration

Définissez `TOKENLAB_API_KEY` avec les étapes du [démarrage rapide](/fr/quickstart) pour macOS, Linux, WSL ou Windows PowerShell, sans placer la clé dans l’historique. Lancez Gemini CLI depuis ce terminal. Pour un usage permanent, utilisez un gestionnaire local de secrets plutôt qu’une clé en clair dans le profil du shell.

Conservez votre connexion Google et votre configuration actuelle. Pour TokenLab, choisissez une racine libre comme `~/.gemini-tokenlab` (`$HOME` dans PowerShell) et créez son dossier `.gemini`. Copiez votre `.gemini/settings.json` et les fichiers de politique nécessaires aux emplacements correspondants, en conservant permissions, sandbox et autres réglages. Fusionnez le champ d’authentification ci-dessous uniquement dans cette copie ; créez le fichier s’il n’existe pas. Ne copiez pas les caches OAuth et ne supprimez pas vos identifiants initiaux. Respectez les politiques d’authentification gérées.

```json
{
  "security": {
    "auth": {
      "selectedType": "gemini-api-key"
    }
  }
}
```

## Utilisation

Le lancement ci-dessous utilise `~/.gemini-tokenlab/.gemini/settings.json`. Adaptez le chemin si vous avez choisi une autre racine. Confirmez le dossier de travail via la demande de confiance habituelle et conservez les règles d’approbation des outils. Le modèle est choisi explicitement pour cette session.

<CodeGroup>
```bash macOS / Linux / WSL
GEMINI_CLI_HOME="$HOME/.gemini-tokenlab" GEMINI_API_KEY="${TOKENLAB_API_KEY:?Set TOKENLAB_API_KEY first}" GOOGLE_GEMINI_BASE_URL=https://api.tokenlab.sh gemini --model gemini-3.5-flash
```

```powershell Windows PowerShell
if (-not $env:TOKENLAB_API_KEY) { throw 'Set TOKENLAB_API_KEY first' }
$previous = @{}
$previous['GEMINI_CLI_HOME'] = [Environment]::GetEnvironmentVariable('GEMINI_CLI_HOME', 'Process')
$previous['GEMINI_API_KEY'] = [Environment]::GetEnvironmentVariable('GEMINI_API_KEY', 'Process')
$previous['GOOGLE_GEMINI_BASE_URL'] = [Environment]::GetEnvironmentVariable('GOOGLE_GEMINI_BASE_URL', 'Process')
try {
  $env:GEMINI_CLI_HOME = (Join-Path $HOME '.gemini-tokenlab')
  $env:GEMINI_API_KEY = $env:TOKENLAB_API_KEY
  $env:GOOGLE_GEMINI_BASE_URL = 'https://api.tokenlab.sh'
  gemini --model gemini-3.5-flash
} finally {
  foreach ($name in $previous.Keys) {
    [Environment]::SetEnvironmentVariable($name, $previous[$name], 'Process')
  }
}
```
</CodeGroup>

Ces variables s’appliquent uniquement à ce lancement ; le compte, le modèle par défaut et les permissions enregistrés sont conservés. Lancez normalement sans ces variables pour retrouver vos réglages. Ne les enregistrez pas dans le profil du shell.

## Vérification

Enregistrer les réglages ou lister les modèles ne valide ni la clé ni un appel terminé. Un prompt utilise le solde TokenLab. Vérifiez la réponse et son [enregistrement correspondant](https://tokenlab.sh/dashboard/runs?section=requests) avant de tester les outils ; les requêtes auxiliaires peuvent aussi être facturées.

```text
Reply only with TOKENLAB_CONNECTION_OK. Do not use tools or modify files.
```
