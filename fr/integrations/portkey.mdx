## Aperçu

Portkey Gateway peut acheminer les requêtes vers TokenLab en tant que fournisseur amont. L'option par défaut la plus sûre est celle des complétions de chat compatibles avec OpenAI ; utilisez Responses lorsque votre version de Portkey expose ce chemin pour TokenLab.

<Note>
**Type** : AI Gateway

**Chemins principaux** : Complétions de chat compatibles avec OpenAI et Responses

**Niveau de support** : Chemin pris en charge
</Note>

## Valeurs du fournisseur

| Champ | Valeur |
|-------|-------|
| Provider | `tokenlab` |
| Base URL | `https://api.tokenlab.sh/v1` |
| API key | `sk-your-tokenlab-key` |
| Modèle par défaut | `gpt-5.4-mini` |

## Complétions de chat

Utilisez TokenLab pour les requêtes de chat compatibles avec OpenAI :

```bash
curl https://your-portkey-gateway.example/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "x-portkey-provider: tokenlab" \
  -H "Authorization: Bearer sk-your-tokenlab-key" \
  -d '{
    "model": "gpt-5.4-mini",
    "messages": [{"role": "user", "content": "Say hello from TokenLab."}]
  }'
```

## Responses

Si votre build Portkey achemine les Responses de TokenLab, utilisez `gpt-5.5`, `gpt-5.4` ou `gpt-5.4-mini` avec `/v1/responses`.

## Note sur les endpoints natifs

TokenLab expose également directement les endpoints compatibles avec Anthropic Messages et Gemini. La possibilité de les utiliser via Portkey dépend du fournisseur Portkey et de la prise en charge des endpoints dans votre version déployée.
