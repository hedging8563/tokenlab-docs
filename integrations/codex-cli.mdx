## Overview




Codex CLI can connect to TokenLab through `/v1/responses`. The selected model must list `responses` in `accepted_request_formats`; features can vary by model.

Remote compaction uses `POST /v1/responses/compact`. Codex sends the current session model in `body.model`, so that model must also support Responses. Do not configure `/v1/compact`.

## System Requirements

Use the [official CLI installation guide](https://learn.chatgpt.com/docs/codex/cli) for macOS, Linux or Windows. Native Windows and WSL are separate environments; follow the [Windows guide](https://learn.chatgpt.com/docs/windows/windows-sandbox). The npm command below is one installation option, not a requirement for native binaries.


## Configuration

### Step 1: Set API Key

**Temporary (current session):**

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

**Permanent configuration:**

Add to `~/.bashrc`, `~/.zshrc`, or `~/.bash_profile`:

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

Then reload:

```bash
source ~/.zshrc  # or source ~/.bashrc
```

### Step 2: Configure config.toml

Merge these settings into your user-level `~/.codex/config.toml`; do not replace the entire file. Keep your other providers, accounts, sandbox settings, and approval rules. Provider and authentication settings belong in the user configuration, not a project’s `.codex/config.toml`. See the [official configuration guide](https://learn.chatgpt.com/docs/config-file/config-advanced#custom-model-providers).

To keep your current default provider, save the configuration below in `~/.codex/tokenlab.config.toml` and start `codex --profile tokenlab` on Codex 0.134.0 or later. Use the actual `CODEX_HOME` if customized. Do not create a legacy `[profiles.tokenlab]` table, overwrite `auth.json`, log out of your existing account, or change approval settings. To restore, start without this profile.

In each command group below, choose **TokenLab profile** for `tokenlab.config.toml`, or **TokenLab default** only after merging the settings into `config.toml`. A plain `codex` command uses your default configuration; it does not remember a profile selected in a previous session.

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"

[model_providers.tokenlab]
env_key = "TOKENLAB_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000
```

This WebSocket mode is a Responses-over-WebSocket bridge for Codex clients. It accepts only official `response.create` events; `stream` is implicit, and `background` and `response.cancel` are not available on this transport. It is not the OpenAI Realtime API and does not accept `session.update`, `conversation.item.*`, `input_audio_buffer.*`, binary audio, or nested Realtime `response.create.response` envelopes.

<Note>
Create the chosen configuration file if it does not exist. After editing it, start a new session with the matching command below.
</Note>

Current Codex uses `wire_api = "responses"`. Do not configure `chat/completions`. Keep `requires_openai_auth` unset or false for this custom provider so `env_key` is used.

<Note>
Responses requests are not converted to Chat Completions. Optional and future fields depend on the selected model.
</Note>

## Basic Usage

**Start interactive mode:**

<CodeGroup>
```bash TokenLab profile
codex --profile tokenlab
```

```bash TokenLab default
codex
```
</CodeGroup>

**Direct command:**

<CodeGroup>
```bash TokenLab profile
codex --profile tokenlab "Fix the bug in main.py line 42"
```

```bash TokenLab default
codex "Fix the bug in main.py line 42"
```
</CodeGroup>

**Specify model:**

<CodeGroup>
```bash TokenLab profile
codex --profile tokenlab -m gpt-5.6-sol "Build a REST API server"
```

```bash TokenLab default
codex -m gpt-5.6-sol "Build a REST API server"
```
</CodeGroup>

## Choose a model

Use a model that currently lists `responses` in `accepted_request_formats`. Compare candidates on your own coding tasks and check current prices on the [Models page](https://tokenlab.sh/en/models).

## Verify Configuration

Check whether the environment variable is set without printing its value. This check does not validate the key:

```bash
if [ -n "${TOKENLAB_API_KEY:-}" ]; then
  printf '%s\n' 'TOKENLAB_API_KEY is set'
else
  printf '%s\n' 'TOKENLAB_API_KEY is not set'
fi
```

Start Codex and run `/status` to check the active model and permissions. If you use a profile, start that same profile. See the [official status command](https://learn.chatgpt.com/docs/developer-commands?surface=cli#inspect-the-session-with-status).

When you are ready to make a real request, run the command below. It uses your TokenLab balance. Check the reply and the matching record in [Requests](https://tokenlab.sh/dashboard/runs?section=requests); an environment check or successful startup alone does not prove a request succeeded.

<CodeGroup>
```bash TokenLab profile
codex --profile tokenlab "Reply only with OK. Do not use tools or modify files."
```

```bash TokenLab default
codex "Reply only with OK. Do not use tools or modify files."
```
</CodeGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Connection Error">
    - Verify `base_url` in config.toml is exactly `https://api.tokenlab.sh/v1`
    - Check network connectivity
    - Ensure no proxy interference
  </Accordion>

  <Accordion title="Authentication Failed">
    After upgrading to Codex 0.149.0 or later, `API_KEY_REQUIRED` or `401 Unauthorized` can occur if a custom provider relies only on `auth.json` while `requires_openai_auth` is unset or `false`. This guide reads the key from `TOKENLAB_API_KEY` through `env_key` and does not rely on `auth.json`. Keep `requires_openai_auth` unset or `false`; this setup does not require changing it to `true` or overwriting `auth.json`.

    - Verify that the active configuration or profile contains `env_key = "TOKENLAB_API_KEY"`. If you saved the settings in `tokenlab.config.toml`, launch with `codex --profile tokenlab`.
    - Verify that `TOKENLAB_API_KEY` is set in the terminal used to launch Codex, then restart Codex from that terminal.
    - Check that the key starts with `sk-`
    - Ensure the key is active in TokenLab dashboard
  </Accordion>

  <Accordion title="Model Not Found">
    - Check model name matches exactly
    - Verify model availability at [tokenlab.sh/en/models](https://tokenlab.sh/en/models)
  </Accordion>

  <Accordion title="Responses-native field rejected">
    - Optional `/v1/responses` fields depend on the selected model
    - If you see `unsupported_request_field`, remove that field or switch to a workflow that does not depend on it
  </Accordion>

  <Accordion title="/compact or auto-compact fails">
    - Codex CLI calls `POST /v1/responses/compact`, not `/v1/compact`
    - The compaction request uses the current session `model`, so that model must be available on the Responses path
    - Keep `wire_api = "responses"` and `base_url = "https://api.tokenlab.sh/v1"`
  </Accordion>
</AccordionGroup>
