## Overview

Use the **OpenAI-API-compatible** model-provider plugin to connect Dify to TokenLab. Set the model type to **LLM**, **Completion mode** to **Chat**, and **API Type** to **Chat Completions API**. This guide uses Chat Completions.


## Prerequisites

- TokenLab account with API access
- Dify Cloud or self-hosted Dify

## Configuration Steps

### Step 1: Get Your API Key

1. Log into [TokenLab Dashboard](https://tokenlab.sh/dashboard)
2. Open [API Keys](https://tokenlab.sh/dashboard/api)
3. Create or copy an API key that starts with `sk-`

### Step 2: Configure the Provider

<Steps>
  <Step title="Open Model Providers">
    In Dify, go to **Settings** → **Model Providers**
  </Step>
  <Step title="Select OpenAI-API-compatible">
    Open **OpenAI-API-compatible**. If it is missing, install that model-provider plugin from the Dify Marketplace. Choose **Add model** to enter the TokenLab settings.
  </Step>
  <Step title="Enter TokenLab Settings">
    Use these values:

    | Field | Value |
    |-------|-------|
    | API Key | `sk-your-tokenlab-key` |
    | Model type | LLM |
    | Completion mode | Chat |
    | API Type | Chat Completions API |
    | API Base URL | `https://api.tokenlab.sh/v1` |
  </Step>
  <Step title="Add Models">
    Add the models you want to use, for example:
    - `gpt-5.4`
    - `gpt-5.4-mini`
    - `claude-sonnet-5`
    - `claude-opus-4-8`
    - `gemini-3.5-flash`
    - `gemini-3.1-flash-lite`
    - `deepseek-v4-flash`
  </Step>
</Steps>

### Step 3: Test Connection

1. Select a model you added, such as `gpt-5.4-mini`.
2. Send a test prompt
3. Confirm Dify receives a valid response

## Embeddings for Knowledge Bases

For RAG and knowledge base indexing, add an embedding model such as:
- `text-embedding-3-small`
- `text-embedding-3-large`

Then set it as the default embedding model in the relevant knowledge base or application settings.

## Choose models

Copy current chat and embedding model IDs from the [Models page](https://tokenlab.sh/en/models). Dify must configure chat and embeddings separately, and each model must support the API used by that Dify component.

## Best Practices

<AccordionGroup>
  <Accordion title="OpenAI plugin alternative">
    The separate **OpenAI** plugin can be used for models supported by its catalog. Set its custom base URL to `https://api.tokenlab.sh/v1` and **API Protocol** to **Chat Completions**; its default may be Responses. It is not an older name for OpenAI-API-compatible, and it does not accept every custom model ID.
  </Accordion>

  <Accordion title="Compare models with your own Dify app">
    Test the same representative inputs and compare output quality and final cost in Usage before changing the model.
  </Accordion>

  <Accordion title="This setup uses Chat Completions">
    Keep **Completion mode = Chat** and **API Type = Chat Completions API** for this setup. Responses is a separate API option; this guide does not configure it or WebSocket connections.
  </Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Connection Error">
    - Verify the base URL is exactly `https://api.tokenlab.sh/v1`
    - Remove trailing slashes if Dify duplicates them
    - Confirm the Dify server can reach TokenLab over the public internet
  </Accordion>

  <Accordion title="401 Unauthorized">
    - Double-check the API key
    - Confirm the key is active in TokenLab dashboard
    - Make sure the value pasted into Dify does not contain extra spaces or line breaks
  </Accordion>

  <Accordion title="Model Not Found">
    - Verify the model name exactly
    - Re-add the model entry if the provider UI cached an older value
    - Check current model availability in TokenLab docs or dashboard
  </Accordion>
</AccordionGroup>
