## Overview


[GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/use-byok-models) can connect to any OpenAI Chat Completions-compatible endpoint. TokenLab works through Copilot CLI's BYOK environment variables.

## Install

With Node.js 22 or later, install through npm:

```bash
npm install -g @github/copilot@1.0.85
```

On macOS or Linux, you can alternatively use Homebrew:

```bash
brew install --cask copilot-cli
```

Verify the installation:

```bash
copilot --version
```



## Configure TokenLab

Set the provider variables before starting Copilot CLI:

Use the [Quickstart](/quickstart) terminal instructions for macOS, Linux, WSL, or Windows PowerShell to set `TOKENLAB_API_KEY` without putting the key in command history. Launch Copilot CLI from that terminal. For persistent use, use your local secret manager; do not append a plaintext key to your shell profile.

These variables apply only to this launch; your saved account, default model and permission settings stay in place. Launch normally without the variables to use your previous setup. Do not persist them in your shell profile.

<CodeGroup>
```bash macOS / Linux / WSL
COPILOT_PROVIDER_TYPE=openai COPILOT_PROVIDER_BASE_URL=https://api.tokenlab.sh/v1 COPILOT_PROVIDER_API_KEY="${TOKENLAB_API_KEY:?Set TOKENLAB_API_KEY first}" copilot --model kimi-k3
```

```powershell Windows PowerShell
if (-not $env:TOKENLAB_API_KEY) { throw 'Set TOKENLAB_API_KEY first' }
$previous = @{}
$previous['COPILOT_PROVIDER_TYPE'] = [Environment]::GetEnvironmentVariable('COPILOT_PROVIDER_TYPE', 'Process')
$previous['COPILOT_PROVIDER_BASE_URL'] = [Environment]::GetEnvironmentVariable('COPILOT_PROVIDER_BASE_URL', 'Process')
$previous['COPILOT_PROVIDER_API_KEY'] = [Environment]::GetEnvironmentVariable('COPILOT_PROVIDER_API_KEY', 'Process')
try {
  $env:COPILOT_PROVIDER_TYPE = 'openai'
  $env:COPILOT_PROVIDER_BASE_URL = 'https://api.tokenlab.sh/v1'
  $env:COPILOT_PROVIDER_API_KEY = $env:TOKENLAB_API_KEY
  copilot --model kimi-k3
} finally {
  foreach ($name in $previous.Keys) {
    [Environment]::SetEnvironmentVariable($name, $previous[$name], 'Process')
  }
}
```
</CodeGroup>

| Variable | TokenLab value |
|---|---|
| `COPILOT_PROVIDER_TYPE` | `openai` |
| `COPILOT_PROVIDER_BASE_URL` | `https://api.tokenlab.sh/v1` |
| `COPILOT_PROVIDER_API_KEY` | Your TokenLab API key |
| `COPILOT_MODEL` | A live model ID, for example `kimi-k3` |

GitHub requires the selected model to support both streaming and tool calling. `kimi-k3` exposes tool use and a context window larger than GitHub's recommended 128K minimum.

## Verify

Inside Copilot CLI, ask for a read-only action first, such as:

```text
Inspect this repository and summarize its top-level structure. Do not modify files.
```

You can also inspect provider help or switch the model for the current session:

```bash
copilot help providers
```

## Troubleshooting

<AccordionGroup>
  <Accordion title="Authentication failed">
    Confirm `COPILOT_PROVIDER_API_KEY` contains an active TokenLab key and restart `copilot` after changing environment variables.
  </Accordion>
  <Accordion title="Model not found">
    Use the exact ID from the [live TokenLab model catalog](https://tokenlab.sh/en/models). Do not add a provider prefix to `kimi-k3`.
  </Accordion>
  <Accordion title="Tool calling or streaming error">
    Copilot CLI rejects models without both capabilities. Choose a tool-capable chat model such as `kimi-k3`.
  </Accordion>
</AccordionGroup>

<Warning>
Do not commit API keys to shell scripts or dotfiles tracked by Git. Rotate any key that was exposed in terminal history, screenshots, or logs.
</Warning>

Saving settings or listing models does not verify a key or a completed request. A prompt uses TokenLab balance. Check the reply and its matching [request record](https://tokenlab.sh/dashboard/runs?section=requests) before trying tools; auxiliary requests may also be billed.
