## Bağlantı yöntemini seçin

TokenLab’i ana model yapmak için Harness Web UI’da **custom provider** ekleyin. İsteğe bağlı TokenLab bundle zorunlu değildir. [MCP](/tr/integrations/tokenlab-mcp-server) araç, [Skill](/tr/integrations/coding-agent-skill) ise API talimatları sağlar; ikisi de ana modeli kendiliğinden değiştirmez.

Harness geliştirici önizlemesidir. Bu adımlar 16 Eylül 2026’da resmî belgeler ve yayımlanmış `@deepseek-ai/dsh` `0.1.5-rc.1` paketiyle karşılaştırıldı. Eski bundle’ın tüm `0.1.x` sürümleriyle uyumlu olduğu anlamına gelmez.

## Mevcut ajanınıza verilecek görev

```text
https://docs.tokenlab.sh/tr/integrations/deepseek-harness adresini oku, kurulu sürümümü ve işletim sistemimi kontrol et.
TokenLab ana modeli, MCP araçları veya API Skill seçeneklerinden hangisine ihtiyacım olduğunu doğrula.
Mevcut hesapları, sağlayıcı ayarlarını ve izinleri koru; değişikliklerin nasıl geri alınacağını açıkla.
Sohbette API anahtarı isteme. Anahtarı yerel olarak girip gerekli arayüz adımlarını ben uygulayacağım.
Küçük bir doğrulama isteğinin maliyetini açıkla. Yalnızca bu testi açıkça seçtikten sonra çalıştırmaya ve TokenLab kaydıyla eşleştirmeye yardım et.
```

## Harness’ı başlatın

macOS, Linux veya Windows üzerinde desteklenen Node kullanın; başlangıç için Node 24 LTS uygundur. Proje dizininde terminal veya PowerShell ile çalıştırın:

```bash
node --version
npx @deepseek-ai/dsh@0.1.5-rc.1 web
```

Yazdırılan yerel URL’yi açın ve **Choose workspace** ile projeyi ekleyip seçin. Bu komutlar `web` profile kullanır; Electron’un `desktop` profile’ı bu CLI akışıyla yönetilmez. Resmî [başlangıç](https://github.com/deepseek-ai/deepseek-harness) ve [Web UI](https://deepseek-harness.github.io/deepseek-harness/en/guide/quickstart) kılavuzlarına bakın.

## Bir TokenLab provider yapılandırın

1. **Settings → Models → Add a custom provider** açın; mevcut sağlayıcıları ve izinleri koruyun.
2. `tokenlab-chat` gibi küçük harfli bir Provider ID girip tablodan bir protokol ve Base URL çifti seçin.
3. TokenLab anahtarını yerel forma kaydedin. UI anahtarı `$DSH_HOME/.credentials.yaml` içinde, ayarlarda yalnızca başvurusu tutulur. Sohbete veya git’e koymayın.
4. [Güncel katalogdan](https://tokenlab.sh/tr/models) tam kimliği ekleyin ve [model ayrıntısındaki](/tr/api-reference/models/get-model) `tokenlab.accepted_request_formats` alanını kontrol edin.
5. Sağlayıcıyı kaydedip modeli seçin ve **yeni oturum** açın. Daha önce istek göndermiş oturumlar kayıtlı modelini korur.

| Provider ID örneği | Harness API protocol | Base URL | Gerekli genel istek biçimi |
| --- | --- | --- | --- |
| `tokenlab-chat` | `openai-completions` | `https://api.tokenlab.sh/v1` | `openai_chat_completions` |
| `tokenlab-responses` | `openai-responses` | `https://api.tokenlab.sh/v1` | `openai_responses` |
| `tokenlab-messages` | `anthropic-messages` | `https://api.tokenlab.sh` | `anthropic_messages` |

İlk metin testi için hâlâ sunulan `gpt-4.1-mini` Chat satırıyla kullanılabilir. **Fetch available models → Add selected** keşfe yardımcı olur; sonrasında kaydetmek gerekir. Başarısızsa kimliği elle girin. Listeleme protokol uyumluluğunu kanıtlamaz. Burada Gemini native protokolü yoktur; yalnızca model ayrıntılarında destekleniyorsa Chat kullanın. Görsel girişi ve akıl yürütme için ek `settings.yaml` alanları gerekebilir; [resmî provider belgesini](https://deepseek-harness.github.io/deepseek-harness/en/guide/providers) ve model ayrıntılarını izleyin.

## Küçük bir isteği doğrulayın

Yeni oturumda şunu gönderin:

```text
Yalnızca TOKENLAB_CONNECTION_OK yanıtını ver. Araç kullanma ve dosya değiştirme.
```

Bu istek ücretlidir. Yanıt ile [TokenLab kayıtlarındaki](https://tokenlab.sh/dashboard/runs?section=requests) model, zaman ve durumu karşılaştırın. İlk bağlantı için üç protokolü veya ücretli medya üretimini sınamak gerekmez. Model listesi ya da MCP keşfi, üretim yetkisini tek başına doğrulamaz.

## İsteğe bağlı: yayımlanmış TokenLab bundle

[`@tokenlabai/dsh-provider@0.1.1`](https://www.npmjs.com/package/@tokenlabai/dsh-provider/v/0.1.1) yayımlanmıştır ve Harness `0.1.1-rc.2` sürümünü hedefler; yeni sürüm uyumluluğu ayrıca kontrol edilmelidir. Yeni kurulumda yukarıdaki yerleşik custom provider yolunu kullanın. Bundle, **2026-08-26 tarihli sabit model anlık görüntüsü**, üç model yolu, `@tokenlabai/mcp-server@0.6.17` paketinin 80 `full` aracı ve `tokenlab_wait_task` içerir. Katalog otomatik güncellenmez; güncel kataloğu kontrol edip yeni kimlikleri custom provider ile ekleyin.

Uyumlu mevcut kurulumda önce `pnpm` komutunun PATH içinde olduğunu doğrulayın. Kurulum ve başlatmada aynı `dsh` sürümünü ve profile’ı kullanın. `npx` kullanıyorsanız aşağıdaki `dsh` yerine aynı sürümlü başlatma komutunu yazın:

```bash
dsh --version
pnpm --version
dsh plugin --profile web add --workspace-root @tokenlabai/dsh-provider@0.1.1
```

Profile’ı başlatmadan önce anahtarı başlatma ortamında veya okunan `.env` dosyasında ayarlayın:

```dotenv
TOKENLAB_API_KEY=sk-your-tokenlab-key
```

Harness, başlatma dizini ve `$DSH_HOME` (genellikle `~/.dsh`) altındaki `.env` dosyalarını okur; devralınan ortam değişkeni önceliklidir. Sonradan workspace seçmek `.env` dosyasını değiştirmez. Dosyayı commit etmeyin; değişiklikten sonra aynı profile’ı yeniden başlatın. UI’da kaydedilen model anahtarı bundle’ın `TOKENLAB_API_KEY` değişkeni olmaz. `headless` için hem kurulumda hem başlatmada `web` yerine o profile’ı kullanın. Mevcut `llm-pi-ai` ayarları bundle varsayılanlarından önceliklidir; `$DSH_HOME/settings.yaml` içindeki sağlayıcıları koruyup birleştirin, tüm Cordis patch ile değiştirmeyin.

Bundle ortam değişkenleri aşağıdadır; `catalog` yalnızca keşif, `core` daha küçük araç kümesi içindir:

| Değişken | Varsayılan | Amaç |
| --- | --- | --- |
| `TOKENLAB_API_KEY` | yok | Model, MCP ve asenkron polling kimlik doğrulaması |
| `TOKENLAB_API_BASE` | `https://api.tokenlab.sh` | MCP ve task API root |
| `TOKENLAB_OPENAI_BASE_URL` | `https://api.tokenlab.sh/v1` | Responses ve Chat base URL |
| `TOKENLAB_ANTHROPIC_BASE_URL` | `https://api.tokenlab.sh` | Messages base URL |
| `TOKENLAB_MCP_TOOL_PROFILE` | `full` | `catalog`, `core` veya `full` |
| `TOKENLAB_MCP_SCHEMA_MODE` | `portable` | `portable`, `exact` veya `strict` |

`delivery.mode` değeri `complete` ise sonucu doğrudan kullanın. `async` ise `delivery.task_id` değerini `tokenlab_wait_task` aracına verip son `status`, `response` ve `result_urls` alanlarını okuyun. Bekleme süresinin dolması tamamlanma değildir. Ücretli veya yıkıcı araçların onaylarını koruyun; [asenkron görevler](/tr/guides/async-jobs-polling) kılavuzuna bakın.

Aynı başlatıcı ve profile ile kaldırın, ardından yeniden başlatın:

```bash
dsh plugin --profile web remove --workspace-root @tokenlabai/dsh-provider
```

## Hata durumunda

- **Yazma alanı kapalı:** workspace ve model seçin.
- **`MISSING_CREDENTIAL` veya 401:** sağlayıcı kimlik bilgilerini kontrol edin; bundle araçları başlatma ortamındaki `TOKENLAB_API_KEY` değişkenini ayrı okur.
- **`UNKNOWN_MODEL` veya emekli kimlik:** güncel kataloğu kontrol edin, tam kimliği yapılandırıp yeni oturum açın. `0.1.1` yeniden kurulunca anlık görüntü güncellenmez.
- **Üretim başarısız:** protokol, Base URL ve kabul edilen biçimleri karşılaştırın. Yalnızca başarı elde etmek için geçmişi, araçları veya görselleri silmeyin.
- **`dsh` veya `pnpm` yok:** yukarıdaki sürümlü `npx` komutunu kullanın; plugin komutlarından önce [pnpm kurun](https://pnpm.io/installation).

## MCP ve Skills ayrı seçeneklerdir

Elle provider eklemek araç kurmaz. Bundle gerekmiyorsa [TokenLab MCP kılavuzunu](/tr/integrations/tokenlab-mcp-server) izleyin ve üretimden önce keşfi kontrol edin. [Skill](/tr/integrations/coding-agent-skill) klasörünü `SKILL.md` ve başvuru dosyalarıyla birlikte proje kökündeki `.dsh/skills/tokenlab-api-integration/` altına koyun. Harness, `.agents/skills/` dizinini de okur. Skill; provider, MCP sunucusu veya anahtar kurmaz. [Resmî Skills belgesine](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/skill/skill-filesystem/README.md) bakın.
