## Genel Bakış



<Note>
**Tür**: Kodlama Aracı

**Birincil Yol**: OpenAI Responses (gelişmiş isteğe bağlı yol)

**Destek Güveni**: Model/yol sınırlamalarıyla destekleniyor
</Note>

OpenAI Codex, terminalde kod okuyabilen, değiştirebilen ve çalıştırabilen hafif bir kodlama ajanı olarak hizmet veren açık kaynaklı bir komut satırı aracıdır (CLI). GPT modelleri üzerine inşa edilmiştir ve kod üretimi için optimize edilmiştir.

TokenLab için, Codex CLI `/v1/responses` kullanabilir, ancak bunu gelişmiş bir uyumluluk yolu olarak ele almalısınız. Sadece Responses özelliklerinin her model ve yönlendirilen yol boyunca garantili olmadığı durumlar vardır.

Codex CLI uzaktan sıkıştırma `POST /v1/responses/compact` üzerinde desteklenir. Codex, `/compact` ve otomatik sıkıştırma için geçerli oturumun `model` değerini `body.model` içinde gönderir, bu nedenle sıkıştırmada kullanmak istediğiniz model Responses yolunda kullanılabilir olmalıdır. `/v1/compact` yapılandırmayın.

## Sistem Gereksinimleri

macOS, Linux veya Windows için [resmî CLI kılavuzunu](https://learn.chatgpt.com/docs/codex/cli) izleyin. Yerel Windows ve WSL ayrı ortamlardır; [Windows kılavuzuna](https://learn.chatgpt.com/docs/windows/windows-sandbox) bakın. npm bir kurulum seçeneğidir, yerel ikili dosyalar için zorunlu değildir.

## Kurulum

```bash
npm install -g @openai/codex
```

Kurulumu doğrulayın:

```bash
codex --version
```

## Yapılandırma

### Adım 1: API Anahtarını Ayarlayın

**Geçici (mevcut oturum):**

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

**Kalıcı yapılandırma:**

Şunlara ekleyin: `~/.bashrc`, `~/.zshrc` veya `~/.bash_profile`:

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

Sonra yeniden yükleyin:

```bash
source ~/.zshrc  # or source ~/.bashrc
```

### Adım 2: config.toml'u Yapılandırma

Bu ayarları kullanıcı düzeyindeki `~/.codex/config.toml` dosyanızla birleştirin; dosyanın tamamını değiştirmeyin. Diğer sağlayıcıları, hesapları, sandbox ayarlarını ve onay kurallarını koruyun. Sağlayıcı ve kimlik doğrulama ayarları projenin `.codex/config.toml` dosyasında değil, kullanıcı yapılandırmasında olmalıdır. [Resmî yapılandırma kılavuzuna](https://learn.chatgpt.com/docs/config-file/config-advanced#custom-model-providers) bakın.

Varsayılan sağlayıcıyı korumak için Codex 0.134.0 ve sonrasında örneği `~/.codex/tokenlab.config.toml` olarak kaydedip `codex --profile tokenlab` çalıştırın. Özelleştirilmişse gerçek `CODEX_HOME` dizinini kullanın. Eski `[profiles.tokenlab]` tablosu oluşturmayın, `auth.json` üzerine yazmayın, oturumu kapatmayın veya izinleri değiştirmeyin. Geri almak için bu profil olmadan başlatın.

Aşağıdaki her komut grubunda `tokenlab.config.toml` için **TokenLab profili** seçeneğini kullanın. **Varsayılan TokenLab** seçeneğini yalnızca ayarları `config.toml` ile birleştirdikten sonra kullanın. Tek başına `codex`, varsayılan yapılandırmayı kullanır; önceki oturumda seçilen profili hatırlamaz.

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"

[model_providers.tokenlab]
env_key = "TOKENLAB_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000
```

Bu WebSocket modu, Codex istemcileri için bir Responses-over-WebSocket köprüsüdür. Yalnızca resmi `response.create` olaylarını kabul eder; `stream` örtüktür ve bu transport üzerinde `background` ile `response.cancel` kullanılamaz. OpenAI Realtime API değildir ve `session.update`, `conversation.item.*`, `input_audio_buffer.*`, ikili ses veya iç içe Realtime `response.create.response` zarflarını kabul etmez.

<Note>
Seçtiğiniz yapılandırma dosyası yoksa oluşturun. Düzenledikten sonra aşağıdaki ilgili komutla yeni bir oturum başlatın.
</Note>

Güncel Codex `chat/completions` yerine `wire_api = "responses"` kullanır. Sağlayıcının `env_key` kullanması için `requires_openai_auth` ayarını yazmayın veya false yapın.

<Note>
TokenLab bilinmeyen Responses alanlarını best-effort iletir ve isteği sessizce Chat Completions’a düşürmez. Alanın veya kombinasyonun desteklenip desteklenmediğine seçilen upstream karar verir.
</Note>

| Komut | Açıklama |
|---------|-------------|
| `/help` | Yardımı görüntüle |

| `/status` | Etkin modeli, izinleri ve token kullanımını göster |
| `/model <name>` | Modeli değiştir |

## Yapılandırmayı Doğrulayın

Değerini yazdırmadan yalnızca ortam değişkeninin ayarlanıp ayarlanmadığını kontrol edin. Bu kontrol anahtarın geçerliliğini doğrulamaz:

```bash
if [ -n "${TOKENLAB_API_KEY:-}" ]; then
  printf '%s\n' 'TOKENLAB_API_KEY is set'
else
  printf '%s\n' 'TOKENLAB_API_KEY is not set'
fi
```

Codex’i başlatıp etkin modeli ve izinleri kontrol etmek için `/status` çalıştırın. Bir profil kullanıyorsanız aynı profili başlatın. [Resmî durum komutuna](https://learn.chatgpt.com/docs/developer-commands?surface=cli#inspect-the-session-with-status) bakın.

Gerçek bir istek göndermeye hazır olduğunuzda aşağıdaki komutu çalıştırın. Bu işlem TokenLab bakiyenizi kullanır. Yanıtı ve [İstekler](https://tokenlab.sh/dashboard/runs?section=requests) sayfasındaki ilgili kaydı kontrol edin. Değişkenin ayarlanmış olması veya uygulamanın başlaması, isteğin başarılı olduğunu tek başına kanıtlamaz.

<CodeGroup>
```bash TokenLab profili
codex --profile tokenlab "Reply only with OK. Do not use tools or modify files."
```

```bash Varsayılan TokenLab
codex "Reply only with OK. Do not use tools or modify files."
```
</CodeGroup>

## Sorun Giderme

<AccordionGroup>
  <Accordion title="Bağlantı Hatası">
    - `config.toml` içindeki `base_url`'un tam olarak `https://api.tokenlab.sh/v1` olduğundan emin olun
    - Ağ bağlantısını kontrol edin
    - Proxy müdahalesi olmadığından emin olun
  </Accordion>

  <Accordion title="Kimlik Doğrulama Başarısız">
    Codex 0.149.0 veya daha yeni bir sürüme yükselttikten sonra, özel bir sağlayıcı `requires_openai_auth` tanımlanmamış veya `false` iken yalnızca `auth.json` kullanıyorsa `API_KEY_REQUIRED` veya `401 Unauthorized` hataları oluşabilir. Bu kılavuz anahtarı `env_key` aracılığıyla `TOKENLAB_API_KEY` değişkeninden okur ve `auth.json` dosyasına dayanmaz. `requires_openai_auth` ayarını tanımlamadan bırakın veya `false` olarak ayarlayın; bu yapılandırmada değeri `true` olarak değiştirmeniz ya da `auth.json` dosyasının üzerine yazmanız gerekmez.

    - Gerçekte kullanılan yapılandırmanın veya profilin `env_key = "TOKENLAB_API_KEY"` içerdiğini doğrulayın. Ayarları `tokenlab.config.toml` dosyasına kaydettiyseniz Codex’i `codex --profile tokenlab` ile başlatın
    - `TOKENLAB_API_KEY` değişkeninin Codex’i başlattığınız terminalde tanımlı olduğundan emin olun. Değişkeni ayarladıktan sonra Codex’i aynı terminalden yeniden başlatın
    - Anahtarın `sk-` ile başladığını kontrol edin
    - Anahtarın TokenLab kontrol panelinde aktif olduğundan emin olun
  </Accordion>

  <Accordion title="Model Bulunamadı">
    - Model adının tam olarak eşleştiğini kontrol edin
    - Model kullanılabilirliğini şu adreste doğrulayın: [tokenlab.sh/en/models](https://tokenlab.sh/tr/models)
  </Accordion>

  <Accordion title="Responses-yerel alan reddedildi">
    - Bazı alanlar yalnızca TokenLab seçili model ve yol için bu davranışı garanti edebildiğinde `/v1/responses` üzerinde kullanılabilir
    - Eğer `unsupported_request_field` görürseniz, o alanı kaldırın veya buna bağlı olmayan bir iş akışına geçin
  </Accordion>

  <Accordion title="/compact veya otomatik sıkıştırma başarısız">
    - Codex CLI `/v1/compact` değil, `POST /v1/responses/compact` çağırır
    - Sıkıştırma isteği geçerli oturumun `model` değerini kullanır, bu yüzden bu model Responses yolunda kullanılabilir olmalıdır
    - `wire_api = "responses"` ve `base_url = "https://api.tokenlab.sh/v1"` ayarlarını koruyun
  </Accordion>
</AccordionGroup>
