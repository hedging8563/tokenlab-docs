## نظرة عامة

هذه الواجهات مخصصة للفرق التي تستخدم بالفعل شكل مهام Seedance بأسلوب Volc. يتم التوثيق باستخدام TokenLab Bearer API key. يبدأ معرف المهمة المرجع بـ `cgt-`؛ قم بالاستعلام عن الحالة حتى تصبح `status` إحدى `succeeded` أو `failed` أو `cancelled` أو `expired`.

<Warning>
لا تُعد استخدام تعداد أو بنية استجابة v1. يستخدم `/v1/tasks/{id}` الحالات `pending` و`processing` و`completed` و`failed`، بينما يستخدم هذا المسار تعداد v3 الموضح أعلاه. في v3 تكون `duration` سلسلة نصية عند وجودها، ولا يظهر `error` إلا عند الفشل.
</Warning>

انظر أيضا [نماذج فيديو Seedance 2.0](/ar/guides/seedance-2-video) و [توليد الفيديو](/ar/guides/video-generation).

## شكل الاستجابة

تستخدم استجابة المهمة `queued` أو `running` أو `succeeded` أو `failed` أو `cancelled` أو `expired`. تعيد المهام الناجحة `content.video_url`، وقد تعيد `content.last_frame_url` وحقول الجيل الرسمية و`usage`. لا يظهر `error` إلا عند الفشل، ولا تُضاف حقول TokenLab مثل `progress` أو `return_last_frame` أو `watermark` أو `priority` أو `camera_fixed`.

## مثال

```bash
curl https://api.tokenlab.sh/api/v3/contents/generations/tasks/cgt-20260102030405-a1b2c \
  -H "Authorization: Bearer $TOKENLAB_API_KEY"
```
