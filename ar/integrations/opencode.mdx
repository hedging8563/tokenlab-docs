## نظرة عامة



<Note>
**النوع**: أداة برمجة

**المسار الرئيسي**: متوافق مع OpenAI

**مستوى الدعم**: مسار مدعوم
</Note>

OpenCode هو مساعد برمجة AI مفتوح المصدر يعمل داخل الطرفية الخاصة بك. وهو يدعم عدة مزوّدي LLM ويمكن تهيئته لاستخدام API الخاصة بـ TokenLab للوصول إلى مئات النماذج.

## التثبيت

[OpenCode](https://opencode.ai/docs/)

```bash
npm install -g opencode-ai
```

تحقق من التثبيت:

```bash
opencode --version
```

## التهيئة

### الخطوة 1: تعيين متغيرات البيئة

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

للتهيئة الدائمة، أضف إلى `~/.bashrc` أو `~/.zshrc`:

```bash
echo 'export TOKENLAB_API_KEY="sk-your-tokenlab-key"' >> ~/.zshrc
source ~/.zshrc
```

### الخطوة 2: تهيئة OpenCode

توصي وثائق OpenCode الحالية بتهيئة المزوّدين من خلال `opencode.json` أو `opencode.jsonc`. بالنسبة إلى TokenLab، استخدم مزوّدًا مخصصًا بدلًا من تحميل المزوّد المدمج `openai` فوق طاقته:

يستخدم المثال تنسيق V1 المدعوم. ادمجه في `~/.config/opencode/opencode.json` مع إبقاء المزودات والأذونات. يقرأ V2 إعدادات V1 المدعومة، لكن لا تخلط التنسيقين داخل المزود. راجع [دليل الترحيل](https://opencode.ai/v2/docs/migrate-v1/). تحقق عبر `/models` ثم طابق اختبارًا مدفوعًا مع سجل TokenLab. للتراجع اختر النموذج السابق واحذف هذا العنصر فقط.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "tokenlab": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "TokenLab",
      "options": {
        "baseURL": "https://api.tokenlab.sh/v1",
        "apiKey": "{env:TOKENLAB_API_KEY}"
      },
      "models": {
        "gpt-5.6-terra": {
          "name": "GPT-5.6 Terra"
        },
        "gpt-5.6-luna": {
          "name": "GPT-5.6 Luna"
        }
      }
    }
  },
  "model": "tokenlab/gpt-5.6-terra"
}
```

<Note>
استخدم `@ai-sdk/openai-compatible` للتوافق بأسلوب chat-completions. إذا كنت تحتاج تحديدًا إلى مسار مزوّد مبني على `/v1/responses`، فإن وثائق OpenCode توصي بتبديل الحزمة إلى `@ai-sdk/openai`.
</Note>

## الاستخدام الأساسي

**ابدأ الوضع التفاعلي:**

```bash
opencode
```

**شغّل مع prompt:**

```bash
opencode run "Explain this codebase"
```

**حدد النموذج:**

```bash
opencode run --model tokenlab/gpt-5.6-terra "Fix the bugs in main.py"
```

## النماذج المتاحة

| النموذج | الأفضل لـ |
|-------|----------|
| `gpt-5.6-terra` | المهام المعقدة، بنية الكود |
| `gpt-5.6-luna` | الإصلاحات السريعة، الاستعلامات البسيطة |
| `claude-sonnet-4-6` | مراجعة الكود، التوثيق |
| `claude-opus-4-6` | الاستدلال المعقد |
| `gemini-3.5-flash` | الاستجابات السريعة |

## الأوامر الشائعة

**تحليل الكود:**

```bash
opencode run "What does this function do?" < src/utils.ts
```

**توليد الكود:**

```bash
opencode run "Create a REST API with Express"
```

**مراجعة التغييرات:**

```bash
git diff | opencode run "Review these changes"
```

**إصلاح الأخطاء:**

```bash
opencode run "Fix the TypeScript errors in this project"
```

## الأوامر التفاعلية

| الأمر | الوصف |
|---------|-------------|
| `/help` | عرض الأوامر المتاحة |
| `/models` | التبديل إلى نموذج مختلف |
| `/clear` | مسح سجل المحادثة |
| `/exit` | الخروج من OpenCode |

## استكشاف الأخطاء وإصلاحها

<AccordionGroup>
  <Accordion title="خطأ في الاتصال">
    - تحقق من أن `options.baseURL` مضبوط على `https://api.tokenlab.sh/v1`
    - تحقق من اتصال الشبكة
    - جرّب `curl https://api.tokenlab.sh/v1/models` للاختبار
  </Accordion>

  <Accordion title="فشلت المصادقة">
    - تحقق من تعيين متغير البيئة `TOKENLAB_API_KEY`
    - تحقق من أن `options.apiKey` يشير إلى `{env:TOKENLAB_API_KEY}` أو إلى مصدر secret صالح آخر
    - تحقق من أن المفتاح يبدأ بـ `sk-`
    - تأكد من أن المفتاح نشط في لوحة تحكم TokenLab
  </Accordion>

  <Accordion title="النموذج غير موجود">
    - تحقق من أن اسم النموذج في ملف التهيئة مطابق تمامًا
    - تحقق من توفر النموذج على [tokenlab.sh/en/models](https://tokenlab.sh/ar/models)
  </Accordion>
</AccordionGroup>
