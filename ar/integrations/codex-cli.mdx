## نظرة عامة



<Note>
**النوع**: أداة برمجة

**المسار الأساسي**: OpenAI Responses (مسار اختياري متقدم)

**ثقة الدعم**: مدعوم مع قيود على النموذج/المسار
</Note>

OpenAI Codex هو أداة مفتوحة المصدر لسطر الأوامر (CLI) تعمل كوكيل برمجي خفيف الوزن، قادر على قراءة الكود وتعديله وتشغيله في الطرفية. تم بناؤه على نماذج GPT ومحسّن لتوليد الشيفرة.

بالنسبة لـ TokenLab، يمكن لـ Codex CLI استخدام `/v1/responses`، لكن يجب اعتباره مسار توافق متقدم. بعض ميزات Responses-only غير مضمونة عبر كل نموذج ومسار موجه.

يدعم Codex CLI الضغط البعيد عبر `POST /v1/responses/compact`. يرسل Codex قيمة `model` الخاصة بالجلسة الحالية في `body.model` عند استخدام `/compact` والضغط التلقائي، لذلك يجب أن يكون النموذج الذي تريد استخدامه للضغط متاحا على مسار Responses. لا تقم بضبط `/v1/compact`.

## متطلبات النظام

اتبع [دليل CLI الرسمي](https://learn.chatgpt.com/docs/codex/cli) لنظام macOS أو Linux أو Windows. Windows الأصلي وWSL بيئتان منفصلتان؛ راجع [دليل Windows](https://learn.chatgpt.com/docs/windows/windows-sandbox). npm خيار تثبيت وليس شرطًا للملفات التنفيذية الأصلية.

## التثبيت

```bash
npm install -g @openai/codex
```

التحقق من التثبيت:

```bash
codex --version
```

## التكوين

### الخطوة 1: تعيين مفتاح API

**مؤقت (الجلسة الحالية):**

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

**تكوين دائم:**

أضف إلى `~/.bashrc`، `~/.zshrc`، أو `~/.bash_profile`:

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

ثم أعد التحميل:

```bash
source ~/.zshrc  # or source ~/.bashrc
```

### الخطوة 2: تكوين config.toml

ادمج هذه الإعدادات في ملف المستخدم `~/.codex/config.toml` دون استبدال الملف بالكامل. احتفظ بموفري الخدمة والحسابات وإعدادات العزل وقواعد الموافقة الأخرى. يجب وضع إعدادات موفر الخدمة والمصادقة في إعدادات المستخدم، وليس في ملف `.codex/config.toml` الخاص بالمشروع. راجع [دليل الإعداد الرسمي](https://learn.chatgpt.com/docs/config-file/config-advanced#custom-model-providers).

لإبقاء المزود الافتراضي، احفظ المثال في `~/.codex/tokenlab.config.toml` على Codex 0.134.0 أو أحدث وشغّل `codex --profile tokenlab`. استخدم المجلد الفعلي إن خصصت `CODEX_HOME`. لا تنشئ جدول `[profiles.tokenlab]` القديم ولا تستبدل `auth.json` أو تسجل الخروج أو تغيّر الأذونات. شغّل دون هذا الملف الشخصي للاستعادة.

في كل مجموعة أوامر أدناه، اختر **ملف تعريف TokenLab** عند استخدام `tokenlab.config.toml`. استخدم **TokenLab افتراضي** فقط بعد دمج الإعدادات في `config.toml`. يستخدم الأمر `codex` وحده الإعداد الافتراضي ولا يتذكر ملف التعريف المحدد في جلسة سابقة.

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"

[model_providers.tokenlab]
env_key = "TOKENLAB_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000
```

وضع WebSocket هذا هو جسر Responses-over-WebSocket لعملاء Codex. يقبل أحداث `response.create` الرسمية فقط؛ يكون `stream` ضمنيًا، ولا تتوفر `background` أو `response.cancel` على هذا النقل. وهو ليس OpenAI Realtime API ولا يقبل `session.update` أو `conversation.item.*` أو `input_audio_buffer.*` أو الصوت الثنائي أو أغلفة Realtime المتداخلة `response.create.response`.

<Note>
أنشئ ملف الإعداد المختار إذا لم يكن موجودًا. بعد تعديله، ابدأ جلسة جديدة باستخدام الأمر المطابق أدناه.
</Note>

يستخدم Codex الحالي `wire_api = "responses"` وليس `chat/completions`. احذف إعداد `requires_openai_auth` أو اجعله false كي يستخدم هذا المزود `env_key`.

<Note>
تمرر TokenLab حقول Responses غير المعروفة بأفضل جهد من دون تخفيض الطلب بصمت إلى Chat Completions. يقرر upstream المحدد ما إذا كان الحقل أو التركيب مدعومًا.
</Note>

## النماذج الموصى بها

| النموذج | الأفضل لـ |
|-------|----------|
| `gpt-5.6-sol` | أفضل خيار افتراضي للترميز والتفكير المنطقي |
| `gpt-5-mini` | بديل أسرع وأرخص لسير عمل الترميز |
| `claude-sonnet-4-6` | مراجعة الشيفرة، التوثيق |

## الأوامر التفاعلية

| الأمر | الوصف |
|---------|-------------|
| `/help` | عرض المساعدة |
| `/exit` or `Ctrl+C` | الخروج |
| `/clear` | مسح المحادثة |
| `/status` | عرض النموذج النشط والصلاحيات واستخدام الرموز |
| `/model <name>` | تبديل النموذج |

## التحقق من التكوين

تحقق فقط من تعيين متغير البيئة دون طباعة قيمته. هذا الفحص لا يتحقق من صلاحية المفتاح:

```bash
if [ -n "${TOKENLAB_API_KEY:-}" ]; then
  printf '%s\n' 'TOKENLAB_API_KEY is set'
else
  printf '%s\n' 'TOKENLAB_API_KEY is not set'
fi
```

شغّل Codex ونفّذ `/status` للتحقق من النموذج النشط والصلاحيات. إذا كنت تستخدم ملف تعريف، فشغّل ملف التعريف نفسه. راجع [أمر الحالة الرسمي](https://learn.chatgpt.com/docs/developer-commands?surface=cli#inspect-the-session-with-status).

عندما تكون مستعدًا لإرسال طلب حقيقي، نفّذ الأمر التالي. سيستخدم رصيدك في TokenLab. تحقق من الرد والسجل المطابق في [الطلبات](https://tokenlab.sh/dashboard/runs?section=requests). تعيين المتغير أو نجاح بدء التشغيل وحده لا يثبت نجاح الطلب.

<CodeGroup>
```bash ملف تعريف TokenLab
codex --profile tokenlab "Reply only with OK. Do not use tools or modify files."
```

```bash TokenLab افتراضي
codex "Reply only with OK. Do not use tools or modify files."
```
</CodeGroup>

## استكشاف الأخطاء وإصلاحها

<AccordionGroup>
  <Accordion title="خطأ في الاتصال">
    - تحقق أن `base_url` في config.toml هو بالضبط `https://api.tokenlab.sh/v1`
    - تحقق من اتصال الشبكة
    - تأكد من عدم وجود تداخل بروكسي
  </Accordion>

  <Accordion title="فشل المصادقة">
    بعد الترقية إلى Codex 0.149.0 أو أحدث، قد يظهر الخطأ `API_KEY_REQUIRED` أو `401 Unauthorized` إذا كان المزوّد المخصص يعتمد فقط على `auth.json` وكان `requires_openai_auth` غير معيّن أو مضبوطًا على `false`. يقرأ هذا الدليل المفتاح من `TOKENLAB_API_KEY` عبر `env_key` ولا يعتمد على `auth.json`. اترك `requires_openai_auth` دون تعيين أو اضبطه على `false`؛ لا يتطلب هذا الإعداد تغييره إلى `true` أو الكتابة فوق `auth.json`.

    - تحقق من أن الإعدادات أو ملف التعريف المستخدم فعليًا يتضمن `env_key = "TOKENLAB_API_KEY"`؛ إذا حفظت الإعدادات في `tokenlab.config.toml`، فابدأ باستخدام `codex --profile tokenlab`
    - تحقق من تعيين متغير البيئة `TOKENLAB_API_KEY` في الطرفية التي تستخدمها لتشغيل Codex، ثم أعد تشغيل Codex من تلك الطرفية بعد تعيينه
    - تأكد من أن المفتاح يبدأ بـ `sk-`
    - تأكد من أن المفتاح نشط في لوحة تحكم TokenLab
  </Accordion>

  <Accordion title="النموذج غير موجود">
    - تحقق أن اسم النموذج يطابق بالضبط
    - تحقق من توفر النموذج على [tokenlab.sh/en/models](https://tokenlab.sh/ar/models)
  </Accordion>

  <Accordion title="رفض حقل مخصص لـ Responses">
    - بعض الحقول متاحة فقط على `/v1/responses` عندما يمكن لـ TokenLab ضمان هذا السلوك للنموذج والمسار المحددين
    - إذا رأيت `unsupported_request_field`، احذف ذلك الحقل أو انتقل إلى سير عمل لا يعتمد عليه
  </Accordion>

  <Accordion title="فشل /compact أو الضغط التلقائي">
    - يستدعي Codex CLI `POST /v1/responses/compact`، وليس `/v1/compact`
    - يستخدم طلب الضغط `model` الخاص بالجلسة الحالية، لذلك يجب أن يكون هذا النموذج متاحا على مسار Responses
    - أبق `wire_api = "responses"` و `base_url = "https://api.tokenlab.sh/v1"`
  </Accordion>
</AccordionGroup>
