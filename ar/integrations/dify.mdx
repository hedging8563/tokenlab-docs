## نظرة عامة

استخدم إضافة مزود النماذج **OpenAI-API-compatible** لربط Dify بـ TokenLab. اضبط نوع النموذج على **LLM**، و**Completion mode** على **Chat**، و**API Type** على **Chat Completions API**. يستخدم هذا الدليل Chat Completions.

<Note>
**النوع**: إطار عمل أو منصة

**المسار الأساسي**: مسار المحادثة المتوافق مع OpenAI

**مستوى دعم الموثوقية**: مدعوم مع حدود للنطاق
</Note>

## المتطلبات الأساسية

- حساب TokenLab مع وصول إلى API
- Dify Cloud أو نسخة Dify مستضافة ذاتياً

## خطوات الإعداد

### الخطوة 1: الحصول على مفتاح API الخاص بك

1. سجل الدخول إلى [TokenLab Dashboard](https://tokenlab.sh/dashboard)
2. افتح [API Keys](https://tokenlab.sh/dashboard/api)
3. أنشئ أو انسخ مفتاح API يبدأ بـ `sk-`

### الخطوة 2: تكوين المزود

<Steps>
  <Step title="فتح مزودي النماذج">
    في Dify، انتقل إلى **Settings** ← **Model Providers**
  </Step>
  <Step title="اختيار OpenAI-API-compatible">
    افتح **OpenAI-API-compatible**. إذا لم تجده، فثبّت إضافة مزود النماذج هذه من Dify Marketplace. اختر **Add model** لإدخال إعدادات TokenLab.
  </Step>
  <Step title="إدخال إعدادات TokenLab">
    استخدم هذه القيم:

    | الحقل | القيمة |
    |-------|-------|
    | API Key | `sk-your-tokenlab-key` |
    | Model type | LLM |
    | Completion mode | Chat |
    | API Type | Chat Completions API |
    | API Base URL | `https://api.tokenlab.sh/v1` |
  </Step>
  <Step title="إضافة النماذج">
    أضف النماذج التي تريد استخدامها، على سبيل المثال:
    - `gpt-5.4`
    - `gpt-5.4-mini`
    - `claude-sonnet-5`
    - `claude-opus-4-8`
    - `gemini-3.5-flash`
    - `gemini-3.1-flash-lite`
    - `deepseek-v4-flash`
  </Step>
</Steps>

### الخطوة 3: اختبار الاتصال

1. اختر نموذجاً أضفته، مثل `gpt-5.4-mini`.
2. أرسل رسالة اختبار (prompt)
3. تأكد من أن Dify يتلقى استجابة صالحة

## التضمينات (Embeddings) لقواعد المعرفة

بالنسبة لـ RAG وفهرسة قواعد المعرفة، أضف نموذج تضمين مثل:
- `text-embedding-3-small`
- `text-embedding-3-large`

ثم قم بتعيينه كنموذج التضمين الافتراضي في قاعدة المعرفة ذات الصلة أو إعدادات التطبيق.

## أدوار النماذج الموصى بها

| حالة الاستخدام | النماذج المقترحة |
|----------|------------------|
| المحادثة الافتراضية | `gpt-5.4-mini`, `gpt-5.4`, `claude-sonnet-5` |
| الاستنتاج العميق | `gpt-5.5`, `gpt-5.4`, `claude-opus-4-8`, `deepseek-v4-pro` |
| سريع/رخيص | `gpt-5.4-mini`, `gemini-3.5-flash`, `deepseek-v4-flash` |
| التضمينات | `text-embedding-3-small`, `text-embedding-3-large` |

## أفضل الممارسات

<AccordionGroup>
  <Accordion title="إضافة OpenAI كخيار بديل">
    يمكن استخدام إضافة **OpenAI** المنفصلة للنماذج التي يدعمها كتالوجها. اضبط عنوانها الأساسي المخصص على `https://api.tokenlab.sh/v1` و**API Protocol** على **Chat Completions**؛ فقد يكون الخيار الافتراضي Responses. ليست اسماً قديماً لإضافة OpenAI-API-compatible، ولا تقبل جميع معرّفات النماذج المخصصة.
  </Accordion>

  <Accordion title="استخدم نماذج أرخص للتكرار">
    استخدم `gpt-5.4-mini` أو `gemini-3.5-flash` أو `deepseek-v4-flash` أثناء التكرار، ثم قم بتحويل سير العمل الثقيل إلى نماذج أقوى فقط عند الحاجة.
  </Accordion>

  <Accordion title="يستخدم هذا الإعداد Chat Completions">
    أبقِ **Completion mode = Chat** و**API Type = Chat Completions API** لهذا الإعداد. Responses خيار API مستقل؛ لا يضبط هذا الدليل ذلك الخيار أو اتصالات WebSocket.
  </Accordion>
</AccordionGroup>

## استكشاف الأخطاء وإصلاحها

<AccordionGroup>
  <Accordion title="خطأ في الاتصال">
    - تحقق من أن العنوان الأساسي هو بالضبط `https://api.tokenlab.sh/v1`
    - قم بإزالة الشرطات المائلة الزائدة إذا كان Dify يكررها
    - تأكد من أن خادم Dify يمكنه الوصول إلى TokenLab عبر الإنترنت العام
  </Accordion>

  <Accordion title="401 غير مصرح به">
    - تحقق جيداً من مفتاح API
    - تأكد من أن المفتاح نشط في لوحة تحكم TokenLab
    - تأكد من أن القيمة التي تم لصقها في Dify لا تحتوي على مسافات إضافية أو فواصل أسطر
  </Accordion>

  <Accordion title="النموذج غير موجود">
    - تحقق من اسم النموذج بدقة
    - أعد إضافة إدخال النموذج إذا قامت واجهة المزود بتخزين قيمة قديمة مؤقتاً
    - تحقق من توفر النموذج الحالي في وثائق TokenLab أو لوحة التحكم
  </Accordion>
</AccordionGroup>
