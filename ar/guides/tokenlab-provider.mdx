<Note>
هذا الدليل مخصّص لمستخدمي **OpenClaw المستضاف محليًا (self-hosted)** الذين يرغبون في ربط TokenLab كمزوِّد AI خاص بهم.
</Note>

## موصى به: تثبيت الإضافة

اختياريًا، ثبّت إضافة المزوّد المنشورة **0.1.0**. وفّر `TOKENLAB_API_KEY` في بيئة Gateway نفسها الموضحة أدناه واختر النموذج للجلسة فقط. يغيّر معالج الإعداد النموذج الافتراضي، لذا لا يشغّل هذا الدليل `openclaw onboard`. احتفظ بالإضافات والأذونات الحالية وتحقق من تحميل الإضافة وقائمة النماذج قبل أي طلب.

راجع الإمكانات التي يطلبها المثبّت واتبع رسائل التأكيد في العميل. لا تمنح أذونات غير مرتبطة ولا تغيّر أذونات الإضافات الموجودة.

```bash
openclaw plugins install @tokenlabai/openclaw-provider@0.1.0
openclaw plugins list
openclaw models list --provider tokenlab
```

```text
/model tokenlab/claude-sonnet-5 -s
/model default -s
```

## تكوين الموفر يدويًا

استخدم إدخالات `models.providers` اليدوية أدناه فقط عندما تحتاج صراحةً إلى مسارات منفصلة لـ **Responses API** أو **Claude native** أو **Gemini native** أو **MiniMax native**.

إذا اخترت التكوين اليدوي، فيكفي تكوين `tokenlab` بمفرده. أضف الموفرين الآخرين فقط عندما تحتاج صراحةً إلى سلوك **Responses API** أو **Claude native** أو **Gemini native** أو **MiniMax native**.

| المزوّد | OpenClaw `api` | الأفضل لـ | baseUrl |
|--------|----------------|-----------|---------|
| `tokenlab` | `openai-completions` | GPT وDeepSeek وQwen ومعظم الاستدعاءات المتوافقة مع OpenAI | `https://api.tokenlab.sh/v1` |
| `tokenlab-responses` | `openai-responses` | تدفقات عمل OpenAI Responses التي تتوقع دلالات `/v1/responses` | `https://api.tokenlab.sh/v1` |
| `tokenlab-claude` | `anthropic-messages` | واجهة Claude Messages الأصلية | `https://api.tokenlab.sh` |
| `tokenlab-gemini` | `google-generative-ai` | صيغة Gemini الأصلية | `https://api.tokenlab.sh` |
| `tokenlab-minimax` | `anthropic-messages` | توجيه MiniMax الأصلي | `https://api.tokenlab.sh` |

<Warning>
استخدم اللاحقة `/v1` فقط مع `openai-completions` و`openai-responses`.

يجب أن تستخدم الموفرات الأصلية مثل `anthropic-messages` و`google-generative-ai` `https://api.tokenlab.sh` بدون `/v1`، وإلا فقد ينشئ OpenClaw مسارًا علويًا غير صحيح.
</Warning>

## المتطلبات المسبقة

- مثيل OpenClaw مستضاف محليًا (self-hosted)
- يتطلب OpenClaw **2026.9.4** إصدار Node.js ضمن النطاق `>=24.16.0 <25 || >=26.1.0` ([متطلبات الإصدار](https://github.com/openclaw/openclaw/blob/v2026.9.4/package.json)). عند استخدام إصدار آخر من OpenClaw، تحقّق من متطلباته الخاصة.
- مفتاح API من TokenLab — [Get one here](https://tokenlab.sh/dashboard/api?tab=keys)

## التكوين

حرّر تهيئة OpenClaw الخاصة بك:

- **مستضاف ذاتيًا**: `~/.openclaw/openclaw.json`

أضف موفري TokenLab تحت `models.providers`:

استخدم ملف التعريف و`OPENCLAW_STATE_DIR` و`OPENCLAW_CONFIG_PATH` نفسها الخاصة بالبوابة العاملة، وانسخ الإعدادات احتياطيًا. ضع `TOKENLAB_API_KEY` في `.env` العام الموثوق أو بيئة الخدمة لهذه النسخة. قد لا تصل متغيرات الطرفية أو `.env` المشروع إلى عملية الخلفية. راجع [البيئة](https://docs.openclaw.ai/help/environment).

أنشئ نسخة احتياطية من الإعداد النشط. أضف عنصر TokenLab فقط واحتفظ بالمزوّدين والحسابات والنموذج الافتراضي والأذونات الحالية. إذا كان الاسم مستخدمًا، فاختر اسمًا آخر وعدّل الأوامر. للتراجع، احذف العنصر الذي أضفته فقط أو استعد نسخته الاحتياطية.

```json5
{
  models: {
    mode: "merge",
    providers: {
      tokenlab: {
        api: "openai-completions",
        baseUrl: "https://api.tokenlab.sh/v1",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gpt-5.6-terra", name: "GPT-5.6 Terra" },
          { id: "deepseek-reasoner", name: "DeepSeek Reasoner" },
          { id: "qwen3-coder-flash", name: "Qwen 3 Coder Flash" }
        ]
      },
      "tokenlab-responses": {
        api: "openai-responses",
        baseUrl: "https://api.tokenlab.sh/v1",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gpt-5.6-terra", name: "GPT-5.6 Terra (Responses)" },
          { id: "gpt-5.2", name: "GPT-5.2 (Responses)" }
        ]
      },
      "tokenlab-claude": {
        api: "anthropic-messages",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "claude-sonnet-5", name: "Claude Sonnet 5" },
          { id: "claude-opus-5", name: "Claude Opus 5" }
        ]
      },
      "tokenlab-gemini": {
        api: "google-generative-ai",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gemini-3.5-flash", name: "Gemini 3.5 Flash" },
          { id: "gemini-2.5-pro", name: "Gemini 2.5 Pro" }
        ]
      },
      "tokenlab-minimax": {
        api: "anthropic-messages",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "minimax-m3", name: "MiniMax M3" }
        ]
      }
    }
  }
}
```

<Info>
جميع الموفرين الخمسة يستخدمون **نفس مفتاح API**. تحتاج لحساب TokenLab واحد فقط.
</Info>

<Info>
قوائم `models` أعلاه تعرض أمثلة شائعة فقط. أضف المزيد من معرفات النماذج لكل موفر حسب الحاجة.
</Info>

## استخدام النماذج

لا يزال OpenClaw يشير إلى النماذج بصيغة `provider/model`:

في **OpenClaw 2026.9.4**، اختر النموذج للجلسة الحالية فقط باستخدام `-s`. احتفظ بـ `agents.defaults.model` وإعدادات الوكيل الافتراضية والأذونات. استخدم `/model default -s` لإعادة الجلسة إلى نموذجها الافتراضي.

```text
/model tokenlab-claude/claude-sonnet-5 -s
/model default -s
```

### أمثلة على النماذج

| المزوّد | مرجع النموذج | الوصف |
|--------|--------------|-------|
| `tokenlab` | `tokenlab/gpt-5.6-terra` | مسار متوافق مع OpenAI |
| `tokenlab-responses` | `tokenlab-responses/gpt-5.6-terra` | مسار Responses API |
| `tokenlab-claude` | `tokenlab-claude/claude-sonnet-5` | مسار Claude Messages الأصلي |
| `tokenlab-gemini` | `tokenlab-gemini/gemini-3.5-flash` | مسار Gemini الأصلي |
| `tokenlab-minimax` | `tokenlab-minimax/minimax-m3` | مسار MiniMax الأصلي |

تصفّح جميع النماذج المتاحة على [tokenlab.sh/models](https://tokenlab.sh/ar/models).

## متى تستخدم أي موفر

- `tokenlab`: الخيار الافتراضي لمعظم حالات استخدام الوكلاء والدردشة العامة.
- `tokenlab-responses`: استخدمه عندما يعتمد سير عمل OpenClaw صراحةً على دلالات OpenAI Responses.
- `tokenlab-claude`: استخدمه عندما تريد سلوك Messages الأصلي الخاص بـ Claude.
- `tokenlab-gemini`: استخدمه عندما تريد تنسيق طلب/استجابة أصلي لـ Gemini أو تكاملات بصيغة Gemini الموجودة مسبقًا.
- `tokenlab-minimax`: استخدمه عندما تريد MiniMax عبر مساره الأصلي.

إذا لم تكن بحاجة إلى سلوك Gemini الأصلي، فلا يزال بإمكانك استدعاء نماذج Gemini عبر `tokenlab/gemini-*` على المسار المتوافق مع OpenAI.

## الأخطاء الشائعة

<AccordionGroup>
  <Accordion title="لا تزال تستخدم مصفوفة الموفرين القديمة على المستوى العلوي">
    تستخدم وثائق OpenClaw الحالية `models.providers`. إذا احتفظت بالتنسيق القديم لمصفوفة `providers` على المستوى العلوي، فقد يتجاهل OpenClaw التهيئة أو يفشل في حل بادئات الموفر كما هو متوقع.
  </Accordion>
  <Accordion title="نسيان /v1 على tokenlab-responses">
    تقوم `openai-responses` بالتوجيه إلى مسار `/v1/responses` الخاص بـ TokenLab، لذلك يجب أن يستخدم `tokenlab-responses` `https://api.tokenlab.sh/v1`.
  </Accordion>
  <Accordion title="إضافة /v1 إلى tokenlab-claude أو tokenlab-gemini أو tokenlab-minimax">

  </Accordion>
  <Accordion title="هل لا يزال OpenClaw يدعم Gemini الأصلي؟">
    نعم. لا تزال وثائق OpenClaw الحالية تتضمن الموفر المدمج `google` وتدعم أيضًا الموفرات المخصصة باستخدام `api: "google-generative-ai"`. لذا يظل `tokenlab-gemini` مسار Gemini أصليًا صالحًا لمستخدمي OpenClaw.
  </Accordion>
</AccordionGroup>

## التحقق من الإعداد

أعد تشغيل النسخة نفسها وافحص النموذج والمزود. `models status` دون `--probe` ليس اختبارًا لاستدعاء النموذج. الاختبارات الحية والرسائل قد تستهلك tokens. طابق الرد مع سجل TokenLab. للاستعادة اختر النموذج السابق واحذف العناصر المضافة فقط.

```bash
openclaw gateway restart
openclaw models status
```
