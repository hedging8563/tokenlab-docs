## اختيار المزوّد في TokenLab

تختار TokenLab تلقائيًا مزودًا متاحًا للنموذج المطلوب.

### استراتيجيات الاختيار

| الاستراتيجية | السلوك | الأفضل لـ |
|-------------|--------|-----------|
| **PRIORITY** | استخدام المزود المتاح الأعلى أولوية | التركيز على الموثوقية |
| **COST** | استخدام المزود المتاح الأقل تكلفة | التركيز على التكلفة |

يمكنك تعيين استراتيجيتك المفضلة في لوحة التحكم.

### إعادة المحاولة تلقائيًا

إذا كان مزود غير متاح أو أعاد خطأ، تُعيد TokenLab المحاولة تلقائيًا مع مزود آخر متاح:

```
طلب: claude-sonnet-4-6
  → المزود A (أساسي): خطأ 503
  → المزود B (إعادة المحاولة): ✓ نجاح
```

يحدث هذا بشفافية — Coding Agent الخاص بك يرى استجابة طبيعية.

### تنسيقات API الأصلية

عندما يدعم النموذج المحدد تنسيق API أصليًا، يمكن لـ TokenLab استخدام ذلك التنسيق لتحقيق توافق أفضل:

| عائلة النموذج | تنسيق API | عنوان URL الأساسي |
|-------------|------------|----------|
| Claude | Anthropic Messages | `https://api.tokenlab.sh` |
| GPT | استجابات OpenAI | `https://api.tokenlab.sh/v1` |
| Gemini | واجهة Gemini الأصلية للـ API | `https://api.tokenlab.sh` أو `https://api.tokenlab.sh/v1beta` بحسب مسار العميل |
| DeepSeek | دردشة OpenAI | `https://api.tokenlab.sh/v1` |

يمثل Claude Code مسارًا قويًا من نوع Anthropic-native. توجد أيضًا واجهات Gemini-native، لكن Gemini CLI نفسه ما يزال مسار توافق best-effort ولا ينبغي اعتباره سير عمل مستقرًا على المدى الطويل.
