## 概要

[WorkBuddy](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model) は OpenAI 互換 API 用のカスタムモデル画面を提供します。ローカル設定ファイルの手動編集は不要です。

## TokenLab の設定

**Settings → Model** を開き、新しいモデルで **Custom** を選択します。

| フィールド | 値 |
|---|---|
| Endpoint URL | `https://api.tokenlab.sh/v1` |
| API Key | TokenLab API Key |
| Model name | `kimi-k3` |
| Custom Protocol | **オフ** |

<Warning>
Custom Protocol はオフにします。標準モードは Base URL を検証し、`/chat/completions` を自動追加します。オンのまま `/v1` だけを入力すると誤ったパスへ送信されます。
</Warning>

ツール、画像、推論の対応と容量は、選択モデルの現在の TokenLab 情報で確認してください。すべてのモデルで有効にしたり、別モデルの 1M/128K 制限をコピーしたりしないでください。表示されたモデル ID を使います。

保存後に `kimi-k3` を選択し、読み取り専用のフォルダー確認で検証してください。設定画面を共有する前に API Key と非公開エンドポイントを隠してください。

保存と選択はローカル設定の確認です。テキストやツールの実行には TokenLab 残高を使います。応答と[リクエスト記録](https://tokenlab.sh/dashboard/runs?section=requests)を確認してください。元に戻すには以前のモデルを選び、追加した TokenLab 項目だけを削除します。

公式デスクトップ版は macOS と Windows 向けです。[公式モデル編集画面](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)を使います。Linux 版や直接編集可能なファイル形式は前提にしていません。

MCP の [API ツール](/ja/integrations/tokenlab-mcp-server)と Skill の[実装手順](/ja/integrations/coding-agent-skill)は別々に導入します。主モデルは変更しません。
