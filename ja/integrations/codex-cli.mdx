## 既存のエージェントに設定を任せる

パソコンですでに使えるエージェントに、次のタスクをコピーして渡してください。

```text
このガイドを読み、Codex CLI を TokenLab に接続するのを手伝ってください：
https://docs.tokenlab.sh/ja/integrations/codex-cli
インストール済みのバージョンと現在有効な設定を最初に確認してください。
既存のアカウント、プロバイダー、権限、その他の設定を保持してください。
ローカルファイルをバックアップし、変更案を示してください。
必要な API キーは私がローカルで入力します。チャットでキーを求めたり、表示したり、貼り付けたりしないでください。
最初に設定を読み込めることを確認してください。
有料リクエストによるテストは、実行前に費用を別途説明してください。
```

## 概要

Codex CLI は `/v1/responses` で TokenLab に接続します。選択したモデルの `tokenlab.accepted_request_formats` に `openai_responses` が必要です。機能はモデルごとに異なります。

Codex CLI のリモート圧縮は `POST /v1/responses/compact` でサポートされています。Codex は `/compact` と自動圧縮で現在のセッションの `model` を `body.model` に送るため、圧縮に使うモデルを Responses 経路で利用可能にしてください。`/v1/compact` は設定しないでください。

## システム要件

macOS、Linux、Windows は[公式 CLI 手順](https://learn.chatgpt.com/docs/codex/cli)に従ってください。ネイティブ Windows と WSL は別環境です。[Windows ガイド](https://learn.chatgpt.com/docs/windows/windows-sandbox)も参照してください。npm はインストール方法の一つであり、ネイティブバイナリの必須条件ではありません。

## インストール

```bash
npm install -g @openai/codex@0.149.0
```

インストール確認:

```bash
codex --version
```

## 設定

### ステップ1: APIキーを設定

[クイックスタート](/ja/quickstart)の macOS、Linux、WSL、Windows PowerShell 向け手順で、キーをコマンド履歴に残さず `TOKENLAB_API_KEY` を設定し、同じターミナルから Codex を起動します。継続して使う場合はローカルのシークレット管理ツールを利用し、平文のキーをシェル設定へ追記しないでください。

### ステップ2: tokenlab.config.toml を設定

Codex **0.149.0** では、使用中の `CODEX_HOME`（通常は `~/.codex`）に独立した `tokenlab.config.toml` を用意します。名前が未使用の場合だけ作成し、既存の TokenLab プロファイルを編集する場合は先にバックアップしてください。`codex --profile tokenlab` で明示的に読み込み、`config.toml`、`auth.json`、アカウント、権限は変更しません。旧形式の `[profiles.tokenlab]` テーブルは使わないでください。通常の設定に戻すにはこのプロファイルなしで起動します。[公式プロファイル設定](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles)を参照してください。

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"

[model_providers.tokenlab]
env_key = "TOKENLAB_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000
```

この WebSocket モードは Codex クライアント向けの Responses-over-WebSocket ブリッジです。公式の `response.create` イベントだけを受け付けます。`stream` は暗黙で、この transport では `background` と `response.cancel` を利用できません。OpenAI Realtime API ではなく、`session.update`、`conversation.item.*`、`input_audio_buffer.*`、バイナリ音声、ネストされた Realtime の `response.create.response` エンベロープは受け付けません。

<Note>
選んだ設定ファイルがなければ作成してください。編集後は、以下の対応するコマンドで新しいセッションを開始します。
</Note>

現在の Codex は `wire_api = "responses"` を使います。`chat/completions` は指定しません。`env_key` を使うため、このプロバイダーの `requires_openai_auth` は省略または false にします。

<Note>
Responses リクエストは Chat Completions に変換されません。任意のフィールドや今後のフィールドは選択したモデルによって異なります。
</Note>

## 基本的な使い方

**対話モードを開始:**

```bash
codex --profile tokenlab
```

**直接コマンド:**

```bash
codex --profile tokenlab "Fix the bug in main.py line 42"
```

**モデルを指定:**

```bash
codex --profile tokenlab -m gpt-5.6-sol "Build a REST API server"
```

## モデルを選ぶ

現在の `tokenlab.accepted_request_formats` に `openai_responses` を含むモデルを選んでください。実際のコーディング作業で比較し、料金は[モデルページ](https://tokenlab.sh/ja/models)で確認します。

## インタラクティブコマンド

| コマンド | 説明 |
|---------|-------------|
| `/help` | ヘルプを表示 |
| `/exit` or `Ctrl+C` | 終了 |
| `/clear` | 会話をクリア |
| `/status` | 現在のモデル、権限、トークン使用量を表示 |
| `/model <name>` | モデルを切り替え |

## 設定の確認

値を表示せずに、環境変数が設定されているかだけを確認します。この確認ではキーの有効性は検証できません：

```bash
if [ -n "${TOKENLAB_API_KEY:-}" ]; then
  printf '%s\n' 'TOKENLAB_API_KEY is set'
else
  printf '%s\n' 'TOKENLAB_API_KEY is not set'
fi
```

Codex を起動して `/status` を実行し、現在のモデルと権限を確認します。プロファイルを使う場合は、同じプロファイルで起動してください。[公式の状態確認コマンド](https://learn.chatgpt.com/docs/developer-commands?surface=cli#inspect-the-session-with-status)を参照してください。

実際のリクエストを送る準備ができたら、次のコマンドを実行してください。TokenLab の残高を使用します。応答と[リクエスト履歴](https://tokenlab.sh/dashboard/runs?section=requests)の対応する記録を確認してください。環境変数の確認や正常な起動だけでは、リクエストの成功は確認できません。

```bash
codex --profile tokenlab "Reply only with OK. Do not use tools or modify files."
```

## よくあるユースケース

**コードレビュー:**

```bash
git diff | codex --profile tokenlab "Review these code changes"
```

**コミットメッセージ生成:**

```bash
git diff --staged | codex --profile tokenlab "Generate a commit message for these changes"
```

**エラー修正:**

```bash
codex --profile tokenlab "Fix the TypeScript errors in src/components/"
```

**コードの説明:**

```bash
cat main.py | codex --profile tokenlab "Explain what this code does"
```

## トラブルシューティング

<AccordionGroup>
  <Accordion title="接続エラー">
    - `tokenlab.config.toml` の `base_url` が正確に `https://api.tokenlab.sh/v1` であることを確認してください
    - ネットワーク接続を確認してください
    - プロキシの干渉がないことを確認してください
  </Accordion>

  <Accordion title="認証に失敗しました">
    Codex 0.149.0 以降にアップグレードした後、カスタムプロバイダーが `auth.json` だけに依存し、`requires_openai_auth` が未設定または `false` の場合、`API_KEY_REQUIRED` や `401 Unauthorized` が発生することがあります。このガイドでは `env_key` を通じて `TOKENLAB_API_KEY` からキーを読み取るため、`auth.json` には依存しません。`requires_openai_auth` は省略するか `false` のままにしてください。この設定では `true` への変更や `auth.json` の上書きは不要です。

    - 実際に使用している設定またはプロファイルに `env_key = "TOKENLAB_API_KEY"` が含まれていることを確認してください。設定を `tokenlab.config.toml` に保存した場合は、`codex --profile tokenlab` で起動してください
    - Codex を起動するターミナルで環境変数 `TOKENLAB_API_KEY` が設定されていることを確認し、設定後にそのターミナルから Codex を再起動してください
    - キーが `sk-` で始まっていることを確認してください
    - TokenLabダッシュボードでキーが有効であることを確認してください
  </Accordion>

  <Accordion title="モデルが見つかりません">
    - モデル名が完全に一致しているか確認してください
    - モデルの可用性を [tokenlab.sh/en/models](https://tokenlab.sh/ja/models) で確認してください
  </Accordion>

  <Accordion title="Responses ネイティブフィールドが拒否されました">
    - 一部のフィールドは、TokenLabが選択されたモデルとルートでその動作を保証できる場合にのみ`/v1/responses`で利用可能です
    - `unsupported_request_field` が表示された場合、そのフィールドを削除するか、それに依存しないワークフローに切り替えてください
  </Accordion>

  <Accordion title="/compact または自動圧縮が失敗する">
    - Codex CLI は `/v1/compact` ではなく `POST /v1/responses/compact` を呼び出します
    - 圧縮リクエストは現在のセッションの `model` を使用するため、そのモデルは Responses 経路で利用可能である必要があります
    - `wire_api = "responses"` と `base_url = "https://api.tokenlab.sh/v1"` を維持してください
  </Accordion>
</AccordionGroup>
