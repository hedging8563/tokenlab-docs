## 概要

このエンドポイントは主に、アップロードされたバッチ入力ファイルと生成された出力/エラーファイルを含む、TokenLab の OpenAI 互換 Batch API を対象としています。

リクエストが Anthropic Files 互換モードを選ぶ場合、同じルートはバインドされたワークスペースで利用可能な Anthropic スタイルのファイルも一覧できます。


Anthropic ヘッダーがない場合、一覧にはバッチファイルと TokenLab の画像/参照ファイルの両方が含まれることがあります。`purpose=batch`、`purpose=batch_output`、`purpose=user_data`、`purpose=vision` で絞り込めます。
## 注意事項

- バッチ入力ファイルは `purpose=batch` を使用する必要があります。
- 生成された出力ファイルに絞り込むには `purpose=batch_output` を使用してください。
- `completion_window` は現在 `24h` です。
- 出力の順序は保証されていません; 常に `custom_id` で一致させてください。
- バッチアイテム内でのストリーミングはサポートされていません。

## 例

<RequestExample>
```bash cURL
curl -X GET "https://api.tokenlab.sh/v1/files?purpose=batch&limit=20" \
  -H "Authorization: Bearer sk-your-api-key"
```
</RequestExample>

## リクエスト / レスポンス

正確なスキーマについては、上記のインタラクティブなOpenAPIパネルを使用してください。

## 操作のヒント

- 冪等性のある下流の調整には `custom_id` を使用してください。
- ワーカーがバッチを最終化した後にのみ `output_file_id` と `error_file_id` を期待してください。

## フィルター

- バッチおよび画像参照ファイルの `limit` は 1–10000（デフォルト 10000）で、ページ送りには `after` を使います。Anthropic Files モードでは 1–1000（デフォルト 20）です。`after_id` または `before_id` のどちらか一方でページ送りします。
- `purpose` は `batch`、`batch_output`、`user_data`、`vision` のいずれかです。
- `user_data` と `vision` は、利用可能な場合に TokenLab が作成した画像参照ファイルを返します。

## レスポンス例

<ResponseExample>
```json 200 OK
{
  "object": "list",
  "data": [{ "id": "file_abc123", "object": "file", "purpose": "batch" }],
  "first_id": "file_abc123",
  "last_id": "file_abc123",
  "has_more": false
}
```
</ResponseExample>

## 重要フィールド

<ResponseField name="object" type="string">レスポンスの object type です。</ResponseField>
<ResponseField name="data" type="array">このレスポンスで返されるリストまたは payload です。</ResponseField>
<ResponseField name="has_more" type="boolean">`has_more` が true の場合、続きの結果があります。</ResponseField>
