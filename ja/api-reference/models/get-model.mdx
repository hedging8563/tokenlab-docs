---
title: "モデルの取得"
openapi: "/openapi/ja.json GET /v1/models/{model}"
description: "モデルの機能、価格、APIフォーマットを取得します"
---

## パスパラメータ

<ParamField path="model" type="string" required>
  `gpt-5.6-terra` や `claude-sonnet-4-6` などのモデルID。
</ParamField>

## レスポンス

<ResponseField name="id" type="string">モデルID。</ResponseField>
<ResponseField name="object" type="string">常に `model` となります。</ResponseField>
<ResponseField name="owned_by" type="string">モデルの作成者。</ResponseField>
<ResponseField name="tokenlab" type="object">
  機能、価格、課金単位、コンテキスト制限、対応APIフォーマット、操作、ライフサイクルステータスを含むTokenLabモデル情報。
</ResponseField>

一般的な `tokenlab` フィールドには以下が含まれます：

- `capabilities`: テキスト、画像、動画、音声、その他の機能。
- `pricing`: 現在の公開価格。
- `max_input_tokens` および `max_output_tokens`: コンテキストおよび出力の制限。
- `accepted_request_formats`: サポートされているAPIフォーマット。
- `supported_operations`: テキストから画像への変換や画像から動画への変換などの操作。
- `lifecycle`: 可用性、リリース日、廃止日、または代替モデル。

一部のメディアモデルには、推奨ステータスと更新時刻も含まれます。推奨事項は可用性やパフォーマンスに応じて変更される可能性があるため、順序をハードコードしないでください。

## 例

```bash
curl "https://api.tokenlab.sh/v1/models/gpt-5.6-terra"
```

```json
{
  "id": "gpt-5.6-terra",
  "object": "model",
  "owned_by": "openai",
  "tokenlab": {
    "category": "chat",
    "capabilities": ["coding", "json-mode", "prompt-cache", "reasoning", "tool-use", "vision"],
    "accepted_request_formats": ["openai_chat_completions", "openai_responses"]
  }
}
```

不明なモデルを指定した場合は `404 model_not_found` が返されます。
