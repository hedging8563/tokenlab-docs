## Überblick

Gemini CLI **0.60.0** dokumentiert `GOOGLE_GEMINI_BASE_URL` für die API-Schlüssel-Authentifizierung. Nutzen Sie den nativen Gemini-Endpunkt von TokenLab mit einem aktuellen Modell, das `gemini_generate_content` unterstützt. Siehe [Konfigurationsreferenz](https://geminicli.com/docs/reference/configuration/) und [Authentifizierung](https://geminicli.com/docs/get-started/authentication/). Ein Google-Abonnement wird damit nicht über TokenLab geleitet.

## Installation

```bash
npm install -g @google/gemini-cli@0.60.0
gemini --version
```

## Konfiguration

Setzen Sie `TOKENLAB_API_KEY` mit den Terminal-Schritten im [Schnellstart](/de/quickstart) für macOS, Linux, WSL oder Windows PowerShell, ohne den Schlüssel im Befehlsverlauf zu speichern. Starten Sie Gemini CLI in diesem Terminal. Verwenden Sie für dauerhaften Zugriff einen lokalen Secret-Manager statt eines Klartextschlüssels im Shell-Profil.

Erhalten Sie Ihre Google-Anmeldung und bisherige Konfiguration. Wählen Sie für TokenLab ein unbenutztes Konfigurationsverzeichnis wie `~/.gemini-tokenlab` (`$HOME` in PowerShell) und erstellen Sie darin `.gemini`. Kopieren Sie die bisherige `.gemini/settings.json` und benötigte Richtliniendateien an die entsprechenden Stellen; erhalten Sie Berechtigungen, Sandbox und andere Einstellungen. Ergänzen Sie nur in dieser Kopie das folgende Authentifizierungsfeld, oder erstellen Sie die Datei, falls keine existiert. Kopieren Sie keine OAuth-Caches und löschen Sie keine bisherigen Zugangsdaten. Beachten Sie verwaltete Authentifizierungsregeln.

```json
{
  "security": {
    "auth": {
      "selectedType": "gemini-api-key"
    }
  }
}
```

## Verwendung

Der folgende Start verwendet `~/.gemini-tokenlab/.gemini/settings.json`. Passen Sie abweichende Verzeichnisse an. Bestätigen Sie das Arbeitsverzeichnis über Geminis normale Vertrauensabfrage und behalten Sie Werkzeugfreigaben bei. Das Modell wird für diese Sitzung explizit gewählt.

<CodeGroup>
```bash macOS / Linux / WSL
GEMINI_CLI_HOME="$HOME/.gemini-tokenlab" GEMINI_API_KEY="${TOKENLAB_API_KEY:?Set TOKENLAB_API_KEY first}" GOOGLE_GEMINI_BASE_URL=https://api.tokenlab.sh gemini --model gemini-3.5-flash
```

```powershell Windows PowerShell
if (-not $env:TOKENLAB_API_KEY) { throw 'Set TOKENLAB_API_KEY first' }
$previous = @{}
$previous['GEMINI_CLI_HOME'] = [Environment]::GetEnvironmentVariable('GEMINI_CLI_HOME', 'Process')
$previous['GEMINI_API_KEY'] = [Environment]::GetEnvironmentVariable('GEMINI_API_KEY', 'Process')
$previous['GOOGLE_GEMINI_BASE_URL'] = [Environment]::GetEnvironmentVariable('GOOGLE_GEMINI_BASE_URL', 'Process')
try {
  $env:GEMINI_CLI_HOME = (Join-Path $HOME '.gemini-tokenlab')
  $env:GEMINI_API_KEY = $env:TOKENLAB_API_KEY
  $env:GOOGLE_GEMINI_BASE_URL = 'https://api.tokenlab.sh'
  gemini --model gemini-3.5-flash
} finally {
  foreach ($name in $previous.Keys) {
    [Environment]::SetEnvironmentVariable($name, $previous[$name], 'Process')
  }
}
```
</CodeGroup>

Diese Variablen gelten nur für diesen Start. Gespeicherte Konten, Standardmodell und Berechtigungen bleiben bestehen. Starten Sie ohne die Variablen für Ihre bisherige Konfiguration; speichern Sie sie nicht im Shell-Profil.

## Prüfen

Gespeicherte Einstellungen oder eine Modellliste bestätigen weder den Schlüssel noch einen abgeschlossenen Aufruf. Ein Prompt verwendet TokenLab-Guthaben. Prüfen Sie Antwort und [zugehörigen Anfrageeintrag](https://tokenlab.sh/dashboard/runs?section=requests), bevor Sie Werkzeuge testen; auch Hilfsanfragen können berechnet werden.

```text
Reply only with TOKENLAB_CONNECTION_OK. Do not use tools or modify files.
```
