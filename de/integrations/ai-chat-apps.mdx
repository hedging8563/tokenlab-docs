## Übersicht

Die meisten allgemeinen KI-Chat-Apps verbinden sich über den standardmäßigen OpenAI-kompatiblen Chat-Pfad mit TokenLab.

In der Praxis bedeutet das:
- Verwenden Sie `https://api.tokenlab.sh/v1` als Basis-URL, sofern die App nicht explizit eine vollständige Endpunkt-URL anfordert
- Verwenden Sie Ihren TokenLab API-Key als OpenAI-kompatiblen API-Key
- Wählen Sie Modelle aus, die die App in einem Standard-Chat-Workflow verwenden kann

<Note>
Allgemeine Chat-Apps sind in der Regel auf **Chat-Completions** ausgelegt und keine WebSocket-Clients für Codex-Antworten. Für Codex CLI/App, Cursor oder andere Coding-Tools, die ein spezifisches Verhalten für Antworten erfordern, verwenden Sie bitte die dedizierten Integrationsanleitungen.
</Note>

<Note>
**Typ**: Chat-App

**Primärer Pfad**: OpenAI-kompatible Chat-Completions

**Support-Status**: Unterstützter Pfad
</Note>

## Unterstützte Anwendungen

| Anwendung | Plattform | Hinweise |
|-------------|----------|-------|
| Open WebUI | Web, Self-hosted | Beliebte Self-hosted-Option mit OpenAI-kompatiblen Verbindungen |
| LibreChat | Web, Self-hosted | Multi-Provider-Chat-Arbeitsbereich mit benutzerdefinierten OpenAI-Endpunkten |
| LobeChat | Web, Desktop, Self-hosted | Starke Unterstützung für benutzerdefinierte Provider |
| Cherry Studio | Windows, macOS, Linux | Guter OpenAI-kompatibler Provider-Workflow |
| Chatbox | Windows, macOS, Linux | Einfaches OpenAI-kompatibles Setup |
| DeepChat | Windows, macOS, Linux | Desktop-Client mit OpenAI-kompatiblen Provider-Einstellungen |
| Jan | Desktop, Self-hosted | Local-first App mit Remote-OpenAI-kompatiblen Providern |
| TypingMind | Web, Desktop | Verwendet einen benutzerdefinierten Endpunkt-Stil |
| NextChat | Web, Self-hosted | Leichtgewichtiger ChatGPT-Client mit Basis-URL-Überschreibung |
| ChatWise | Windows, macOS | Standard-Muster für benutzerdefinierte Provider |

## Standard-Verbindungswerte

| Feld | Wert |
|-------|-------|
| Basis-URL | `https://api.tokenlab.sh/v1` |
| API-Key | `sk-your-tokenlab-key` |
| API-Typ | OpenAI Compatible |

Falls eine App eine **vollständige Endpunkt-URL** anstelle einer Basis-URL verlangt, verwenden Sie:
- Chat-Completions: `https://api.tokenlab.sh/v1/chat/completions`

## Beispiel-App-Setups

<Tabs>
  <Tab title="LobeChat">
**Selbst gehostetes LobeChat**

    ```bash
    OPENAI_API_KEY=sk-your-tokenlab-key
    OPENAI_PROXY_URL=https://api.tokenlab.sh/v1
    ```

    **LobeChat Cloud**
    1. Öffnen Sie **Settings** → **AI Service Provider**
    2. Wählen Sie **OpenAI**
    3. Geben Sie Ihren TokenLab API-Key ein
    4. Setzen Sie den benutzerdefinierten Endpunkt auf `https://api.tokenlab.sh/v1`
  </Tab>

  <Tab title="Cherry Studio">
    1. Öffnen Sie **Settings** → **Model Provider**
    2. Fügen Sie einen **OpenAI-compatible** Provider hinzu
    3. Geben Sie ein:
       - **Name**: TokenLab
       - **API Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
    4. Fügen Sie die Modelle hinzu, die Sie verwenden möchten
  </Tab>

  <Tab title="Chatbox">
    1. Öffnen Sie **Settings** → **AI Model**
    2. Wählen Sie **OpenAI API Compatible**
    3. Geben Sie ein:
       - **API Host**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
       - **Model**: `gpt-5.4-mini` oder `claude-sonnet-5`
  </Tab>

  <Tab title="TypingMind">
    1. Öffnen Sie **Settings**
    2. Wählen Sie **Custom Endpoint**
    3. Geben Sie ein:
       - **Endpoint URL**: `https://api.tokenlab.sh/v1/chat/completions`
       - **API Key**: `sk-your-tokenlab-key`
    4. Konfigurieren Sie die Modelle, die Sie bereitstellen möchten
  </Tab>

  <Tab title="Open WebUI">
    1. Öffnen Sie **Admin Settings** → **Connections**
    2. Fügen Sie eine **OpenAI-compatible** Verbindung hinzu
    3. Geben Sie ein:
       - **Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
    4. Speichern Sie und wählen Sie die Modelle aus, die Sie bereitstellen möchten
  </Tab>

  <Tab title="DeepChat">
    1. Öffnen Sie **Settings** -> **Model Provider**
    2. Fügen Sie einen OpenAI-kompatiblen Provider hinzu
    3. Geben Sie ein:
       - **Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
       - **Model**: `gpt-5.4-mini`
    4. Speichern Sie und führen Sie einen Test-Chat durch
  </Tab>

  <Tab title="Jan">
    1. Öffnen Sie **Settings** -> **Providers**
    2. Fügen Sie einen Remote-OpenAI-kompatiblen Provider hinzu
    3. Geben Sie ein:
       - **Provider name**: TokenLab
       - **Base URL**: `https://api.tokenlab.sh/v1`
       - **API Key**: `sk-your-tokenlab-key`
    4. Wählen Sie `gpt-5.4-mini` oder ein anderes TokenLab-Modell aus
  </Tab>

  <Tab title="LibreChat">
    Fügen Sie einen OpenAI-kompatiblen Endpunkt in Ihrer LibreChat-Provider-Konfiguration hinzu und verweisen Sie auf:

    ```yaml
    customEndpoints:
      - name: TokenLab
        apiKey: '${OPENAI_API_KEY}'
        baseURL: 'https://api.tokenlab.sh/v1'
        models:
          default: ['gpt-5.4-mini', 'gpt-5.4', 'claude-sonnet-5']
          fetch: false
    ```
  </Tab>
</Tabs>

## Tipps

<AccordionGroup>
  <Accordion title="Bevorzugen Sie die Basis-URL, wenn die App dies unterstützt">
    Die meisten Apps lassen sich einfacher konfigurieren und sind weniger fehleranfällig, wenn Sie `https://api.tokenlab.sh/v1` als Basis-URL angeben, anstatt eine vollständige Endpunkt-URL zu verwenden.
  </Accordion>

  <Accordion title="Verwenden Sie zuerst kleinere Modelle">
    Beginnen Sie mit `gpt-5.4-mini` oder `deepseek-v4-flash` für den täglichen Chat und wechseln Sie für komplexere Aufgaben zu `gpt-5.4` oder `claude-opus-4-8`.
  </Accordion>

  <Accordion title="Halten Sie Coding-Tools getrennt">
    Allgemeine Chat-Apps und Coding-Agenten benötigen oft ein unterschiedliches Endpunkt-Verhalten. Verwenden Sie für Codex/Cursor-Tools die dafür vorgesehenen Integrationsseiten.
  </Accordion>
</AccordionGroup>

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Verbindungsfehler">
    - Überprüfen Sie, ob die Basis-URL exakt `https://api.tokenlab.sh/v1` lautet
    - Entfernen Sie nachgestellte Schrägstriche (Slashes), falls die App Pfade automatisch anhängt
    - Falls die App eine vollständige Endpunkt-URL verlangt, verwenden Sie `https://api.tokenlab.sh/v1/chat/completions`
  </Accordion>

  <Accordion title="401 Nicht autorisiert">
    - Überprüfen Sie Ihren API-Key erneut
    - Bestätigen Sie, dass der Key im TokenLab-Dashboard aktiv ist
    - Stellen Sie sicher, dass keine zusätzlichen Leerzeichen oder Zeilenumbrüche vorhanden sind
  </Accordion>

  <Accordion title="Modell nicht verfügbar">
    - Überprüfen Sie den Modellnamen exakt
    - Versuchen Sie einen weit verbreiteten Standard wie `gpt-5.4-mini`, `deepseek-v4-flash` oder `claude-sonnet-5`
    - Überprüfen Sie die aktuelle Verfügbarkeit in der TokenLab-Dokumentation oder im Dashboard
  </Accordion>
</AccordionGroup>
