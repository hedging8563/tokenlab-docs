## Überblick



<Note>
**Typ**: Coding-Tool

**Primärer Pfad**: OpenAI-kompatibel

**Support-Niveau**: Unterstützter Pfad
</Note>

OpenCode ist ein Open-Source-AI-Coding-Assistent, der in Ihrem Terminal läuft. Er unterstützt mehrere LLM-Anbieter und kann so konfiguriert werden, dass er die API von TokenLab für den Zugriff auf über 300 Modelle verwendet.

## Installation

[OpenCode](https://opencode.ai/docs/)

```bash
npm install -g opencode-ai@1.18.31
```

Installation überprüfen:

```bash
opencode --version
```

## Konfiguration

### Schritt 1: Umgebungsvariablen setzen

Setzen Sie `TOKENLAB_API_KEY` mit den Terminal-Schritten im [Schnellstart](/de/quickstart) für macOS, Linux, WSL oder Windows PowerShell, ohne den Schlüssel im Befehlsverlauf zu speichern. Starten Sie OpenCode in diesem Terminal. Verwenden Sie für dauerhaften Zugriff einen lokalen Secret-Manager statt eines Klartextschlüssels im Shell-Profil.

### Schritt 2: OpenCode konfigurieren

Die folgende Konfiguration wurde mit **OpenCode 1.18.31** geprüft. Andere Versionen müssen anhand ihrer offiziellen Dokumentation separat überprüft werden.

Speichern Sie die Konfiguration in einer separaten Datei `~/.config/opencode/tokenlab.jsonc`. Ist `XDG_CONFIG_HOME` gesetzt, verwenden Sie dort `opencode/tokenlab.jsonc`. Lassen Sie die üblichen Dateien `opencode.json` / `opencode.jsonc`, Konten, Standardmodell und Berechtigungen unverändert. Die separate Datei wird nur bei einem Start mit entsprechendem `OPENCODE_CONFIG` geladen. Sind Datei oder Anbietername bereits belegt, wählen Sie andere Namen und passen Sie die Befehle an.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "tokenlab": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "TokenLab",
      "options": {
        "baseURL": "https://api.tokenlab.sh/v1",
        "apiKey": "{env:TOKENLAB_API_KEY}"
      },
      "models": {
        "gpt-5.6-terra": {
          "name": "GPT-5.6 Terra"
        },
        "gpt-5.6-luna": {
          "name": "GPT-5.6 Luna"
        }
      }
    }
  }
}
```

<Note>
Diese Konfiguration sendet Chat Completions über `@ai-sdk/openai-compatible`. Prüfen Sie in den aktuellen Modelldetails die Unterstützung für Chat Completions und benötigte Werkzeuge. Das Beispiel belegt keine Kompatibilität mit anderen Protokollen oder Versionen.
</Note>

Optional bietet der [wiederherstellbare OpenCode-Konfigurationshelfer](https://github.com/hedging8563/tokenlab-skills/blob/247bb17c53754c8288d2d5cb00824fbd9f32899b/skills/tokenlab-api-integration/references/opencode_setup.md) mit Python 3.11+ eine Vorschau, Anwendung und Wiederherstellung der Originaldatei. Das TokenLab-Skills-Plugin **0.1.2** enthält die neuen Skripte. Ein einzeln installierter Skill kann ebenfalls verwendet werden, sobald er auf eine Version mit diesen Skripten aktualisiert wurde. Aktualisieren Sie vorhandene Plugins oder einzeln installierte Skills gemäß der [README-Anleitung](https://github.com/hedging8563/tokenlab-skills/blob/247bb17c53754c8288d2d5cb00824fbd9f32899b/README.md#update-an-existing-installation) und prüfen Sie, ob das Skript vorhanden ist. Die manuelle Konfiguration auf dieser Seite funktioniert auch ohne Helfer.

## Grundlegende Verwendung

Setzen Sie den Schlüssel gemäß Schnellstart und laden Sie die Datei nur für diesen Start mit expliziter Modellauswahl. Passen Sie eigene Pfade und Anbieternamen an. Erhalten Sie vorhandene Einstellungen für `OPENCODE_CONFIG` oder `OPENCODE_CONFIG_CONTENT` und verwenden Sie eine separate Startumgebung. Projekt- und verwaltete Einstellungen können weiterhin Vorrang haben.

<CodeGroup>
```bash macOS / Linux / WSL
OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode models tokenlab
OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode --model tokenlab/gpt-5.6-terra
```

```powershell Windows PowerShell
$tokenlabConfigRoot = if ($env:XDG_CONFIG_HOME) { $env:XDG_CONFIG_HOME } else { Join-Path $HOME '.config' }
$previousConfig = $env:OPENCODE_CONFIG
try {
  $env:OPENCODE_CONFIG = Join-Path $tokenlabConfigRoot 'opencode/tokenlab.jsonc'
  opencode models tokenlab
  opencode --model tokenlab/gpt-5.6-terra
} finally {
  if ($null -eq $previousConfig) {
    Remove-Item Env:OPENCODE_CONFIG -ErrorAction SilentlyContinue
  } else {
    $env:OPENCODE_CONFIG = $previousConfig
  }
}
```
</CodeGroup>

Die Modellliste prüft das lokale Laden, nicht die Gültigkeit des Schlüssels oder einen erfolgreichen Live-Aufruf. Ein Prompt verbraucht TokenLab-Guthaben; OpenCode kann zusätzlich berechnete Hilfsanfragen senden, etwa für einen Titel. Prüfen Sie Antwort und zugehörige [Anfrageprotokolle](https://tokenlab.sh/dashboard/runs?section=requests).

Starten Sie ohne diese Datei, um Ihre normale Konfiguration zu verwenden. Speichern Sie `OPENCODE_CONFIG` für diese Anleitung nicht im Shell-Profil. Entfernen Sie zum Rückgängigmachen nur die neu erstellte separate Datei oder stellen Sie deren vorherige Sicherung wieder her.

## Verfügbare Modelle

| Modell | Am besten geeignet für |
|-------|----------|
| `gpt-5.6-terra` | Komplexe Aufgaben, Code-Architektur |
| `gpt-5.6-luna` | Schnelle Korrekturen, einfache Abfragen |
| `claude-sonnet-4-6` | Code-Review, Dokumentation |
| `claude-opus-4-6` | Komplexes Schlussfolgern |
| `gemini-3.5-flash` | Schnelle Antworten |

## Häufige Befehle

**Code analysieren:**

```bash
OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode run --model tokenlab/gpt-5.6-terra "What does this function do?" < src/utils.ts
```

**Code generieren:**

```bash
OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode run --model tokenlab/gpt-5.6-terra "Create a REST API with Express"
```

**Änderungen überprüfen:**

```bash
git diff | OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode run --model tokenlab/gpt-5.6-terra "Review these changes"
```

**Fehler beheben:**

```bash
OPENCODE_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/opencode/tokenlab.jsonc" opencode run --model tokenlab/gpt-5.6-terra "Fix the TypeScript errors in this project"
```

## Interaktive Befehle

| Command | Beschreibung |
|---------|-------------|
| `/help` | Verfügbare Befehle anzeigen |
| `/models` | Zu einem anderen Modell wechseln |
| `/clear` | Konversationsverlauf löschen |
| `/exit` | OpenCode beenden |

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Verbindungsfehler">
    - Überprüfen Sie, ob `options.baseURL` auf `https://api.tokenlab.sh/v1` gesetzt ist
    - Überprüfen Sie die Netzwerkverbindung
    - Versuchen Sie `curl https://api.tokenlab.sh/v1/models` zum Testen
  </Accordion>

  <Accordion title="Authentifizierung fehlgeschlagen">
    - Überprüfen Sie, ob die Umgebungsvariable `TOKENLAB_API_KEY` gesetzt ist
    - Überprüfen Sie, ob `options.apiKey` auf `{env:TOKENLAB_API_KEY}` oder eine andere gültige Secret-Quelle verweist
    - Prüfen Sie, ob der Schlüssel mit `sk-` beginnt
    - Stellen Sie sicher, dass der Schlüssel im TokenLab-Dashboard aktiv ist
  </Accordion>

  <Accordion title="Modell nicht gefunden">
    - Prüfen Sie, ob der Modellname in der Konfiguration exakt übereinstimmt
    - Überprüfen Sie die Modellverfügbarkeit unter [tokenlab.sh/en/models](https://tokenlab.sh/de/models)
  </Accordion>
</AccordionGroup>
