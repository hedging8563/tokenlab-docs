## Überblick



<Note>
**Typ**: Coding-Tool

**Primärer Pfad**: OpenAI-kompatibel

**Support-Niveau**: Unterstützter Pfad
</Note>

OpenCode ist ein Open-Source-AI-Coding-Assistent, der in Ihrem Terminal läuft. Er unterstützt mehrere LLM-Anbieter und kann so konfiguriert werden, dass er die API von TokenLab für den Zugriff auf über 300 Modelle verwendet.

## Installation

[OpenCode](https://opencode.ai/docs/)

```bash
npm install -g opencode-ai
```

Installation überprüfen:

```bash
opencode --version
```

## Konfiguration

### Schritt 1: Umgebungsvariablen setzen

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

Für eine permanente Konfiguration fügen Sie Folgendes zu `~/.bashrc` oder `~/.zshrc` hinzu:

```bash
echo 'export TOKENLAB_API_KEY="sk-your-tokenlab-key"' >> ~/.zshrc
source ~/.zshrc
```

### Schritt 2: OpenCode konfigurieren

Die aktuelle Dokumentation von OpenCode empfiehlt, Anbieter über `opencode.json` oder `opencode.jsonc` zu konfigurieren. Für TokenLab verwenden Sie einen benutzerdefinierten Anbieter, anstatt den integrierten `openai`-Anbieter zu überladen:

Das Beispiel nutzt das unterstützte V1-Format. Ergänzen Sie `~/.config/opencode/opencode.json` und behalten Sie Anbieter und Berechtigungen. V2 liest unterstützte V1-Einstellungen; mischen Sie innerhalb eines Anbieters keine V2-Felder. Siehe [Migration](https://opencode.ai/v2/docs/migrate-v1/). Prüfen Sie die Registrierung mit `/models` und einen bezahlten Test im TokenLab-Anfrageprotokoll. Zum Rückgängigmachen wählen Sie das alte Modell und entfernen nur diesen Eintrag.

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "tokenlab": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "TokenLab",
      "options": {
        "baseURL": "https://api.tokenlab.sh/v1",
        "apiKey": "{env:TOKENLAB_API_KEY}"
      },
      "models": {
        "gpt-5.6-terra": {
          "name": "GPT-5.6 Terra"
        },
        "gpt-5.6-luna": {
          "name": "GPT-5.6 Luna"
        }
      }
    }
  },
  "model": "tokenlab/gpt-5.6-terra"
}
```

<Note>
Verwenden Sie `@ai-sdk/openai-compatible` für Kompatibilität im Stil von chat-completions. Wenn Sie ausdrücklich einen Anbieterpfad benötigen, der auf `/v1/responses` basiert, empfiehlt die Anbieter-Dokumentation von OpenCode, das Paket auf `@ai-sdk/openai` umzustellen.
</Note>

## Grundlegende Verwendung

**Interaktiven Modus starten:**

```bash
opencode
```

**Mit einem Prompt ausführen:**

```bash
opencode run "Explain this codebase"
```

**Modell angeben:**

```bash
opencode run --model tokenlab/gpt-5.6-terra "Fix the bugs in main.py"
```

## Verfügbare Modelle

| Modell | Am besten geeignet für |
|-------|----------|
| `gpt-5.6-terra` | Komplexe Aufgaben, Code-Architektur |
| `gpt-5.6-luna` | Schnelle Korrekturen, einfache Abfragen |
| `claude-sonnet-4-6` | Code-Review, Dokumentation |
| `claude-opus-4-6` | Komplexes Schlussfolgern |
| `gemini-3.5-flash` | Schnelle Antworten |

## Häufige Befehle

**Code analysieren:**

```bash
opencode run "What does this function do?" < src/utils.ts
```

**Code generieren:**

```bash
opencode run "Create a REST API with Express"
```

**Änderungen überprüfen:**

```bash
git diff | opencode run "Review these changes"
```

**Fehler beheben:**

```bash
opencode run "Fix the TypeScript errors in this project"
```

## Interaktive Befehle

| Command | Beschreibung |
|---------|-------------|
| `/help` | Verfügbare Befehle anzeigen |
| `/models` | Zu einem anderen Modell wechseln |
| `/clear` | Konversationsverlauf löschen |
| `/exit` | OpenCode beenden |

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Verbindungsfehler">
    - Überprüfen Sie, ob `options.baseURL` auf `https://api.tokenlab.sh/v1` gesetzt ist
    - Überprüfen Sie die Netzwerkverbindung
    - Versuchen Sie `curl https://api.tokenlab.sh/v1/models` zum Testen
  </Accordion>

  <Accordion title="Authentifizierung fehlgeschlagen">
    - Überprüfen Sie, ob die Umgebungsvariable `TOKENLAB_API_KEY` gesetzt ist
    - Überprüfen Sie, ob `options.apiKey` auf `{env:TOKENLAB_API_KEY}` oder eine andere gültige Secret-Quelle verweist
    - Prüfen Sie, ob der Schlüssel mit `sk-` beginnt
    - Stellen Sie sicher, dass der Schlüssel im TokenLab-Dashboard aktiv ist
  </Accordion>

  <Accordion title="Modell nicht gefunden">
    - Prüfen Sie, ob der Modellname in der Konfiguration exakt übereinstimmt
    - Überprüfen Sie die Modellverfügbarkeit unter [tokenlab.sh/en/models](https://tokenlab.sh/de/models)
  </Accordion>
</AccordionGroup>
