## Übersicht



<Note>
**Typ**: Codierwerkzeug

**Primärer Pfad**: OpenAI Responses (erweiterter optionaler Pfad)

**Unterstützung**: Unterstützt mit Modell-/Pfad-Einschränkungen
</Note>

OpenAI Codex ist ein Open-Source-Kommandozeilenwerkzeug (CLI), das als leichtgewichtiger Coding-Agent dient und in der Lage ist, Code im Terminal zu lesen, zu ändern und auszuführen. Es basiert auf GPT-Modellen und ist für Code-Generierung optimiert.

Für TokenLab kann Codex CLI `/v1/responses` verwenden, aber Sie sollten dies als einen erweiterten Kompatibilitätspfad behandeln. Einige Responses-only-Funktionen sind nicht für jedes Modell und jeden gerouteten Pfad garantiert.

Remote Compaction in Codex CLI wird über `POST /v1/responses/compact` unterstützt. Codex sendet bei `/compact` und Auto-Compact das aktuelle Sitzungs-`model` in `body.model`, daher muss das gewünschte Modell auf dem Responses-Pfad verfügbar sein. Konfigurieren Sie nicht `/v1/compact`.

## Systemanforderungen

Folgen Sie der [CLI-Anleitung](https://learn.chatgpt.com/docs/codex/cli) für macOS, Linux oder Windows. Natives Windows und WSL sind getrennte Umgebungen; siehe [Windows-Anleitung](https://learn.chatgpt.com/docs/windows/windows-sandbox). npm ist eine Installationsoption, keine Voraussetzung für native Binärdateien.

## Installation

```bash
npm install -g @openai/codex
```


## Konfiguration

### Schritt 1: API-Schlüssel setzen

**Temporär (aktuelle Sitzung):**

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

**Dauerhafte Konfiguration:**

In `~/.bashrc`, `~/.zshrc` oder `~/.bash_profile` hinzufügen:

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

Dann neu laden:

```bash
source ~/.zshrc  # or source ~/.bashrc
```

### Schritt 2: config.toml konfigurieren

Fügen Sie diese Einstellungen in Ihre benutzerweite `~/.codex/config.toml` ein, ohne die gesamte Datei zu ersetzen. Behalten Sie andere Provider, Konten, Sandbox-Einstellungen und Genehmigungsregeln bei. Provider- und Authentifizierungseinstellungen gehören in die Benutzerkonfiguration, nicht in die `.codex/config.toml` eines Projekts. Siehe [offizielle Konfigurationsanleitung](https://learn.chatgpt.com/docs/config-file/config-advanced#custom-model-providers).

Für den bisherigen Standardanbieter speichern Sie ab Codex 0.134.0 das Beispiel in `~/.codex/tokenlab.config.toml` und starten `codex --profile tokenlab`. Bei angepasstem `CODEX_HOME` gilt dessen Verzeichnis. Verwenden Sie keine alte `[profiles.tokenlab]`-Tabelle, überschreiben Sie nicht `auth.json` und ändern Sie weder Anmeldung noch Genehmigungen. Ohne dieses Profil starten stellt die vorige Auswahl wieder her.

Wählen Sie in jeder Befehlsgruppe unten **TokenLab-Profil** für `tokenlab.config.toml`. Verwenden Sie **TokenLab als Standard** nur, wenn Sie die Einstellungen in `config.toml` eingefügt haben. Ein einfaches `codex` verwendet die Standardkonfiguration und übernimmt kein Profil aus einer vorherigen Sitzung.

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"

[model_providers.tokenlab]
env_key = "TOKENLAB_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000
```

Dieser WebSocket-Modus ist eine Responses-over-WebSocket-Brücke für Codex-Clients. Er akzeptiert nur offizielle `response.create`-Ereignisse; `stream` ist implizit, und `background` sowie `response.cancel` sind auf diesem Transport nicht verfügbar. Er ist nicht die OpenAI Realtime API und akzeptiert keine `session.update`-, `conversation.item.*`-, `input_audio_buffer.*`-Events, kein binäres Audio und keine verschachtelten Realtime-`response.create.response`-Envelopes.

<Note>
Erstellen Sie die gewählte Konfigurationsdatei, falls sie noch nicht existiert. Starten Sie nach Änderungen mit dem passenden Befehl unten eine neue Sitzung.
</Note>

Aktuelles Codex nutzt `wire_api = "responses"`, nicht `chat/completions`. Lassen Sie `requires_openai_auth` weg oder setzen Sie es auf false, damit dieser Anbieter `env_key` verwendet.

<Note>
TokenLab leitet unbekannte Responses-Felder bestmöglich weiter, ohne die Anfrage stillschweigend auf Chat Completions herabzustufen. Der ausgewählte Upstream entscheidet, ob ein Feld oder eine Kombination unterstützt wird.
</Note>

## Empfohlene Modelle

| Modell | Am besten für |
|--------|---------------|
| `gpt-5.6-sol` | Beste Standardwahl für Coding und Reasoning |
| `gpt-5-mini` | Schnellere, günstigere Fallback-Option für Coding-Workflows |
| `claude-sonnet-4-6` | Code-Review, Dokumentation |

## Interaktive Befehle

| Befehl | Beschreibung |
|--------|--------------|
| `/help` | Hilfe anzeigen |
| `/exit` oder `Ctrl+C` | Beenden |
| `/clear` | Konversation löschen |
| `/status` | Aktives Modell, Berechtigungen und Tokenverbrauch anzeigen |
| `/model <name>` | Modell wechseln |

## Konfiguration verifizieren

Prüfen Sie nur, ob die Umgebungsvariable gesetzt ist, ohne ihren Wert auszugeben. Diese Prüfung bestätigt nicht die Gültigkeit des Schlüssels:

```bash
if [ -n "${TOKENLAB_API_KEY:-}" ]; then
  printf '%s\n' 'TOKENLAB_API_KEY is set'
else
  printf '%s\n' 'TOKENLAB_API_KEY is not set'
fi
```

Starten Sie Codex und führen Sie `/status` aus, um das aktive Modell und die Berechtigungen zu prüfen. Falls Sie ein Profil verwenden, starten Sie dasselbe Profil. Siehe [offizieller Statusbefehl](https://learn.chatgpt.com/docs/developer-commands?surface=cli#inspect-the-session-with-status).

Führen Sie den folgenden Befehl erst aus, wenn Sie eine echte Anfrage senden möchten. Dabei wird Ihr TokenLab-Guthaben verwendet. Prüfen Sie die Antwort und den zugehörigen Eintrag unter [Anfragen](https://tokenlab.sh/dashboard/runs?section=requests). Eine gesetzte Variable oder ein erfolgreicher Start allein bestätigt keine erfolgreiche Anfrage.

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Verbindungsfehler">
    - Überprüfen Sie, ob `base_url` in config.toml genau `https://api.tokenlab.sh/v1` ist
    - Prüfen Sie die Netzwerkverbindung
    - Stellen Sie sicher, dass kein Proxy stört
  </Accordion>

  <Accordion title="Authentifizierung fehlgeschlagen">
    Nach dem Upgrade auf Codex 0.149.0 oder neuer können `API_KEY_REQUIRED` oder `401 Unauthorized` auftreten, wenn ein benutzerdefinierter Anbieter ausschließlich `auth.json` verwendet und `requires_openai_auth` nicht gesetzt oder `false` ist. Diese Anleitung liest den Schlüssel über `env_key` aus `TOKENLAB_API_KEY` und verwendet dafür nicht `auth.json`. Lassen Sie `requires_openai_auth` weiterhin weg oder setzen Sie es auf `false`; für diese Konfiguration müssen Sie es weder auf `true` ändern noch `auth.json` überschreiben.

    - Überprüfen Sie, ob die tatsächlich verwendete Konfiguration bzw. das verwendete Profil `env_key = "TOKENLAB_API_KEY"` enthält. Wenn Sie die Einstellungen in `tokenlab.config.toml` gespeichert haben, starten Sie mit `codex --profile tokenlab`
    - Überprüfen Sie, ob `TOKENLAB_API_KEY` in dem Terminal gesetzt ist, aus dem Sie Codex starten. Starten Sie Codex nach dem Setzen der Variable aus diesem Terminal neu
    - Prüfen Sie, ob der Schlüssel mit `sk-` beginnt
    - Stellen Sie sicher, dass der Schlüssel im TokenLab-Dashboard aktiv ist
  </Accordion>

  <Accordion title="Modell nicht gefunden">
    - Prüfen Sie, ob der Modellname genau übereinstimmt
    - Überprüfen Sie die Modellverfügbarkeit unter [tokenlab.sh/en/models](https://tokenlab.sh/de/models)
  </Accordion>

  <Accordion title="Responses-native Feld abgelehnt">
    - Einige Felder sind nur auf `/v1/responses` verfügbar, wenn TokenLab dieses Verhalten für das ausgewählte Modell und den gewählten Pfad garantieren kann
    - Wenn Sie `unsupported_request_field` sehen, entfernen Sie dieses Feld oder wechseln Sie zu einem Workflow, der nicht davon abhängt
  </Accordion>

  <Accordion title="/compact oder Auto-Compact schlägt fehl">
    - Codex CLI ruft `POST /v1/responses/compact` auf, nicht `/v1/compact`
    - Die Compaction-Anfrage verwendet das aktuelle Sitzungs-`model`, daher muss dieses Modell auf dem Responses-Pfad verfügbar sein
    - Behalten Sie `wire_api = "responses"` und `base_url = "https://api.tokenlab.sh/v1"` bei
  </Accordion>
</AccordionGroup>
