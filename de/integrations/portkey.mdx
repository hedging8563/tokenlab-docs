## Überblick

Konfigurieren Sie TokenLab in Portkey als benutzerdefinierten OpenAI-kompatiblen Host. Verwenden Sie Responses nur, wenn Ihre Portkey-Version einen benutzerdefinierten Responses-Endpunkt unterstützt.

<Note>
**Typ**: AI Gateway

**Primäre Pfade**: OpenAI-kompatible Chat-Completions und Responses

**Support-Status**: Unterstützter Pfad
</Note>

## Provider-Werte

| Feld | Wert |
|-------|-------|
| Provider | `openai` |
| Custom Host | `https://api.tokenlab.sh/v1` |
| API key | `sk-your-tokenlab-key` |
| Modell | Eine aktuell verfügbare TokenLab-Modell-ID |

## Chat Completions

Verwenden Sie TokenLab für OpenAI-kompatible Chat-Anfragen:

Das Beispiel setzt ein laufendes, selbst gehostetes Portkey Gateway voraus. Ersetzen Sie die Gateway-URL durch die URL Ihrer Bereitstellung. Senden Sie für Portkey Cloud außerdem Ihren Portkey-API-Schlüssel im Header `x-portkey-api-key`. Siehe die [Portkey-Konfigurationsanleitung](https://portkey.ai/docs/api-reference/inference-api/headers).

```bash
curl https://your-portkey-gateway.example/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "x-portkey-provider: openai" \
  -H "x-portkey-custom-host: https://api.tokenlab.sh/v1" \
  -H "Authorization: Bearer sk-your-tokenlab-key" \
  -d '{
    "model": "gpt-5.6-luna",
    "messages": [{"role": "user", "content": "Say hello from TokenLab."}]
  }'
```

## Responses

Wenn Ihre Portkey-Version eine benutzerdefinierte Responses-URL unterstützt, wählen Sie auf der [Modellseite](https://tokenlab.sh/de/models) ein aktuell verfügbares Modell mit Responses-Unterstützung und verwenden Sie `/v1/responses`.

## Hinweis zu nativen Endpunkten

Anthropic Messages und Gemini können über Portkey nur verwendet werden, wenn Ihre Portkey-Version benutzerdefinierte URLs für diese Formate unterstützt.
