## Überblick

Das Portkey Gateway kann Anfragen an TokenLab als Upstream-Provider weiterleiten. Die sicherste Standardeinstellung sind OpenAI-kompatible Chat-Completions; verwenden Sie Responses, wenn Ihre Portkey-Version diesen Pfad für TokenLab bereitstellt.

<Note>
**Typ**: AI Gateway

**Primäre Pfade**: OpenAI-kompatible Chat-Completions und Responses

**Support-Status**: Unterstützter Pfad
</Note>

## Provider-Werte

| Feld | Wert |
|-------|-------|
| Provider | `tokenlab` |
| Base URL | `https://api.tokenlab.sh/v1` |
| API key | `sk-your-tokenlab-key` |
| Standardmodell | `gpt-5.4-mini` |

## Chat Completions

Verwenden Sie TokenLab für OpenAI-kompatible Chat-Anfragen:

```bash
curl https://your-portkey-gateway.example/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "x-portkey-provider: tokenlab" \
  -H "Authorization: Bearer sk-your-tokenlab-key" \
  -d '{
    "model": "gpt-5.4-mini",
    "messages": [{"role": "user", "content": "Say hello from TokenLab."}]
  }'
```

## Responses

Wenn Ihr Portkey-Build TokenLab Responses routet, verwenden Sie `gpt-5.5`, `gpt-5.4` oder `gpt-5.4-mini` mit `/v1/responses`.

## Hinweis zu nativen Endpunkten

TokenLab stellt außerdem direkt Anthropic Messages- und Gemini-kompatible Endpunkte bereit. Ob diese über Portkey genutzt werden können, hängt vom Provider und der Endpunkt-Unterstützung in Ihrer bereitgestellten Portkey-Version ab.
