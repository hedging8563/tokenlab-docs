## Überblick

Verbinden Sie Dify über das Modell-Provider-Plugin **OpenAI-API-compatible** mit TokenLab. Stellen Sie den Modelltyp auf **LLM**, **Completion mode** auf **Chat** und **API Type** auf **Chat Completions API**. Diese Anleitung verwendet Chat Completions.

<Note>
**Typ**: Framework oder Plattform

**Primärer Pfad**: OpenAI-kompatibler Chat-Pfad

**Support-Vertrauen**: Unterstützt mit Einschränkungen im Umfang
</Note>

## Voraussetzungen

- TokenLab-Konto mit API-Zugriff
- Dify Cloud oder selbst gehostetes Dify

## Konfigurationsschritte

### Schritt 1: API-Key abrufen

1. Melden Sie sich im [TokenLab Dashboard](https://tokenlab.sh/dashboard) an
2. Öffnen Sie [API Keys](https://tokenlab.sh/dashboard/api)
3. Erstellen oder kopieren Sie einen API-Key, der mit `sk-` beginnt

### Schritt 2: Provider konfigurieren

<Steps>
  <Step title="Modell-Provider öffnen">
    Gehen Sie in Dify zu **Settings** → **Model Providers**
  </Step>
  <Step title="OpenAI-API-compatible auswählen">
    Öffnen Sie **OpenAI-API-compatible**. Falls es fehlt, installieren Sie dieses Modell-Provider-Plugin aus dem Dify Marketplace. Wählen Sie **Add model**, um die TokenLab-Einstellungen einzugeben.
  </Step>
  <Step title="TokenLab-Einstellungen eingeben">
    Verwenden Sie diese Werte:

    | Feld | Wert |
    |-------|-------|
    | API Key | `sk-your-tokenlab-key` |
    | Model type | LLM |
    | Completion mode | Chat |
    | API Type | Chat Completions API |
    | API Base URL | `https://api.tokenlab.sh/v1` |
  </Step>
  <Step title="Modelle hinzufügen">
    Fügen Sie die Modelle hinzu, die Sie verwenden möchten, zum Beispiel:
    - `gpt-5.4`
    - `gpt-5.4-mini`
    - `claude-sonnet-5`
    - `claude-opus-4-8`
    - `gemini-3.5-flash`
    - `gemini-3.1-flash-lite`
    - `deepseek-v4-flash`
  </Step>
</Steps>

### Schritt 3: Verbindung testen

1. Wählen Sie ein hinzugefügtes Modell, etwa `gpt-5.4-mini`.
2. Senden Sie einen Test-Prompt
3. Bestätigen Sie, dass Dify eine gültige Antwort erhält

## Embeddings für Knowledge Bases

Für RAG und Knowledge-Base-Indizierung fügen Sie ein Embedding-Modell hinzu, wie zum Beispiel:
- `text-embedding-3-small`
- `text-embedding-3-large`

Legen Sie es dann als Standard-Embedding-Modell in den entsprechenden Knowledge-Base- oder Anwendungseinstellungen fest.

## Empfohlene Modellrollen

| Anwendungsfall | Empfohlene Modelle |
|----------|------------------|
| Standard-Chat | `gpt-5.4-mini`, `gpt-5.4`, `claude-sonnet-5` |
| Tiefes Schlussfolgern | `gpt-5.5`, `gpt-5.4`, `claude-opus-4-8`, `deepseek-v4-pro` |
| Schnell/Günstig | `gpt-5.4-mini`, `gemini-3.5-flash`, `deepseek-v4-flash` |
| Embeddings | `text-embedding-3-small`, `text-embedding-3-large` |

## Bewährte Vorgehensweisen

<AccordionGroup>
  <Accordion title="OpenAI-Plugin als Alternative">
    Das separate **OpenAI**-Plugin kann für Modelle aus seinem unterstützten Katalog verwendet werden. Setzen Sie die benutzerdefinierte Basis-URL auf `https://api.tokenlab.sh/v1` und **API Protocol** auf **Chat Completions**; standardmäßig kann Responses ausgewählt sein. Es ist kein früherer Name für OpenAI-API-compatible und akzeptiert nicht jede benutzerdefinierte Modell-ID.
  </Accordion>

  <Accordion title="Günstigere Modelle für Iterationen verwenden">
    Verwenden Sie `gpt-5.4-mini`, `gemini-3.5-flash` oder `deepseek-v4-flash` während der Iteration und wechseln Sie bei schwereren Workflows nur dort zu stärkeren Modellen, wo dies erforderlich ist.
  </Accordion>

  <Accordion title="Diese Einrichtung verwendet Chat Completions">
    Behalten Sie für diese Einrichtung **Completion mode = Chat** und **API Type = Chat Completions API** bei. Responses ist eine separate API-Option; diese Anleitung richtet weder sie noch WebSocket-Verbindungen ein.
  </Accordion>
</AccordionGroup>

## Fehlerbehebung

<AccordionGroup>
  <Accordion title="Verbindungsfehler">
    - Überprüfen Sie, ob die Basis-URL exakt `https://api.tokenlab.sh/v1` lautet
    - Entfernen Sie nachgestellte Schrägstriche, falls Dify diese dupliziert
    - Bestätigen Sie, dass der Dify-Server TokenLab über das öffentliche Internet erreichen kann
  </Accordion>

  <Accordion title="401 Nicht autorisiert">
    - Überprüfen Sie den API-Key erneut
    - Bestätigen Sie, dass der Key im TokenLab-Dashboard aktiv ist
    - Stellen Sie sicher, dass der in Dify eingefügte Wert keine zusätzlichen Leerzeichen oder Zeilenumbrüche enthält
  </Accordion>

  <Accordion title="Modell nicht gefunden">
    - Überprüfen Sie den Modellnamen exakt
    - Fügen Sie den Modelleintrag erneut hinzu, falls die Provider-UI einen älteren Wert zwischengespeichert hat
    - Überprüfen Sie die aktuelle Modellverfügbarkeit in der TokenLab-Dokumentation oder im Dashboard
  </Accordion>
</AccordionGroup>
