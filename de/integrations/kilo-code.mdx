## Übersicht

<Note>
**Typ**: IDE- und CLI-Coding-Agent

**Primärer Pfad**: OpenAI-kompatible Chat Completions

**Support**: Offizieller Custom-Provider-Pfad
</Note>

[Kilo Code](https://kilo.ai/docs/ai-providers/openai-compatible) unterstützt benutzerdefinierte OpenAI-kompatible Provider in der VS-Code-Erweiterung und der CLI.

## Installation und UI-Konfiguration

Installiere den Pre-Release-Kanal von **Kilo Code** in VS Code oder die CLI:

```bash
npm install -g @kilocode/cli@7.7.2
kilo --version
```

Öffne **Settings → Providers → Custom provider**.

Sichern Sie Anbieter, Modell und Verbindungseinstellungen vor der Änderung lokal. Diese Felder ändern die aktive Modellauswahl; stellen Sie danach die bisherigen Werte wieder her. Lassen Sie angemeldete Konten und Werkzeugberechtigungen unverändert. Überschreiben Sie keine andere OpenAI-kompatible Verbindung ohne wiederherstellbare Sicherung.

| Feld | Wert |
|---|---|
| Provider ID | `tokenlab` |
| Display name | `TokenLab` |
| Provider API | **OpenAI Compatible** |
| Base URL | `https://api.tokenlab.sh/v1` |
| API key | Dein TokenLab API Key |
| Model | `kimi-k3` |

Kilo erkennt Modelle über `/v1/models`. Wähle nach dem Speichern `tokenlab/kimi-k3`.

## CLI-Konfiguration

Setzen Sie `TOKENLAB_API_KEY` mit den Terminal-Schritten im [Schnellstart](/de/quickstart) für macOS, Linux, WSL oder Windows PowerShell, ohne den Schlüssel im Befehlsverlauf zu speichern. Starten Sie Kilo in diesem Terminal. Verwenden Sie für dauerhaften Zugriff einen lokalen Secret-Manager statt eines Klartextschlüssels im Shell-Profil.

Sichern Sie vor dem Start von Kilo **7.7.2** die aktive globale Konfiguration und prüfen Sie `permission.bash`. Fehlt diese explizite Regel in einer bestehenden Konfiguration, ergänzt diese Version `bash: "allow"`, auch bei `permission["*"] = deny`. Erhalten Sie Ihre Shell-Regel ausdrücklich in der globalen Datei: Bei einer bisherigen Wildcard-Regel `deny` ergänzen Sie `"bash": "deny"` im bestehenden `permission`-Objekt. Lassen Sie andere Regeln unverändert. Die separate Anbieterdatei verhindert diese Client-Migration nicht.

Speichern Sie die Konfiguration in einer separaten Datei `~/.config/kilo/tokenlab.jsonc`. Ist `XDG_CONFIG_HOME` gesetzt, verwenden Sie dort `kilo/tokenlab.jsonc`. Lassen Sie die üblichen Dateien `kilo.json` / `kilo.jsonc`, Konten, Standardmodell und Berechtigungen unverändert. Die separate Datei wird nur bei einem Start mit entsprechendem `KILO_CONFIG` geladen. Sind Datei oder Anbietername bereits belegt, wählen Sie andere Namen und passen Sie die Befehle an.

```jsonc
{
  "$schema": "https://app.kilo.ai/config.json",
  "provider": {
    "tokenlab": {
      "options": {
        "apiKey": "{env:TOKENLAB_API_KEY}",
        "baseURL": "https://api.tokenlab.sh/v1"
      },
      "models": {
        "kimi-k3": {
          "name": "Kimi K3",
          "tool_call": true,
          "reasoning": true,
          "modalities": {
            "input": [
              "text",
              "image"
            ],
            "output": [
              "text"
            ]
          },
          "limit": {
            "context": 1048576,
            "output": 131072
          }
        }
      },
      "npm": "@ai-sdk/openai-compatible",
      "name": "TokenLab"
    }
  }
}
```

<CodeGroup>
```bash macOS / Linux / WSL
KILO_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/kilo/tokenlab.jsonc" kilo models tokenlab
KILO_CONFIG="${XDG_CONFIG_HOME:-$HOME/.config}/kilo/tokenlab.jsonc" kilo --model tokenlab/kimi-k3
```

```powershell Windows PowerShell
$previous = @{}
$previous['KILO_CONFIG'] = [Environment]::GetEnvironmentVariable('KILO_CONFIG', 'Process')
try {
  $env:KILO_CONFIG = (Join-Path $(if ($env:XDG_CONFIG_HOME) { $env:XDG_CONFIG_HOME } else { Join-Path $HOME '.config' }) 'kilo/tokenlab.jsonc')
  kilo models tokenlab
  kilo --model tokenlab/kimi-k3
} finally {
  foreach ($name in $previous.Keys) {
    [Environment]::SetEnvironmentVariable($name, $previous[$name], 'Process')
  }
}
```
</CodeGroup>

Gespeicherte Einstellungen oder eine Modellliste bestätigen weder den Schlüssel noch einen abgeschlossenen Aufruf. Ein Prompt verwendet TokenLab-Guthaben. Prüfen Sie Antwort und [zugehörigen Anfrageeintrag](https://tokenlab.sh/dashboard/runs?section=requests), bevor Sie Werkzeuge testen; auch Hilfsanfragen können berechnet werden.
