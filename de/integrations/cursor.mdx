## Geltungsbereich

Diese Anleitung gilt für den **Cursor-Desktopeditor** unter macOS, Windows und Linux. OpenAI BYOK unterstützt laut Cursor normale Chatmodelle ohne Reasoning; die Tab-Vervollständigung nutzt weiterhin Cursor-Modelle. Eine andere OpenAI Base URL erschließt nicht sämtliche TokenLab-Modelle oder Cursor-Funktionen. Siehe die [offiziellen Einschränkungen](https://cursor.com/help/models-and-usage/api-keys).

Für Bild-, Video- und andere API-Werkzeuge können Sie den bisherigen Chatanbieter behalten und [MCP](/de/integrations/tokenlab-mcp-server) ergänzen. Ein [Skill](/de/integrations/coding-agent-skill) liefert Anleitungen und wechselt nicht das Hauptmodell.

## Aufgabe für Ihren vorhandenen Agenten

```text
Lies https://docs.tokenlab.sh/de/integrations/cursor und prüfe meine installierte Version sowie das Betriebssystem.
Kläre, ob ich TokenLab als Hauptmodell, MCP-Werkzeuge oder API-Skills brauche.
Erhalte vorhandene Konten, Anbieterkonfiguration und Berechtigungen; erkläre das Zurücksetzen von Änderungen.
Fordere keine API-Schlüssel im Chat an. Ich trage sie lokal ein und erledige notwendige UI-Schritte.
Erkläre die Kosten einer kleinen Testanfrage. Hilf erst nach meiner ausdrücklichen Wahl dieses Tests bei der Ausführung und gleiche den TokenLab-Anfrageeintrag ab.
```

## Die richtigen Einstellungen öffnen

1. Installieren oder aktualisieren Sie den Desktopeditor über [Cursor Downloads](https://cursor.com/downloads). Diese Schritte konfigurieren weder CLI noch Cloud Agents.
2. Öffnen Sie **Cursor Settings** über die Befehlspalette oder `Cmd/Ctrl + Shift + J`. `Cmd/Ctrl + ,` öffnet die allgemeinen Editoreinstellungen.
3. Notieren Sie unter **Models** die bisherige OpenAI-Konfiguration für eine spätere Wiederherstellung. Behalten Sie andere Anbieter bei.
4. Tragen Sie den TokenLab-Schlüssel lokal in **OpenAI API Key** ein und speichern Sie ihn. Senden Sie ihn nicht im Chat und committen Sie ihn nicht.
5. Aktivieren Sie **Override OpenAI Base URL** und tragen Sie Folgendes ein:

```text
https://api.tokenlab.sh/v1
```

Auch BYOK-Anfragen laufen zur Zusammenstellung des Prompts über Cursors Server. Der Editor verbindet sich nicht direkt mit TokenLab.

## Ein Modell wählen

Kopieren Sie die exakte ID aus dem aktuellen [TokenLab-Katalog](https://tokenlab.sh/de/models) und prüfen Sie Cursors OpenAI-BYOK-Unterstützung. Die Kategorie chat bei TokenLab allein belegt keine Cursor-Kompatibilität.

Für einen ersten Texttest eignet sich `gpt-4.1-mini` als Beispiel ohne Reasoning, sofern es noch angeboten wird. Aktivieren Sie den vorhandenen Eintrag unter **Models** oder verwenden Sie **Add model**, falls er fehlt. Wählen Sie ihn anschließend im Chat. Legen Sie integrierte Modelle nicht unter abweichenden Schreibweisen doppelt an; Claude und Gemini nutzen nicht automatisch den OpenAI-Override. Siehe [Cursors Hinweise](https://forum.cursor.com/t/add-custom-model-fail-no-models-available/163488).

## Eine kleine Anfrage prüfen

Starten Sie mit dem ausgewählten Modell einen neuen Chat und senden Sie:

```text
Antworte nur mit TOKENLAB_CONNECTION_OK. Verwende keine Werkzeuge und ändere keine Dateien.
```

Diese Anfrage ist kostenpflichtig. Prüfen Sie die Antwort sowie Modell, Zeitpunkt und Status im passenden [TokenLab-Anfrageeintrag](https://tokenlab.sh/dashboard/runs?section=requests). Ein sichtbares Modell oder eine Antwort ohne diesen Eintrag bestätigt den Weg nicht.

## Fehler beheben

- **Modell fehlt oder wird abgelehnt:** Prüfen Sie ID und BYOK-Unterstützung; verwenden Sie vorhandene integrierte Einträge. Ein Neustart beseitigt keine Inkompatibilität.
- **Authentifizierungsfehler:** Prüfen Sie TokenLab-Schlüssel im OpenAI-Feld und Base URL. Guthaben- oder Kontingentfehler sind von einem ungültigen Schlüssel zu unterscheiden.
- **Kein TokenLab-Eintrag:** Prüfen Sie Chatmodell, Override und Cursor-Fehler. Tab-Vervollständigung ist kein Verbindungstest.
- **Anderer Anbieter funktioniert nicht mehr:** Stellen Sie die bisherige OpenAI-Konfiguration wieder her oder deaktivieren Sie den Override und starten Sie einen neuen Chat.

## MCP und Skills separat ergänzen

[MCP](/de/integrations/tokenlab-mcp-server) ergänzt aufrufbare Werkzeuge über Cursors MCP-Einstellungen oder `.cursor/mcp.json`. Prüfen Sie zuerst die Werkzeugerkennung und führen Sie kostenpflichtige Generierung nur gezielt aus. MCP ersetzt das Hauptmodell nicht.

[Skills](/de/integrations/coding-agent-skill) liefern API-Anleitungen. Legen Sie den vollständigen Ordner mit `SKILL.md` und Referenzdateien unter `.cursor/skills/tokenlab-api-integration/` ab und prüfen Sie **Customize → Skills**. Ein Skill liefert weder Schlüssel noch MCP-Server. Versionsabhängige Details stehen in den offiziellen [MCP](https://cursor.com/docs/mcp)- und [Skills](https://cursor.com/docs/skills)-Anleitungen.
