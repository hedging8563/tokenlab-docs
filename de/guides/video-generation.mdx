Die Videoerstellung ist asynchron. `POST /v1/videos/generations` gibt eine öffentliche Aufgabenidentität und normalerweise eine `poll_url` zurück; das endgültige Video erscheint in späteren Statusantworten.

Übergeben Sie öffentliche HTTP(S)-URLs oder unterstützte data-URLs in den Bildfeldern des gewählten Modells. Sie werden als normale Medieneingaben verarbeitet und erzeugen nicht automatisch wiederverwendbare Material-IDs.

Ist ein ausdrücklich angegebenes Material noch in Vorbereitung, liefert `POST /v1/videos/generations` den Fehler `409 seedance_material_preparing` mit `inactive_asset_ids`. Fragen Sie diese Assets bis `ACTIVE` ab und wiederholen Sie die Anfrage mit denselben IDs. Bei `FAILED` prüfen Sie zunächst `error_message` und korrigieren oder importieren das Asset erneut.

## Unterstützte Operationen

Verwenden Sie explizite `operation` in der Produktion. TokenLab kann einige Operationen aus den Eingaben ableiten, aber explizite Betriebswerte machen Validierung, Unterstützung und Wiederholungen klarer.

| Operation | Erforderliche oder typische Eingabe | Anwendungsfall |
|-----------|-------------------------------------|----------------|
| `text-to-video` | `prompt` | Nur aus Text generieren |
| `image-to-video` | `image_url` oder kompatibles `image` | Ein Startbild animieren |
| `reference-to-video` | `reference_images` und optionale `video_urls` / `audio_urls` bei unterstützten Modellen | Identität, Stil oder Asset-Referenzen beibehalten |
| `start-end-to-video` | `start_image`, `end_image` | Erste und letzte Frames steuern |
| `video-to-video` | `video_url` oder modell-spezifische `task_id` | Einen bestehenden Clip transformieren oder hochskalieren |
| `motion-control` | `image_url` plus `video_url` | Bewegungsreferenz auf ein Subjekt anwenden |
| `audio-to-video` | `audio_url` | Audio-konditionierte Videoabläufe |
| `video-extension` | `task_id`, `extend_at` oder modell-spezifische Erweiterungsfelder | Ein generiertes Video fortsetzen |

## Modellerkennung

```bash
curl "https://api.tokenlab.sh/v1/models?recommended_for=video" \
  -H "Authorization: Bearer sk-your-api-key"
```

Verwenden Sie in `model` die von TokenLab angezeigten Modell-IDs und wählen Sie Funktionsvarianten mit `operation` und den passenden Medieneingaben. Beispiele sind `wan-2.7`, `happyhorse-1.0`, `viduq3`, `viduq3-mix`, `pixverse-v6`, `veo3.1` und `seedance-2.0`; verwenden Sie keine operationsspezifischen Suffixe als TokenLab-Modellnamen.

Lesen Sie die Details des ausgewählten Modells, bevor Sie sich auf spezialisierte Felder wie `reference_images`, `kling_elements`, `output_audio`, `duration`, `resolution` oder `aspect_ratio` verlassen.

## Anfrage erstellen

```bash
curl https://api.tokenlab.sh/v1/videos/generations \
  -H "Authorization: Bearer sk-your-api-key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "veo3.1",
    "operation": "text-to-video",
    "prompt": "Eine ruhige filmische Aufnahme einer Katze, die durch einen sonnigen Garten läuft",
    "duration": 4,
    "aspect_ratio": "16:9"
  }'
```

Für Produktionsmedieneingaben bevorzugen Sie öffentliche `https` URLs gegenüber Inline-`data:` URLs. Wenn Sie temporäre URLs verwenden, halten Sie diese gültig, bis TokenLab die Aufgabe erstellt hat.

## Eingaben und modell-spezifische Felder

- Anfragen der Veo 3 Familie sind standardmäßig auf Audio-an, wenn `output_audio` weggelassen wird. Setzen Sie es explizit, wenn das Modell den Schalter unterstützt und Ihre UX von Ton abhängt.
- Lesen Sie für die Seedance 2.0 Familie den [Leitfaden zu Seedance 2.0 Videomodellen](/de/guides/seedance-2-video), bevor Sie 4K-Ausgabe, Fast/Mini-Auflösungsgrenzen oder multimodale Referenzeingaben verwenden.
- Für video-to-video mit `grok-imagine-video` senden Sie `prompt` und eine öffentliche HTTPS-URL einer `.mp4`-Datei als `video_url`. Diese Operation verwendet keine Auswahl über `duration`, `resolution` oder `aspect_ratio`.

## Ergebnisse abfragen

Verwenden Sie zuerst die zurückgegebene `poll_url`. Wenn Sie einen festen Endpunkt benötigen, verwenden Sie `GET /v1/tasks/{id}` mit derselben `id` / `task_id` aus der Erstellungsantwort.

Abgeschlossene Videoaufgaben können je nach Modell und Ausgabemenge `video_url`, `video` oder `videos` zurückgeben. Behandeln Sie `billing_transaction_id` als Abrechnungsidentifikator, nicht als Aufgabenidentifikator.

## Häufige Fallstricke

- Kodieren Sie keine alten Video-Statuspfade; bevorzugen Sie `poll_url`.
- Kombinieren Sie keine ersten Frame-Felder mit speziellen Referenzbildabläufen, es sei denn, der Modelldetails erlaubt dies.
- Gehen Sie nicht davon aus, dass `duration` die Länge des Eingangsreferenzvideos beschreibt; es steuert normalerweise die Länge des generierten Outputs.
- Wiederholen Sie keine Erstellungsanfragen nach einem Timeout, ohne zu überprüfen, ob bereits eine Aufgabe erstellt wurde.

## OpenAI-Style und Volc-kompatible Video-APIs

Verwenden Sie `/v1/videos/generations` für die einheitliche TokenLab Video-API über mehrere Modelle hinweg. Wenn Sie eine bestehende Seedance-2.0-Integration migrieren, die bereits Volc-ähnliche `content[]`- oder Action-Anfragen nutzt, verwenden Sie die Seedance-Kompatibilitätsendpunkte unter `/api/v3`. Beide Varianten verwenden TokenLab Bearer API Keys und asynchrones Polling, aber Anfrage- und Antwortformate unterscheiden sich.
