Seedance-Materialien sind innerhalb einer Organisation wiederverwendbare Bild-, Video- oder Audioreferenzen. Wählen Sie zuerst den Workflow: Normale Avatar-Materialien und verifizierte Personenmaterialien haben unterschiedliche Erstellungspfade.

## Material-Workflow wählen

| Ziel | Erforderlicher Ablauf |
| --- | --- |
| Einmalige Bild-URL verwenden | URL in einem unterstützten Bildfeld senden; dadurch entsteht keine wiederverwendbare Material-ID |
| Avatar, Produkt oder Stil wiederverwenden | `aigc_avatar`-Gruppe und Asset erstellen, auf `ACTIVE` warten und Asset-ID verwenden |
| Reale Person wiederverwenden | Visuelle Verifizierung abschließen, `GroupId` erhalten, Asset erstellen, auf `ACTIVE` warten und Asset-ID verwenden |
| Volcengine-Materialclient migrieren | Action-Format beibehalten und Volcengine-kompatible Materialreferenz verwenden: [Material-Actions (Volcengine-kompatibel)](/de/api-reference/video/volc-compatible-material-actions) |

## Materialkonzepte

Seedance-Materialien sind wiederverwendbare, organisationsbezogene Referenzen, die später während der Videogenerierung ausgewählt werden können.

| Konzept | Öffentliches Feld | Bedeutung |
|---------|--------------|---------------|
| Materialgruppe | `group_id` | Eine TokenLab-Gruppe, die zugehörige Seedance-Materialien enthält. Verwenden Sie diese beim Hochladen oder Auflisten von Materialien. |
| Material-Asset | `id` | Eine hochgeladene Bild-, Video- oder Audiodatei. Verwenden Sie diesen Wert als `material_asset_id`, nachdem das Asset den Status `ACTIVE` erreicht hat. |
| Materialgruppe für virtuelle Avatare | `library_type: "aigc_avatar"` | Für virtuelle Personen, Avatare, Produkte, Stile und andere wiederverwendbare Referenzen, die keine Verifizierung echter Personen erfordern. |
| Materialgruppe für echte Personen | `library_type: "liveness_face"` | Erstellt durch die Verifizierung von Material echter Personen. Eine Gruppe repräsentiert eine verifizierte echte Person. |

Halten Sie `group_id` und Material-Asset `id` getrennt. `group_id` dient der Organisation von Uploads; die Material-Asset `id` dient der Videogenerierung. Wenn eine Videoanfrage `Seedance material asset not found or not accessible` zurückgibt, stellen Sie sicher, dass Sie eine Material-Asset `id` und keine `group_id` übergeben haben und dass das Asset zur selben Organisation gehört, nicht gelöscht wurde und den `status: "ACTIVE"` aufweist.

## Bild-URLs und wiederverwendbare Materialien

Übergeben Sie öffentliche HTTP(S)-URLs oder unterstützte data-URLs in den Bildfeldern des gewählten Modells. Sie werden als normale Medieneingaben verarbeitet und erzeugen nicht automatisch wiederverwendbare Material-IDs.

Für wiederverwendbare Materialien erstellen Sie ein Asset über die Material-API, warten auf `ACTIVE` und verwenden dann `material_asset_id`, `material_asset_ids` oder `asset://<id>` in einem unterstützten Medienfeld. Behalten Sie die Rolle als Anfangsbild, Endbild oder Referenzbild bei.

Ist ein ausdrücklich angegebenes Material noch in Vorbereitung, liefert `POST /v1/videos/generations` den Fehler `409 seedance_material_preparing` mit `inactive_asset_ids`. Fragen Sie diese Assets bis `ACTIVE` ab und wiederholen Sie die Anfrage mit denselben IDs. Bei `FAILED` prüfen Sie zunächst `error_message` und korrigieren oder importieren das Asset erneut.

## Verifizierung von Material echter Personen

Verwenden Sie die Verifizierung von Material echter Personen, wenn Ihr Produkt eine Zustimmung und Gesichtsverifizierung erfordert, bevor eine echte Person als wiederverwendbare Seedance-Referenz genutzt werden kann.

1. Rufen Sie [Visuelle Verifizierungssitzung erstellen](/de/api-reference/video/create-visual-validation-session) mit `CallbackURL` auf und speichern Sie den zurückgegebenen `Result.BytedToken`.
2. Öffnen Sie `Result.H5Link` für die zu verifizierende Person. Hängen Sie für eine bestimmte Sprache `lng` an den H5-Link an.
3. Nach Abschluss des H5-Ablaufs öffnet der Browser `Result.CallbackURL` mit offiziellen Abfragenamen wie `bytedToken` und `resultCode`.
4. Rufen Sie [Visuelles Verifizierungsergebnis abrufen](/de/api-reference/video/get-visual-validation-result) wiederholt mit `BytedToken` auf, bis `Result.GroupId` zurückgegeben wird.
5. Speichern Sie `GroupId` und verwenden Sie sie beim Erstellen von `liveness_face`-Materialien als `group_id`.

`BytedToken` ist 30 Minuten gültig. Verwenden Sie in beiden Action-Anfragen denselben `ProjectName`. Die Authentifizierung erfolgt mit `Authorization: Bearer <TOKENLAB_API_KEY>`; Volc-AK/SK-Signaturen werden nicht akzeptiert.

Öffnen Sie den zurückgegebenen `H5Link` direkt nach der Erstellung. Die Token-Gültigkeit garantiert nicht, dass die Prüfseite zu jedem Zeitpunkt dieses Zeitraums erstmals geöffnet werden kann.

Optional: Verwenden Sie die [Testkonsole](https://tokenlab.sh/dashboard/seedance-assets), um Ihren Anfrage- und Callback-Ablauf zu verifizieren, Materialgruppen zu untersuchen und den Verifizierungsverlauf einzusehen. Ihre Produktionsintegration sollte die APIs direkt aufrufen.

## Erstellen von Materialgruppen

Verwenden Sie [Material-Asset-Gruppe erstellen](/de/api-reference/video/create-material-asset-group) für `aigc_avatar`-Gruppen. Neue Gruppen für echte Personen werden über den Verifizierungsprozess erstellt, damit die verifizierte Person und die Materialgruppe verknüpft bleiben.

Verwenden Sie [Material-Asset-Gruppen auflisten](/de/api-reference/video/list-material-asset-groups), [Material-Asset-Gruppe abrufen](/de/api-reference/video/get-material-asset-group), [Material-Asset-Gruppe aktualisieren](/de/api-reference/video/update-material-asset-group) und [Material-Asset-Gruppe löschen](/de/api-reference/video/delete-material-asset-group), um Gruppen zu verwalten, nachdem sie erstellt wurden.

Das Löschen einer Materialgruppe löscht auch die darin enthaltenen TokenLab-Materialien und kann nicht rückgängig gemacht werden. Wenn die TokenLab-Materialbibliothek den Löschvorgang nicht abschließen kann, weil der aktuelle Autorisierungsstatus dies nicht zulässt, gibt TokenLab einen neutralen Materialbibliotheksfehler zurück.

## Hochladen von Materialien

Verwenden Sie [Material-Asset erstellen](/de/api-reference/video/create-material-asset), um jeweils eine öffentlich erreichbare Quell-URL zu importieren.

Für `aigc_avatar` ist die `group_id` optional; TokenLab verwendet oder erstellt die standardmäßige virtuelle Avatar-Gruppe der Organisation. Für `liveness_face` ist die `group_id` erforderlich und muss die Gruppe sein, die von [Visuelles Verifizierungsergebnis abrufen](/de/api-reference/video/get-visual-validation-result) zurückgegeben wurde.

| Typ | Unterstützte Eingabe |
|------|-----------------|
| Bild | `jpeg`, `png`, `webp`, `bmp`, `tiff`, `gif`, `heic`, `heif`; ≤ 30 MiB; Breite und Höhe [300, 6000] px; Seitenverhältnis [0.4, 2.5] |
| Video | `mp4`, `mov`; ≤ 200 MiB |
| Audio | `aac`, `wav`, `mp3`; ≤ 15 MiB |

Die Tabelle zeigt Importgrenzen. Eine angenommene Anfrage garantiert nicht die erfolgreiche Medien- oder Personenprüfung. Warten Sie auf `ACTIVE`; bei `FAILED` korrigieren Sie die Quelle anhand von `error_message` vor einem neuen Import.

Die Materialaufnahme erfolgt asynchron. Pollen Sie [Material-Asset abrufen](/de/api-reference/video/get-material-asset), bis der `status` auf `ACTIVE` wechselt. Eine erfolgreiche HTTP-Antwort bedeutet lediglich, dass die Anfrage akzeptiert wurde; lesen Sie immer den Geschäftsstatus. Wenn der Status `FAILED` lautet, untersuchen Sie die `error_message`, korrigieren Sie das Quellmaterial und erstellen Sie ein neues Asset.

In Anfragen zum Erstellen von Materialien ist `asset_url` nur die Importquelle. TokenLab gibt eine Material-Asset-`id` zurück; verwenden Sie diese `id` für die Generierung statt der ursprünglichen URL.

TokenLab behält Material-Assets in Ihrer Organisationsbibliothek, bis Sie das Asset oder seine Materialgruppe löschen.

Bei Materialgruppen für echte Personen entspricht eine Gruppe einer echten Person. Uploads werden mit dem verifizierten Gesicht abgeglichen. Assets mit mehreren Gesichtern oder einem Gesicht, das nicht mit der verifizierten Person übereinstimmt, können fehlschlagen. Für beste Ergebnisse laden Sie sowohl ein Ganzkörper-Referenzbild von vorne als auch eine Nahaufnahme von vorne hoch, auf der das Gesicht klar erkennbar ist.

## Verwendung von Materialien bei der Videogenerierung

Nachdem ein Asset `ACTIVE` ist, übergeben Sie die zurückgegebene TokenLab-Asset `id` als `material_asset_id` oder fügen Sie sie in `material_asset_ids` ein, wenn Sie [Video erstellen](/de/api-reference/video/create-video) aufrufen. Material-Assets zählen gegen die Seedance-Referenzlimits.

## REST oder Volcengine Action

TokenLab-native Integrationen können weiterhin die snake_case-REST-API `/v1/videos/assets*` verwenden. Bestehende Volcengine-Clients behalten PascalCase-Bodies und verwenden die [Volcengine-kompatiblen Material-Actions](/de/api-reference/video/volc-compatible-material-actions). Beide Varianten bearbeiten dieselben organisations- und projektgebundenen Materialdaten.

## API-Beispiele

Erstellen Sie eine virtuelle Avatar-Gruppe, laden Sie ein Bild hoch, pollen Sie, bis es aktiv ist, und verwenden Sie dann die Material-Asset-ID in einer Videoanfrage.

```bash
curl https://api.tokenlab.sh/v1/videos/assets/groups \
  -H "Authorization: Bearer $TOKENLAB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"library_type":"aigc_avatar","group_name":"Product references"}'

curl https://api.tokenlab.sh/v1/videos/assets \
  -H "Authorization: Bearer $TOKENLAB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"library_type":"aigc_avatar","group_id":"group-20260720123456-abc12","asset_url":"https://example.com/reference.png","asset_type":"Image"}'

curl https://api.tokenlab.sh/v1/videos/assets/asset-20260720123457-def45 \
  -H "Authorization: Bearer $TOKENLAB_API_KEY"
```

Erstellen Sie für eine Materialgruppe einer echten Person zuerst eine visuelle Verifizierungssitzung und rufen Sie das Ergebnis ab, bevor Sie Materialien hochladen.

```bash
curl 'https://api.tokenlab.sh/api/v3?Action=CreateVisualValidateSession&Version=2024-01-01' \
  -H "Authorization: Bearer $TOKENLAB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"CallbackURL":"https://yourapp.example.com/seedance/callback","ProjectName":"default"}'

curl 'https://api.tokenlab.sh/api/v3?Action=GetVisualValidateResult&Version=2024-01-01' \
  -H "Authorization: Bearer $TOKENLAB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"BytedToken":"ZXhhbXBsZS10b2tlbg","ProjectName":"default"}'
```

## Vollständiger Action-Ablauf für reale Personen

Übergeben Sie die vom Verifizierungsergebnis gelieferte `GroupId` an `CreateAsset`.

```bash
curl 'https://api.tokenlab.sh/?Action=CreateAsset&Version=2024-01-01' \
  -H "Authorization: Bearer $TOKENLAB_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "GroupId":"group-20260720123456-real1",
    "URL":"https://example.com/person-front.png",
    "Name":"Verified front view",
    "AssetType":"Image",
    "ProjectName":"default"
  }'
```

Pollen Sie `GetAsset`, bis der Status `Active` ist, und verwenden Sie dann die zurückgegebene Material-ID in der Videogenerierung.
