## Übersicht

Dieser Endpunkt dient in erster Linie dem Abruf von Datei-Inhalten in TokenLabs OpenAI-kompatibler Batch-API.

Wenn die Anfrage in den Anthropic-Files-Kompatibilitätsmodus wechselt, kann dieselbe Route außerdem den ursprünglich gespeicherten Dateiinhalte für den gebundenen Workspace durchreichen.


Ohne Anthropic-Header lädt diese Route Batch-Dateiinhalte herunter oder proxyt Inhalte einer gebundenen Bild-/Referenzdatei, wenn der Anbieter Dateiinhalte abrufen kann.
## Hinweise

- Batch-Eingabedateien müssen `purpose=batch` verwenden.
- Verwenden Sie `purpose=batch_output`, um sich auf erzeugte Ausgabedateien zu konzentrieren.
- `completion_window` beträgt derzeit `24h`.
- Die Ausgabe-Reihenfolge ist nicht garantiert; immer nach `custom_id` abgleichen.
- Streaming wird innerhalb von Batch-Elementen nicht unterstützt.

## Beispiel

<RequestExample>
```bash cURL
curl -X GET "https://api.tokenlab.sh/v1/files/file_abc123/content" \
  -H "Authorization: Bearer sk-your-api-key" \
  --output batch-output.jsonl
```
</RequestExample>

## Anfrage / Antwort

Verwenden Sie das interaktive OpenAPI-Panel oben für das genaue Schema.

## Betriebliche Tipps

- Verwenden Sie `custom_id` für idempotente nachgelagerte Abstimmungen.
- Erwarten Sie `output_file_id` und `error_file_id` erst, nachdem der Worker den Batch abgeschlossen hat.

## Inhaltstypen

Batch-Dateiinhalte werden als JSONL oder Klartext zurückgegeben. Inhalte von TokenLab-erstellten Bildreferenzen können als Binärdaten weitergeleitet werden, wenn der zugrunde liegende Dateianbieter den Inhaltsabruf unterstützt.

## Antwortbeispiel

<ResponseExample>

## Wichtige Felder

<ResponseField name="body" type="binary|string">Dateiinhalt. Je nach `Content-Type` speichern oder verarbeiten; JSONL zeilenweise parsen.</ResponseField>
<ResponseField name="custom_id" type="string">ID zum Zuordnen eines Batch-Eingabeelements zu seinem Ergebnis.</ResponseField>
