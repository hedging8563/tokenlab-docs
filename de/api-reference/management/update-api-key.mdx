---
title: "API-Key aktualisieren"
openapi: "PATCH /v1/management/api-keys/{keyId}"
description: "Aktualisiert einen vorhandenen Benutzer-API-Key für die aktuelle Organisation."
---

## Überblick

Verwenden Sie diesen Endpunkt, um Name, Nutzungslimit, erlaubte Modelle, Ablaufzeit oder Status eines vorhandenen Benutzer-API-Keys zu aktualisieren.

## Request-Body

Mindestens ein Feld muss angegeben werden.

| Feld | Typ | Standard / Grenzen | Beschreibung |
|------|-----|--------------------|--------------|
| `status` | enum | - | `active`, `inactive`, `revoked` |
| `name` | string | Länge `1-50` | Aktualisierter Anzeigename |
| `limitAmount` | number \| null | min. `0`, Eingabe max. `1000000` | `null` = unbegrenzt, `0` = Nullkontingent. Positive Werte werden auf ein gespeichertes Limit normalisiert, das 100000 USD Gegenwert nicht überschreiten kann. |
| `limitCurrency` | enum | Standardwert `USD` | Nur USD. Das Senden von `CNY` gibt `400 currency_retired` zurück. |
| `models` | string[] | - | Aktualisierte Allowlist für logische Modelle |
| `expiresAt` | string \| null | RFC3339-Datetime | `null` entfernt die Ablaufzeit |

## Hinweise

- Geldbetragsfelder unterstützen ausschließlich USD. `CNY`-Eingaben sind außer Betrieb genommen und geben `400 currency_retired` zurück.

- Hard Delete wird in Management API v1 bewusst nicht unterstützt.
- `revoked` ist für den normalen operativen Einsatz ein Endzustand; erstellen Sie lieber einen neuen Key, statt auf eine spätere Reaktivierung zu hoffen.

## Beispiel

<RequestExample>
```bash cURL
curl -X PATCH "https://api.tokenlab.sh/v1/management/api-keys/key_abc123def456" \
  -H "Authorization: Bearer mt-your-management-token" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "inactive",
    "limitAmount": 0
  }'
```
</RequestExample>

## Wichtige Felder

<ResponseField name="id" type="string">API-Schlüssel-ID für nachfolgende Management-API-Aufrufe.</ResponseField>
<ResponseField name="name" type="string">Anzeigename des API-Schlüssels.</ResponseField>
<ResponseField name="key_prefix" type="string">Nicht geheimer Schlüsselpräfix für Anzeige und Support.</ResponseField>
<ResponseField name="status" type="string">Einer der Werte `active`, `inactive` oder `revoked`.</ResponseField>
<ResponseField name="limit_amount" type="number | null">Ausgabenlimit in USD als JSON-Zahl für die Anzeige. `null` bedeutet unbegrenzt.</ResponseField>
<ResponseField name="limit_amount_decimal" type="string | null">Exaktes Ausgabenlimit in USD als Dezimalzeichenfolge. `null` bedeutet unbegrenzt.</ResponseField>
<ResponseField name="used_amount" type="number">Kumulierte Nutzungskosten in USD als JSON-Zahl für die Anzeige.</ResponseField>
<ResponseField name="used_amount_decimal" type="string">Exakte kumulierte Nutzungskosten in USD als Dezimalzeichenfolge.</ResponseField>
<ResponseField name="models" type="string[]">Liste zulässiger Modelle pro Schlüssel. Ein leeres Array bedeutet, dass keine zusätzliche Modellbeschränkung auf Schlüsselebene gilt.</ResponseField>
<ResponseField name="expires_at" type="string | null">ISO-Zeitstempel, zu dem der Schlüssel abläuft, oder `null` ohne Ablaufdatum.</ResponseField>
<ResponseField name="last_used_at" type="string | null">ISO-Zeitstempel der letzten Nutzung oder `null`, wenn noch nicht verwendet.</ResponseField>
<ResponseField name="created_at" type="string">ISO-Zeitstempel der Erstellung.</ResponseField>
