---
title: "Task-Status abrufen"
openapi: "GET /v1/tasks/{id}"
description: "Rufen Sie den Status und das Ergebnis jeder asynchronen Task über die von den Create-Endpunkten zurückgegebene `poll_url` ab"
---

## Übersicht

Verwenden Sie diesen Endpunkt für ein einheitliches asynchrones Polling über verschiedene Task-Typen hinweg, z. B. Video-, Bild-, Musik- und 3D-Generierung.

Wenn eine Create-Antwort `poll_url` enthält, rufen Sie genau diesen Pfad auf. Bei neueren asynchronen Workflows kann `poll_url` auf `/v1/tasks/{id}` verweisen.

## Pfadparameter

<ParamField path="id" type="string" required>
  Die von der Create-Anfrage zurückgegebene Task-ID.
</ParamField>

## Antwort

<Note>
Ergebnis-, Fehler-, Zeitstempel- und Modellfelder werden zurückgegeben, wenn sie für den Task verfügbar sind.
</Note>

<ResponseField name="id" type="string">
  Task-Bezeichner.
</ResponseField>

<ResponseField name="task_id" type="string">
  Alias für die asynchrone Task-ID.
</ResponseField>

<ResponseField name="poll_url" type="string">
  Bevorzugte Polling-URL, wenn die Create-Antwort sie bereitstellt.
</ResponseField>

<ResponseField name="status" type="string">
  Task-Status wie `pending`, `processing`, `completed` oder `failed`. Abgebrochene Tasks werden als `failed` mit `cancelled: true` dargestellt.
</ResponseField>

<ResponseField name="cancelled" type="boolean">
  `true`, wenn ein wartender asynchroner Task vor der Ausführung abgebrochen wurde.
</ResponseField>

<ResponseField name="cancellation_status" type="string">
  Abbruchmarker. Bei erfolgreichem Abbruch `cancelled`.
</ResponseField>

<ResponseField name="data" type="array">
  Für abgeschlossene Bild-Tasks werden die generierten Bildergebnisse hier zurückgegeben. Bild-Tasks geben URLs in `data[].url` zurück.
</ResponseField>

<ResponseField name="progress" type="number">
  Optionaler Fortschrittswert. Wird nur zurückgegeben, wenn ein echter Fortschrittswert verfügbar ist; verwenden Sie `status`, um den Abschluss zu erkennen.
</ResponseField>

<ResponseField name="video_url" type="string">
  URL des Ergebnis-Assets, wenn die Task abgeschlossen wird und ein Video erzeugt.
</ResponseField>

<ResponseField name="video" type="object">
  Einzelnes Videoobjekt mit `url`, `duration`, `width` und `height`, falls verfügbar.
</ResponseField>

<ResponseField name="videos" type="array">
  Video-Array, wenn die Generierungsaufgabe mehrere Ausgaben zurückgibt.
</ResponseField>

<ResponseField name="created" type="integer">
  Zeitstempel der Erstellung.
</ResponseField>

<ResponseField name="updated" type="integer">
  Zeitstempel der letzten Aktualisierung.
</ResponseField>

<ResponseField name="model" type="string">
  Für die Task verwendetes Modell.
</ResponseField>

<ResponseField name="error" type="string | object">
  Fehlermeldung, wenn die Task fehlschlägt.
</ResponseField>

## Fehlerverhalten

Ein abgelaufener oder nicht verfügbarer öffentlicher Task kann `404 async_task_not_found` zurückgeben. Ist die Zugehörigkeit zum aktuellen API-Schlüssel nicht feststellbar, lautet die Antwort `403 task_not_owned`.

```json
{
  "error": {
    "message": "Task not found or no longer available.",
    "type": "invalid_request_error",
    "code": "async_task_not_found"
  }
}
```

## Beispiele

<RequestExample>
```bash cURL
curl "https://api.tokenlab.sh/v1/tasks/ldtask_aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa" \
  -H "Authorization: Bearer sk-your-api-key"
```
</RequestExample>

```python Python
import requests

poll_url = "/v1/tasks/ldtask_aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
response = requests.get(
    f"https://api.tokenlab.sh{poll_url}",
    headers={"Authorization": "Bearer sk-your-api-key"},
)
print(response.json())
```

```javascript JavaScript
const pollUrl = '/v1/tasks/ldtask_aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa';
const response = await fetch(`https://api.tokenlab.sh${pollUrl}`, {
  headers: { Authorization: 'Bearer sk-your-api-key' },
});
console.log(await response.json());
```
