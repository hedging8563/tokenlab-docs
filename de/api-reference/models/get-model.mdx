---
title: "Modell abrufen"
openapi: "GET /v1/models/{model}"
description: "Rufen Sie die Fähigkeiten, Preise und API-Formate eines Modells ab"
---

## Pfadparameter

<ParamField path="model" type="string" required>
  Modell-ID, wie z. B. `gpt-5.6-terra` oder `claude-sonnet-4-6`.
</ParamField>

## Antwort

<ResponseField name="id" type="string">Modell-ID.</ResponseField>
<ResponseField name="object" type="string">Immer `model`.</ResponseField>
<ResponseField name="owned_by" type="string">Hersteller des Modells.</ResponseField>
<ResponseField name="tokenlab" type="object">
  TokenLab-Modellinformationen, einschließlich Fähigkeiten, Preisen, Abrechnungseinheiten, Kontextlimits, akzeptierten API-Formaten, Operationen und Lebenszyklusstatus.
</ResponseField>

Zu den gängigen `tokenlab`-Feldern gehören:

- `capabilities`: Text-, Bild-, Video-, Audio- und andere Fähigkeiten.
- `pricing`: Aktuelle öffentliche Preise.
- `max_input_tokens` und `max_output_tokens`: Kontext- und Ausgabelimits.
- `accepted_request_formats`: Unterstützte API-Formate.
- `supported_operations`: Operationen wie Text-zu-Bild oder Bild-zu-Video.
- `lifecycle`: Verfügbarkeit, Veröffentlichungsdatum, Datum der Einstellung oder Ersatzmodell.

Einige Medienmodelle enthalten auch einen Empfehlungsstatus und eine Aktualisierungszeit. Empfehlungen können sich je nach Verfügbarkeit und Leistung ändern, daher sollten Sie deren Reihenfolge nicht fest im Code hinterlegen (hard-code).

## Beispiel

```bash
curl "https://api.tokenlab.sh/v1/models/gpt-5.6-terra"
```

```json
{
  "id": "gpt-5.6-terra",
  "object": "model",
  "owned_by": "openai",
  "tokenlab": {
    "category": "chat",
    "capabilities": ["coding", "json-mode", "prompt-cache", "reasoning", "tool-use", "vision"],
    "accepted_request_formats": ["openai_chat_completions", "openai_responses"]
  }
}
```

Ein unbekanntes Modell gibt `404 model_not_found` zurück.
