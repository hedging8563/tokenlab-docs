## Überblick

Diese Endpunkte sind für Teams gedacht, die bereits die Volc-ähnliche Seedance-Aufgabenstruktur verwenden. Die Authentifizierung erfolgt mit einem TokenLab Bearer API Key. Die zurückgegebene Aufgaben-ID beginnt mit `cgt-`; fragen Sie den Status ab, bis `status` `succeeded`, `failed`, `cancelled` oder `expired` ist.

<Warning>
Verwenden Sie hier weder das v1-Status-Enum noch dessen Response-Struct. `/v1/tasks/{id}` nutzt `pending`, `processing`, `completed` und `failed`; dieser Endpunkt nutzt das oben beschriebene v3-Enum. In v3 ist `duration` eine Zeichenkette und `error` erscheint nur bei Fehlern.
</Warning>

Siehe auch [Seedance 2.0 Videomodelle](/de/guides/seedance-2-video) und [Videogenerierung](/de/guides/video-generation).

## Antwortformat

Die Aufgabenantwort verwendet `queued`, `running`, `succeeded`, `failed`, `cancelled` oder `expired`. Erfolgreiche Aufgaben liefern `content.video_url`; optional erscheinen `content.last_frame_url`, offizielle Generierungsfelder und `usage`. `error` wird nur bei Fehlern ausgegeben. TokenLab-Felder wie `progress`, `return_last_frame`, `watermark`, `priority` oder `camera_fixed` werden nicht ergänzt.

## Beispiel

```bash
curl https://api.tokenlab.sh/api/v3/contents/generations/tasks/cgt-20260102030405-a1b2c \
  -H "Authorization: Bearer $TOKENLAB_API_KEY"
```
