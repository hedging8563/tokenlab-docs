## 建議：安裝外掛

選用：安裝已發布的供應商外掛 **0.1.0**，透過下文所述的相同 Gateway 環境提供 `TOKENLAB_API_KEY`，並只為工作階段選擇模型。外掛的入門精靈會改變預設模型，因此本指南不執行 `openclaw onboard`。保留原外掛項目與權限，在傳送請求前檢查外掛載入與模型清單。

檢查安裝程式要求的能力，並依用戶端提示確認。不要授予無關權限或改變既有外掛的權限。

```bash
openclaw plugins install @tokenlabai/openclaw-provider@0.1.0
openclaw plugins list
openclaw models list --provider tokenlab
```

```text
/model tokenlab/claude-sonnet-5 -s
/model default -s
```

## 手動提供者設定

僅在明確需要獨立的 **Responses API**、**Claude native**、**Gemini native** 或 **MiniMax native** 路由時，才使用下方的 `models.providers` 手動設定。

如果您選擇手動設定，僅設定 `tokenlab` 即足夠。僅在您明確需要 **Responses API**、**Claude native**、**Gemini native** 或 **MiniMax native** 行為時才新增其他提供者。

| 提供者 | OpenClaw `api` | 適用於 | baseUrl |
|----------|----------------|----------|---------|
| `tokenlab` | `openai-completions` | 適用於 GPT、DeepSeek、Qwen 以及大多數與 OpenAI 相容的呼叫 | `https://api.tokenlab.sh/v1` |
| `tokenlab-responses` | `openai-responses` | 期望 `/v1/responses` 語意的 OpenAI Responses 工作流程 | `https://api.tokenlab.sh/v1` |
| `tokenlab-claude` | `anthropic-messages` | 原生 Claude Messages API | `https://api.tokenlab.sh` |
| `tokenlab-gemini` | `google-generative-ai` | 原生 Gemini API 格式 | `https://api.tokenlab.sh` |
| `tokenlab-minimax` | `anthropic-messages` | 原生 MiniMax 路由 | `https://api.tokenlab.sh` |

<Warning>
僅對 `openai-completions` 與 `openai-responses` 使用 `/v1` 後綴。

像 `anthropic-messages` 與 `google-generative-ai` 這類原生提供者應使用 `https://api.tokenlab.sh`（不要加 `/v1`），否則 OpenClaw 可能會組成錯誤的供應商路徑。
</Warning>

## 前置需求

- 一個自我部署的 OpenClaw 實例
- OpenClaw **2026.9.4** 需要 Node.js `>=24.16.0 <25 || >=26.1.0`（[版本需求](https://github.com/openclaw/openclaw/blob/v2026.9.4/package.json)）。使用其他 OpenClaw 版本時，請核對對應版本的需求。
- 一個 TokenLab API Key — [在這裡取得](https://tokenlab.sh/dashboard/api?tab=keys)

## 設定

編輯您的 OpenClaw 設定檔：

- **自我部署**: `~/.openclaw/openclaw.json`

在 `models.providers` 下新增 TokenLab 提供者：

請使用執行中 Gateway 對應的 profile、`OPENCLAW_STATE_DIR` 與 `OPENCLAW_CONFIG_PATH`，合併前備份實際設定。將 `TOKENLAB_API_KEY` 放入該實例可信的全域 `.env` 或服務環境；終端 export 或專案 `.env` 不一定能供背景 Gateway 讀取。參閱[環境說明](https://docs.openclaw.ai/help/environment)。

先備份目前設定。只新增 TokenLab 項目，保留既有供應商、帳戶、預設模型與權限。如果名稱已被使用，另選名稱並同步修改指令。還原時只移除本次新增的項目，或還原其原始備份。

```json5
{
  models: {
    mode: "merge",
    providers: {
      tokenlab: {
        api: "openai-completions",
        baseUrl: "https://api.tokenlab.sh/v1",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gpt-5.6-terra", name: "GPT-5.6 Terra" },
          { id: "deepseek-reasoner", name: "DeepSeek Reasoner" },
          { id: "qwen3-coder-flash", name: "Qwen 3 Coder Flash" }
        ]
      },
      "tokenlab-responses": {
        api: "openai-responses",
        baseUrl: "https://api.tokenlab.sh/v1",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gpt-5.6-terra", name: "GPT-5.6 Terra (Responses)" },
          { id: "gpt-5.2", name: "GPT-5.2 (Responses)" }
        ]
      },
      "tokenlab-claude": {
        api: "anthropic-messages",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "claude-sonnet-5", name: "Claude Sonnet 5" },
          { id: "claude-opus-5", name: "Claude Opus 5" }
        ]
      },
      "tokenlab-gemini": {
        api: "google-generative-ai",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "gemini-3.5-flash", name: "Gemini 3.5 Flash" },
          { id: "gemini-2.5-pro", name: "Gemini 2.5 Pro" }
        ]
      },
      "tokenlab-minimax": {
        api: "anthropic-messages",
        baseUrl: "https://api.tokenlab.sh",
        apiKey: "${TOKENLAB_API_KEY}",
        models: [
          { id: "minimax-m3", name: "MiniMax M3" }
        ]
      }
    }
  }
}
```

<Info>
所有 5 個提供者使用相同的 **API Key**。您只需要一個 TokenLab 帳戶。
</Info>

<Info>
上面 `models` 陣列僅顯示常見範例。視需要為每個提供者新增更多模型 ID。
</Info>

## 使用模型

OpenClaw 仍以 `provider/model` 格式來參考模型：

在 **OpenClaw 2026.9.4** 使用 `-s` 只為目前工作階段選擇模型，保留 `agents.defaults.model`、Agent 預設設定與權限。執行 `/model default -s` 可讓本工作階段恢復使用已設定的預設模型。

```text
/model tokenlab-claude/claude-sonnet-5 -s
/model default -s
```

### 模型範例

| 提供者 | 模型參考 | 說明 |
|----------|-----------------|-------------|
| `tokenlab` | `tokenlab/gpt-5.6-terra` | OpenAI 相容路由 |
| `tokenlab-responses` | `tokenlab-responses/gpt-5.6-terra` | Responses API 路由 |
| `tokenlab-claude` | `tokenlab-claude/claude-sonnet-5` | Claude 原生 Messages 路由 |
| `tokenlab-gemini` | `tokenlab-gemini/gemini-3.5-flash` | Gemini 原生路由 |
| `tokenlab-minimax` | `tokenlab-minimax/minimax-m3` | MiniMax 原生路由 |

在 [tokenlab.sh/models](https://tokenlab.sh/zh-TW/models) 瀏覽所有可用模型。

## 何時使用哪個提供者

- `tokenlab`: 大多數通用代理與聊天使用情境的預設選擇。
- `tokenlab-responses`: 當您的 OpenClaw 工作流程明確依賴 OpenAI Responses 語意時使用。
- `tokenlab-claude`: 當您想要 Claude 的原生 Messages 行為時使用。
- `tokenlab-gemini`: 當您需要 Gemini 原生的請求/回應格式或已有 Gemini 風格的整合時使用。
- `tokenlab-minimax`: 當您想要透過 MiniMax 的原生路由時使用。

如果您不需要 Gemini 原生行為，仍然可以透過 OpenAI 相容路由使用 `tokenlab/gemini-*` 呼叫 Gemini 模型。

## 常見錯誤

<AccordionGroup>
  <Accordion title="仍在使用舊的頂層 providers 陣列">
    目前的 OpenClaw 文件使用 `models.providers`。如果您保留舊的頂層 `providers` 陣列格式，OpenClaw 可能會忽略該設定或無法如預期解析提供者前綴。
  </Accordion>
  <Accordion title="在 tokenlab-responses 忘記加上 /v1">
    `openai-responses` 映射到 TokenLab 的 `/v1/responses` 路徑，因此 `tokenlab-responses` 必須使用 `https://api.tokenlab.sh/v1`。
  </Accordion>
  <Accordion title="在 tokenlab-claude、tokenlab-gemini 或 tokenlab-minimax 新增 /v1">
    `anthropic-messages` 與 `google-generative-ai` 應使用 `https://api.tokenlab.sh`（不要加 `/v1`）。加上 `/v1` 會產生不正確的請求路徑。
  </Accordion>
  <Accordion title="OpenClaw 仍然支援原生 Gemini 嗎？">
    支援。現行 OpenClaw 文件仍包含內建的 `google` 提供者，並且也支援使用 `api: "google-generative-ai"` 的自訂提供者。因此 `tokenlab-gemini` 對於 OpenClaw 使用者來說仍然是有效的原生 Gemini 路由。
  </Accordion>
</AccordionGroup>

## 驗證設定

重新啟動同一實例後檢查模型與供應商。不帶 `--probe` 的 `models status` 不是模型測試；真實探測或對話可能消耗 token。請核對回覆與 TokenLab 請求記錄。還原時選回原模型，僅移除本次加入的項目。

```bash
openclaw gateway restart
openclaw models status
```
