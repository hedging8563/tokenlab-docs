多數工具只需更換 API 金鑰和位址就能連接 TokenLab。具體設定取決於工具使用哪種 API 格式。

| API 格式 | Base URL | 常見用戶端 |
| --- | --- | --- |
| Chat Completions (OpenAI 相容) | `https://api.tokenlab.sh/v1` | OpenAI SDK、多種聊天應用程式和框架 |
| OpenAI Responses | `https://api.tokenlab.sh/v1` | Responses 用戶端和依賴 Responses 事件的工具 |
| Anthropic Messages | `https://api.tokenlab.sh` | Anthropic SDK 和 Claude 工具 |
| Gemini | `https://api.tokenlab.sh` | 允許自訂位址的 Gemini REST 或 SDK 用戶端 |

所選模型的 `accepted_request_formats` 必須包含相同格式。串流輸出和工具呼叫還取決於模型能力與用戶端支援。設定範例請見[選擇 API 格式](/zh-Hant/guides/api-formats)。

## 狀態說明

| 狀態 | 含義 |
| --- | --- |
| **可用** | 連結頁面中的 TokenLab 設定使用用戶端公開支援的設定選項 |
| **有部分限制** | 設定適用於特定功能或驗證方式；廠商其他服務仍有各自的使用要求 |

這些狀態描述連結頁面中的設定方式。具體功能是否可用，還取決於所選模型和用戶端版本。

## 串流回應中的用量

Chat Completions 串流接受 `stream_options: { include_usage: true }`，會在串流結束前追加一個用量區塊。Responses API 不提供 `include_usage`；Responses 串流在終止事件中回傳用量。

## 自訂 API 金鑰無法取代的服務

有些產品既呼叫模型，也提供自己的線上功能。TokenLab API 金鑰可用於 BYOK 設定開放的模型請求，但無法取代第三方產品的訂閱、自動補全服務、帳戶功能或專有擴充功能。

工具升級後若設定方式改變，請以目前的整合頁面為準，不要繼續複製舊的環境變數片段。

## 使用前確認

- 工具允許為所需格式填入自訂 Base URL。
- 模型的 `accepted_request_formats` 包含該格式。
- 功能依賴串流輸出或工具呼叫時，使用實際請求驗證。
- API 金鑰僅儲存在可信任裝置或伺服器端。
- 回報問題時保留請求 ID。
