---
title: "取得 API Key 用量"
openapi: "GET /v1/management/api-keys/{keyId}/usage"
description: "返回某個使用者 API Key 的分頁用量明細。"
---

## 概覽

這個 endpoint 會回傳單一 API Key 維度的用量明細，同時不暴露實體 routing 中繼資料。

## 查詢參數

| 參數 | 型別 | 預設值 / 限制 | 說明 |
|------|------|---------------|------|
| `page` | integer | 預設 `1`，最小 `1` | 從 1 開始的頁碼 |
| `limit` | integer | 預設 `50`，最小 `1`，最大 `100` | 每頁筆數 |
| `model` | string | 最大長度 `100` | 請求時使用的模型名稱 |
| `modelVendor` | string | 最大長度 `100` | 公開模型供應商 |
| `scene` | enum | - | `chat`, `image`, `audio`, `video`, `embedding`, `rerank`, `translation`, `music`, `3d`, `realtime` |
| `startDate` | string | - | 起始時間（含），接受帶時區的 RFC3339 或 `YYYY-MM-DD` |
| `endDate` | string | - | 結束時間（含），接受帶時區的 RFC3339 或 `YYYY-MM-DD` |

如果同時提供 `startDate` 與 `endDate`，則 `startDate` 必須早於或等於 `endDate`。

## 說明

- 金額欄位僅支援 USD。`CNY` 輸入已停用，並會回傳 `400 currency_retired`。

- 回應支援分頁。
- 回應只包含公開 billing 與 reporting 欄位。
- 當底層請求已完成結算時，每條用量明細還會包含 `billing_transaction_id`。建議將它與 `request_id` 一起用於請求級對帳。
- 內部 routing 與實體渠道中繼資料會持續被隱藏。

## 範例

<RequestExample>
```bash cURL
curl "https://api.tokenlab.sh/v1/management/api-keys/key_abc123def456/usage?page=1&limit=20&scene=video&startDate=2026-03-01&endDate=2026-03-31" \
  -H "Authorization: Bearer mt-your-management-token"
```
</RequestExample>

## 重要欄位

<ResponseField name="api_key" type="object">API Key 摘要，欄位與列出、建立和更新回應相同。</ResponseField>
<ResponseField name="items" type="array">分頁後的用量明細。</ResponseField>
<ResponseField name="pagination" type="object">分頁中繼資料，包含 `page`、`limit`、`total` 和 `totalPages`。</ResponseField>
<ResponseField name="summary" type="object">依所選篩選條件彙總的總計。</ResponseField>
<ResponseField name="breakdowns" type="object">依所選篩選條件彙總的明細拆分。</ResponseField>
<ResponseField name="items[].request_id" type="string | null">用於技術支援和對帳的公開請求識別碼。</ResponseField>
