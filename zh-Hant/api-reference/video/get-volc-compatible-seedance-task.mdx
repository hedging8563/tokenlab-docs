## 概覽

這些介面面向已經使用火山風格 Seedance 任務結構的團隊。鑑權使用 TokenLab Bearer API Key。返回的任務 ID 以 `cgt-` 開頭；請輪詢狀態介面，直到 `status` 變為 `succeeded`、`failed`、`cancelled` 或 `expired`。

<Warning>
不要重用 v1 的任務列舉或回應 struct。`/v1/tasks/{id}` 使用 `pending`、`processing`、`completed`、`failed`；本介面使用上面的 v3 列舉。v3 的 `duration` 是字串，`error` 只在失敗時出現。
</Warning>

另見 [Seedance 2.0 影片模型](/zh-Hant/guides/seedance-2-video) 和 [影片生成](/zh-Hant/guides/video-generation).

## 回應結構

任務狀態使用 `queued`、`running`、`succeeded`、`failed`、`cancelled` 或 `expired`。成功任務返回 `content.video_url`；可用時還會返回 `content.last_frame_url`、官方生成欄位與 `usage`。`error` 只在失敗時出現，不會加入 `progress`、`return_last_frame`、`watermark`、`priority` 或 `camera_fixed` 等 TokenLab 擴充欄位。

## 範例

```bash
curl https://api.tokenlab.sh/api/v3/contents/generations/tasks/cgt-20260102030405-a1b2c \
  -H "Authorization: Bearer $TOKENLAB_API_KEY"
```
