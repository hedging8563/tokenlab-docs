## 概覽

使用模型提供者外掛 **OpenAI-API-compatible** 將 Dify 連接至 TokenLab。將模型類型設為 **LLM**、**Completion mode** 設為 **Chat**、**API Type** 設為 **Chat Completions API**。本指南使用 Chat Completions。

<Note>
**類型**: 框架或平台

**主要路徑**: OpenAI 相容的 chat 路徑

**支援信心**: 在範圍限制內支援
</Note>

## 先決條件

- 擁有 API 存取權限的 TokenLab 帳號
- Dify Cloud 或自行託管的 Dify

## 設定步驟

### 步驟 1：取得您的 API Key

1. 登入 [TokenLab Dashboard](https://tokenlab.sh/dashboard)
2. 開啟 [API Keys](https://tokenlab.sh/dashboard/api)
3. 建立或複製一個以 `sk-` 開頭的 API key

### 步驟 2：設定提供者

<Steps>
  <Step title="開啟模型提供者">
    在 Dify 中，前往 **Settings** → **Model Providers**
  </Step>
  <Step title="選擇 OpenAI-API-compatible">
    開啟 **OpenAI-API-compatible**。若未顯示，請先從 Dify Marketplace 安裝此模型提供者外掛。選擇 **Add model**，輸入 TokenLab 設定。
  </Step>
  <Step title="輸入 TokenLab 設定">
    使用以下數值：

    | 欄位 | 數值 |
    |-------|-------|
    | API Key | `sk-your-tokenlab-key` |
    | Model type | LLM |
    | Completion mode | Chat |
    | API Type | Chat Completions API |
    | API Base URL | `https://api.tokenlab.sh/v1` |
  </Step>
  <Step title="新增模型">
    新增您想要使用的模型，例如：
    - `gpt-5.4`
    - `gpt-5.4-mini`
    - `claude-sonnet-5`
    - `claude-opus-4-8`
    - `gemini-3.5-flash`
    - `gemini-3.1-flash-lite`
    - `deepseek-v4-flash`
  </Step>
</Steps>

### 步驟 3：測試連線

1. 選擇已新增的模型，例如 `gpt-5.4-mini`。
2. 發送測試提示詞 (prompt)
3. 確認 Dify 收到有效的回應

## 用於知識庫的 Embeddings

若要進行 RAG 與知識庫索引，請新增一個 embedding 模型，例如：
- `text-embedding-3-small`
- `text-embedding-3-large`

然後在相關的知識庫或應用程式設定中，將其設為預設的 embedding 模型。

## 建議模型角色

| 使用案例 | 建議模型 |
|----------|------------------|
| 預設聊天 | `gpt-5.4-mini`, `gpt-5.4`, `claude-sonnet-5` |
| 深度推理 | `gpt-5.5`, `gpt-5.4`, `claude-opus-4-8`, `deepseek-v4-pro` |
| 快速/經濟 | `gpt-5.4-mini`, `gemini-3.5-flash`, `deepseek-v4-flash` |
| Embeddings | `text-embedding-3-small`, `text-embedding-3-large` |

## 最佳實踐

<AccordionGroup>
  <Accordion title="以 OpenAI 外掛作為備選">
    獨立的 **OpenAI** 外掛可用於其目錄支援的模型。將自訂 Base URL 設為 `https://api.tokenlab.sh/v1`，並將 **API Protocol** 設為 **Chat Completions**；預設值可能是 Responses。它不是 OpenAI-API-compatible 的舊名稱，也不接受所有自訂模型 ID。
  </Accordion>

  <Accordion title="在迭代時使用較便宜的模型">
    在迭代過程中請使用 `gpt-5.4-mini`、`gemini-3.5-flash` 或 `deepseek-v4-flash`，僅在必要時才將繁重的工作流程切換至更強大的模型。
  </Accordion>

  <Accordion title="此設定使用 Chat Completions">
    此設定請保持 **Completion mode = Chat** 與 **API Type = Chat Completions API**。Responses 是獨立的 API 選項；本指南不設定該選項或 WebSocket 連線。
  </Accordion>
</AccordionGroup>

## 疑難排解

<AccordionGroup>
  <Accordion title="連線錯誤">
    - 確認 Base URL 完全正確為 `https://api.tokenlab.sh/v1`
    - 如果 Dify 重複了斜線，請移除結尾的斜線
    - 確認 Dify 伺服器能透過公用網際網路存取 TokenLab
  </Accordion>

  <Accordion title="401 未授權">
    - 再次檢查 API key
    - 確認該 key 在 TokenLab dashboard 中為啟用狀態
    - 確保貼入 Dify 的數值不包含多餘的空格或換行符
  </Accordion>

  <Accordion title="找不到模型 (Model Not Found)">
    - 確認模型名稱完全正確
    - 如果提供者 UI 快取了舊值，請重新新增模型項目
    - 在 TokenLab 文件或 dashboard 中檢查目前的模型可用性
  </Accordion>
</AccordionGroup>
