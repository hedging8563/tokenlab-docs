## 概覽

Codex CLI 透過 `/v1/responses` 連線至 TokenLab。所選模型的 `tokenlab.accepted_request_formats` 必須包含 `openai_responses`，功能可能因模型而異。

Codex CLI 遠端壓縮支援 `POST /v1/responses/compact`。Codex 在 `/compact` 和自動壓縮時會把目前工作階段的 `model` 放在 `body.model` 中，因此請確保要用於壓縮的模型在 Responses 路徑上可用；不要設定 `/v1/compact`。

## 系統需求

macOS、Linux 或 Windows 請依[官方 CLI 指南](https://learn.chatgpt.com/docs/codex/cli)安裝。原生 Windows 與 WSL 為不同環境，參閱 [Windows 指南](https://learn.chatgpt.com/docs/windows/windows-sandbox)。下方 npm 是一種安裝方式，並非原生二進位檔的前置需求。

## 安裝

```bash
npm install -g @openai/codex@0.149.0
```

驗證安裝：

```bash
codex --version
```

## 設定

### 第 1 步：設定 API Key

依[快速開始](/zh-Hant/quickstart)的 macOS、Linux、WSL 或 Windows PowerShell 步驟設定 `TOKENLAB_API_KEY`，避免把金鑰寫入命令歷史，再從同一終端機啟動 Codex。長期使用請透過本地秘密管理工具提供金鑰，不要把明文金鑰附加至 shell 設定檔。

### 第 2 步：設定 tokenlab.config.toml

在 Codex **0.149.0** 使用中的 `CODEX_HOME`（通常為 `~/.codex`）新增獨立的 `tokenlab.config.toml`。只在名稱未被使用時建立；修改既有 TokenLab profile 前先備份。使用 `codex --profile tokenlab` 明確載入，保留預設 `config.toml`、`auth.json`、帳戶及權限規則。不要使用舊式 `[profiles.tokenlab]` 表。正常啟動時不加此 profile 即可回到原設定。請參閱[官方 profile 設定](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles)。

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"

[model_providers.tokenlab]
env_key = "TOKENLAB_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000
```

此 WebSocket 模式是面向 Codex 用戶端的 Responses-over-WebSocket 橋接層。它只接受官方 `response.create` 事件；`stream` 為隱含行為，此 transport 不提供 `background` 或 `response.cancel`。它不是 OpenAI Realtime API，也不接受 `session.update`、`conversation.item.*`、`input_audio_buffer.*`、二進位音訊或巢狀 Realtime `response.create.response` 信封。

<Note>
若所選設定檔不存在，請建立該檔案。修改後，使用下方對應命令啟動新的工作階段。
</Note>

目前 Codex 使用 `wire_api = "responses"`，勿設定 `chat/completions`。此供應商的 `requires_openai_auth` 應省略或為 false，以使用 `env_key`。

<Note>
Responses 請求不會轉換為 Chat Completions。選用與未來欄位的支援取決於所選模型。
</Note>

## 基本用法

**啟動互動模式:**

```bash
codex --profile tokenlab
```

**直接指令:**

```bash
codex --profile tokenlab "Fix the bug in main.py line 42"
```

**指定模型:**

```bash
codex --profile tokenlab -m gpt-5.6-sol "Build a REST API server"
```

## 選擇模型

選擇目前 `tokenlab.accepted_request_formats` 包含 `openai_responses` 的模型。請用自己的程式設計工作比較候選模型，並在[模型頁](https://tokenlab.sh/zh-TW/models)查看目前價格。

## 互動指令

| 指令 | 說明 |
|---------|-------------|
| `/help` | 顯示說明 |
| `/exit` 或 `Ctrl+C` | 退出 |
| `/clear` | 清除對話 |
| `/status` | 檢視目前模型、權限與 token 用量 |
| `/model <name>` | 切換模型 |

## 驗證設定

只檢查環境變數是否已設定，不輸出其值。這項檢查無法判斷金鑰是否有效：

```bash
if [ -n "${TOKENLAB_API_KEY:-}" ]; then
  printf '%s\n' 'TOKENLAB_API_KEY is set'
else
  printf '%s\n' 'TOKENLAB_API_KEY is not set'
fi
```

啟動 Codex 後執行 `/status`，核對目前模型與權限。如果使用 profile，請啟動相同的 profile。請參閱[官方狀態命令說明](https://learn.chatgpt.com/docs/developer-commands?surface=cli#inspect-the-session-with-status)。

準備好發出真實請求後，再執行下列命令；它會使用 TokenLab 餘額。核對回覆與[請求記錄](https://tokenlab.sh/dashboard/runs?section=requests)中的對應記錄。環境檢查通過或用戶端成功啟動，都不等於請求已成功。

```bash
codex --profile tokenlab "Reply only with OK. Do not use tools or modify files."
```

## 常見用例

**程式碼審查:**

```bash
git diff | codex --profile tokenlab "Review these code changes"
```

**產生 commit 訊息:**

```bash
git diff --staged | codex --profile tokenlab "Generate a commit message for these changes"
```

**修復錯誤:**

```bash
codex --profile tokenlab "Fix the TypeScript errors in src/components/"
```

**解釋程式碼:**

```bash
cat main.py | codex --profile tokenlab "Explain what this code does"
```

## 故障排除

<AccordionGroup>
  <Accordion title="連線錯誤">
    - 驗證 `base_url` 在 tokenlab.config.toml 中是否為 `https://api.tokenlab.sh/v1`
    - 檢查網路連線
    - 確保沒有代理干擾
  </Accordion>

  <Accordion title="認證失敗">
    升級至 Codex 0.149.0 或更新版本後，若自訂供應商只依賴 `auth.json`，且 `requires_openai_auth` 未設定或為 `false`，可能會出現 `API_KEY_REQUIRED` 或 `401 Unauthorized`。本指南透過 `env_key` 從 `TOKENLAB_API_KEY` 讀取金鑰，不依賴 `auth.json`。請維持省略 `requires_openai_auth` 或設為 `false`；此設定方式不需要改成 `true`，也不需要覆寫 `auth.json`。

    - 確認實際啟用的設定或 profile 包含 `env_key = "TOKENLAB_API_KEY"`；若設定存於 `tokenlab.config.toml`，請以 `codex --profile tokenlab` 啟動
    - 確認啟動 Codex 的終端機已設定 `TOKENLAB_API_KEY` 環境變數，並在設定後從該終端機重新啟動 Codex
    - 檢查金鑰是否以 `sk-` 開頭
    - 確保該金鑰在 TokenLab 儀表板中為啟用狀態
  </Accordion>

  <Accordion title="找不到模型">
    - 檢查模型名稱是否完全相符
    - 在 [tokenlab.sh/en/models](https://tokenlab.sh/zh-TW/models) 驗證模型的可用性
  </Accordion>

  <Accordion title="Responses 原生欄位被拒絕">
    - 某些欄位僅在 TokenLab 能為所選模型與路由保證該行為時，才在 `/v1/responses` 上可用
    - 若您看到 `unsupported_request_field`，請移除該欄位或切換至不依賴該欄位的工作流程
  </Accordion>

  <Accordion title="/compact 或自動壓縮失敗">
    - Codex CLI 會呼叫 `POST /v1/responses/compact`，不是 `/v1/compact`
    - 壓縮請求使用目前工作階段的 `model`，因此該模型必須在 Responses 路徑上可用
    - 保持 `wire_api = "responses"` 和 `base_url = "https://api.tokenlab.sh/v1"`
  </Accordion>
</AccordionGroup>
