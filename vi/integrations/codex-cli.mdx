## Tổng quan

OpenAI Codex là một công cụ dòng lệnh (CLI) mã nguồn mở hoạt động như một đại lý lập trình nhẹ, có khả năng đọc, sửa đổi và chạy mã trong terminal. Nó được xây dựng trên các mô hình GPT và được tối ưu hóa cho việc tạo mã.

Đối với TokenLab, Codex CLI có thể sử dụng `/v1/responses`, nhưng bạn nên coi đó là một đường dẫn tương thích nâng cao. Một số tính năng chỉ dành cho Responses không được đảm bảo hoạt động trên mọi mô hình và đường dẫn.

Nén từ xa của Codex CLI được hỗ trợ tại `POST /v1/responses/compact`. Codex gửi `model` của phiên hiện tại trong `body.model` cho `/compact` và tự động nén, vì vậy model bạn muốn dùng để nén phải có sẵn trên đường dẫn Responses. Không cấu hình `/v1/compact`.

## Yêu cầu hệ thống

Làm theo [hướng dẫn CLI chính thức](https://learn.chatgpt.com/docs/codex/cli) cho macOS, Linux hoặc Windows. Windows nguyên bản và WSL là môi trường riêng; xem [hướng dẫn Windows](https://learn.chatgpt.com/docs/windows/windows-sandbox). npm là một cách cài đặt, không phải yêu cầu của bản nhị phân.

## Cài đặt

```bash
npm install -g @openai/codex
```

Xác minh cài đặt:

```bash
codex --version
```

## Cấu hình

### Bước 1: Thiết lập API Key

**Tạm thời (phiên hiện tại):**

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

**Cấu hình vĩnh viễn:**

Thêm vào `~/.bashrc`, `~/.zshrc`, hoặc `~/.bash_profile`:

```bash
export TOKENLAB_API_KEY="sk-your-tokenlab-key"
```

Sau đó nạp lại:

```bash
source ~/.zshrc  # or source ~/.bashrc
```

### Bước 2: Cấu hình config.toml

Hợp nhất các thiết lập này vào tệp người dùng `~/.codex/config.toml`; không thay thế toàn bộ tệp. Giữ nguyên các nhà cung cấp, tài khoản, thiết lập sandbox và quy tắc phê duyệt khác. Cấu hình nhà cung cấp và xác thực phải nằm trong cấu hình người dùng, không phải `.codex/config.toml` của dự án. Xem [hướng dẫn cấu hình chính thức](https://learn.chatgpt.com/docs/config-file/config-advanced#custom-model-providers).

Để giữ nhà cung cấp mặc định, từ Codex 0.134.0 hãy lưu ví dụ vào `~/.codex/tokenlab.config.toml` và chạy `codex --profile tokenlab`. Dùng thư mục thật nếu đã đổi `CODEX_HOME`. Không tạo bảng `[profiles.tokenlab]` cũ, ghi đè `auth.json`, đăng xuất hay đổi quyền. Khởi chạy không dùng profile này để khôi phục.

Trong mỗi nhóm lệnh bên dưới, chọn **Hồ sơ TokenLab** khi dùng `tokenlab.config.toml`. Chỉ dùng **TokenLab mặc định** sau khi hợp nhất thiết lập vào `config.toml`. Lệnh `codex` không có tùy chọn dùng cấu hình mặc định, không ghi nhớ hồ sơ đã chọn trong phiên trước.

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"

[model_providers.tokenlab]
env_key = "TOKENLAB_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000
```

Chế độ WebSocket này là cầu nối Responses-over-WebSocket cho client Codex. Nó chỉ nhận sự kiện chính thức `response.create`; `stream` là ngầm định, còn `background` và `response.cancel` không khả dụng trên transport này. Đây không phải OpenAI Realtime API và không nhận `session.update`, `conversation.item.*`, `input_audio_buffer.*`, âm thanh nhị phân hoặc envelope Realtime lồng nhau `response.create.response`.

<Note>
Tạo tệp cấu hình đã chọn nếu chưa có. Sau khi sửa, bắt đầu phiên mới bằng lệnh tương ứng bên dưới.
</Note>

Codex hiện dùng `wire_api = "responses"`, không phải `chat/completions`. Bỏ `requires_openai_auth` hoặc đặt false để nhà cung cấp dùng `env_key`.

<Note>
TokenLab chuyển tiếp các trường Responses chưa biết theo best-effort mà không âm thầm hạ cấp yêu cầu sang Chat Completions. Upstream được chọn quyết định trường hoặc tổ hợp có được hỗ trợ hay không.
</Note>

<CodeGroup>

## Các model được khuyến nghị

| Mô hình | Phù hợp cho |
|-------|-------------|
| `gpt-5.6-sol` | Lựa chọn mặc định tốt nhất cho việc lập trình và suy luận |
| `gpt-5-mini` | Phương án dự phòng nhanh hơn, rẻ hơn cho quy trình làm việc viết mã |
| `claude-sonnet-4-6` | Đánh giá mã, viết tài liệu |

## Lệnh tương tác

| Lệnh | Mô tả |
|---------|-------------|
| `/help` | Hiển thị trợ giúp |
| `/exit` or `Ctrl+C` | Thoát |
| `/clear` | Xóa cuộc hội thoại |
| `/status` | Hiển thị mô hình, quyền và lượng token đang sử dụng |
| `/model <name>` | Chuyển model |

## Xác minh cấu hình

Chỉ kiểm tra biến môi trường đã được đặt hay chưa, không in giá trị. Kiểm tra này không xác nhận khóa có hợp lệ hay không:

```bash
if [ -n "${TOKENLAB_API_KEY:-}" ]; then
  printf '%s\n' 'TOKENLAB_API_KEY is set'
else
  printf '%s\n' 'TOKENLAB_API_KEY is not set'
fi
```

Khởi động Codex rồi chạy `/status` để kiểm tra mô hình và quyền đang dùng. Nếu sử dụng hồ sơ cấu hình, hãy khởi động cùng hồ sơ đó. Xem [lệnh trạng thái chính thức](https://learn.chatgpt.com/docs/developer-commands?surface=cli#inspect-the-session-with-status).

Khi sẵn sàng gửi yêu cầu thật, hãy chạy lệnh dưới đây. Lệnh sẽ sử dụng số dư TokenLab. Kiểm tra câu trả lời và bản ghi tương ứng trong [Yêu cầu](https://tokenlab.sh/dashboard/runs?section=requests). Biến đã được đặt hoặc ứng dụng khởi động thành công chưa chứng minh yêu cầu đã thành công.

<CodeGroup>
```bash Hồ sơ TokenLab
codex --profile tokenlab "Reply only with OK. Do not use tools or modify files."
```

```bash TokenLab mặc định
codex "Reply only with OK. Do not use tools or modify files."
```
</CodeGroup>

## Xử lý sự cố

<AccordionGroup>
  <Accordion title="Lỗi kết nối">
    - Xác nhận `base_url` trong config.toml là chính xác `https://api.tokenlab.sh/v1`
    - Kiểm tra kết nối mạng
    - Đảm bảo không có can nhiễu proxy
  </Accordion>

  <Accordion title="Xác thực thất bại">
    - Xác nhận `env_key = "TOKENLAB_API_KEY"` có trong `~/.codex/tokenlab.config.toml` / `~/.codex/config.toml`
    - Xác nhận biến môi trường `TOKENLAB_API_KEY` đã được đặt
    - Kiểm tra rằng khóa bắt đầu bằng `sk-`
    - Đảm bảo khóa đang hoạt động trong dashboard của TokenLab
  </Accordion>

  <Accordion title="Không tìm thấy model">
    - Kiểm tra tên model khớp chính xác
    - Xác minh khả dụng của model tại [tokenlab.sh/en/models](https://tokenlab.sh/vi/models)
  </Accordion>

  <Accordion title="Trường native của Responses bị từ chối">
    - Một số trường chỉ có sẵn trên `/v1/responses` khi TokenLab có thể đảm bảo hành vi đó cho mô hình và đường dẫn đã chọn
    - Nếu bạn thấy `unsupported_request_field`, loại bỏ trường đó hoặc chuyển sang một luồng công việc không phụ thuộc vào nó
  </Accordion>

  <Accordion title="/compact hoặc tự động nén thất bại">
    - Codex CLI gọi `POST /v1/responses/compact`, không phải `/v1/compact`
    - Yêu cầu nén dùng `model` của phiên hiện tại, vì vậy model đó phải có sẵn trên đường dẫn Responses
    - Giữ `wire_api = "responses"` và `base_url = "https://api.tokenlab.sh/v1"`
  </Accordion>
</AccordionGroup>
