---
title: "Management API"
description: "Check Workspace balances, manage API keys, and retrieve usage and billing"
---

Use the Management API from your own backend or automation to manage a TokenLab Workspace. It uses a management token, so the program does not need a regular API key.

Create a management token in **Console → Settings**:

```bash
Authorization: Bearer mt-your-management-token
```

<Warning>
Management tokens and API keys have different roles. Use `mt-...` only with `/v1/management/*`. Use `sk-...` with model APIs such as `/v1/responses`.
</Warning>

## Endpoints

| Endpoint | Method | Use |
| --- | --- | --- |
| `/v1/management/balance` | GET | Get the Workspace balance |
| `/v1/management/api-keys` | GET | List API keys |
| `/v1/management/api-keys` | POST | Create an API key |
| `/v1/management/api-keys/{keyId}` | PATCH | Change its name, limit, models, expiration, or status |
| `/v1/management/api-keys/{keyId}/usage` | GET | Get individual usage records |
| `/v1/management/api-keys/{keyId}/billing` | GET | Get a billing summary |

## API Keys

- A new key's full secret appears only in the create response.
- `models: []` adds no key-level model restriction.
- `limitAmount: null` means unlimited. `0` prevents the key from incurring spend.
- Amounts use USD. Sending `CNY` returns `400 currency_retired`.
- `inactive` can be enabled again. Use `revoked` to retire a key permanently.

## Usage and Billing

`/usage` returns paginated records and supports model, model maker, scene, and date filters. Settled records can include `billing_transaction_id`; save it with `request_id` when you need to match a charge to a request.

`/billing` returns totals grouped by model, model maker, scene, and date. It does not include Workspace top-ups or invoices.

## Example

```bash
curl "https://api.tokenlab.sh/v1/management/balance" \
  -H "Authorization: Bearer mt-your-management-token"
```
