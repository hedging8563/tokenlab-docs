## 개요

Codex CLI는 `/v1/responses`로 TokenLab에 연결합니다. 선택한 모델의 `tokenlab.accepted_request_formats`에 `openai_responses`가 포함되어야 하며 기능은 모델마다 다를 수 있습니다.

Codex CLI 원격 압축은 `POST /v1/responses/compact`에서 지원됩니다. Codex는 `/compact` 및 자동 압축 시 현재 세션의 `model`을 `body.model`로 보내므로, 압축에 사용할 모델이 Responses 경로에서 사용 가능해야 합니다. `/v1/compact`는 설정하지 마세요.

## 시스템 요구사항

macOS, Linux, Windows는 [공식 CLI 설치 안내](https://learn.chatgpt.com/docs/codex/cli)를 따르세요. 네이티브 Windows와 WSL은 별도 환경입니다. [Windows 안내](https://learn.chatgpt.com/docs/windows/windows-sandbox)를 확인하세요. npm은 설치 방법 중 하나이며 네이티브 실행 파일의 필수 조건이 아닙니다.

## 설치

```bash
npm install -g @openai/codex@0.149.0
```

설치 확인:

```bash
codex --version
```

## 구성

### 1단계: API 키 설정

[빠른 시작](/ko/quickstart)의 macOS, Linux, WSL 또는 Windows PowerShell 절차로 키를 명령 기록에 남기지 않고 `TOKENLAB_API_KEY`를 설정한 뒤 같은 터미널에서 Codex를 실행하세요. 계속 사용하려면 로컬 비밀 관리 도구를 이용하고 셸 프로필에 평문 키를 추가하지 마세요.

### 2단계: tokenlab.config.toml 구성

Codex **0.149.0**에서는 활성 `CODEX_HOME`(보통 `~/.codex`)에 별도 `tokenlab.config.toml`을 사용하세요. 이름이 비어 있을 때만 만들고, 기존 TokenLab 프로필을 편집한다면 먼저 백업하세요. `codex --profile tokenlab`로 명시적으로 로드하므로 `config.toml`, `auth.json`, 계정과 권한 정책을 변경하지 않습니다. 예전 `[profiles.tokenlab]` 테이블은 사용하지 마세요. 이 프로필 없이 시작하면 원래 구성으로 돌아갑니다. [공식 프로필 구성](https://learn.chatgpt.com/docs/config-file/config-advanced#profiles)을 참고하세요.

```toml
model_provider = "tokenlab"
model = "gpt-5.6-sol"
model_reasoning_effort = "xhigh"

[model_providers.tokenlab]
env_key = "TOKENLAB_API_KEY"
name = "TokenLab"
base_url = "https://api.tokenlab.sh/v1"
wire_api = "responses"
supports_websockets = true
websocket_connect_timeout_ms = 15000
```

이 WebSocket 모드는 Codex 클라이언트를 위한 Responses-over-WebSocket 브리지입니다. 공식 `response.create` 이벤트만 허용하며 `stream`은 암시적입니다. 이 transport에서는 `background`와 `response.cancel`을 사용할 수 없습니다. OpenAI Realtime API가 아니며 `session.update`, `conversation.item.*`, `input_audio_buffer.*`, 바이너리 오디오 또는 중첩된 Realtime `response.create.response` envelope는 허용하지 않습니다.

<Note>
선택한 설정 파일이 없다면 새로 만드세요. 수정한 뒤 아래의 해당 명령으로 새 세션을 시작하세요.
</Note>

현재 Codex는 `wire_api = "responses"`를 사용합니다. `chat/completions`를 설정하지 마세요. `env_key`가 사용되도록 이 제공자의 `requires_openai_auth`는 생략하거나 false로 둡니다.

<Note>
Responses 요청은 Chat Completions로 변환되지 않습니다. 선택적 필드와 향후 필드 지원은 선택한 모델에 따라 달라집니다.
</Note>

## 기본 사용법

**대화형 모드 시작:**

```bash
codex --profile tokenlab
```

**직접 명령:**

```bash
codex --profile tokenlab "Fix the bug in main.py line 42"
```

**모델 지정:**

```bash
codex --profile tokenlab -m gpt-5.6-sol "Build a REST API server"
```

## 모델 선택

현재 `tokenlab.accepted_request_formats`에 `openai_responses`가 포함된 모델을 선택하세요. 자신의 코딩 작업으로 비교하고 [모델 페이지](https://tokenlab.sh/ko/models)에서 현재 가격을 확인하세요.

## 대화형 명령

| 명령 | 설명 |
|---------|-------------|
| `/help` | 도움말 표시 |
| `/exit` 또는 `Ctrl+C` | 종료 |
| `/clear` | 대화 지우기 |
| `/status` | 현재 모델, 권한 및 토큰 사용량 표시 |
| `/model <name>` | 모델 전환 |

## 구성 확인

값을 출력하지 않고 환경 변수가 설정되어 있는지만 확인합니다. 이 확인으로 키의 유효성을 검증할 수는 없습니다:

```bash
if [ -n "${TOKENLAB_API_KEY:-}" ]; then
  printf '%s\n' 'TOKENLAB_API_KEY is set'
else
  printf '%s\n' 'TOKENLAB_API_KEY is not set'
fi
```

Codex를 시작한 뒤 `/status`를 실행하여 현재 모델과 권한을 확인하세요. 프로필을 사용한다면 동일한 프로필로 시작하세요. [공식 상태 명령 안내](https://learn.chatgpt.com/docs/developer-commands?surface=cli#inspect-the-session-with-status)를 참고하세요.

실제 요청을 보낼 준비가 되면 아래 명령을 실행하세요. TokenLab 잔액을 사용합니다. 응답과 [요청 기록](https://tokenlab.sh/dashboard/runs?section=requests)의 해당 항목을 확인하세요. 환경 변수 확인이나 클라이언트 시작 성공만으로 요청 성공을 확인할 수는 없습니다.

```bash
codex --profile tokenlab "Reply only with OK. Do not use tools or modify files."
```

## 일반 사용 사례

**코드 리뷰:**

```bash
git diff | codex --profile tokenlab "Review these code changes"
```

**커밋 메시지 생성:**

```bash
git diff --staged | codex --profile tokenlab "Generate a commit message for these changes"
```

**오류 수정:**

```bash
codex --profile tokenlab "Fix the TypeScript errors in src/components/"
```

**코드 설명:**

```bash
cat main.py | codex --profile tokenlab "Explain what this code does"
```

## 문제 해결

<AccordionGroup>
  <Accordion title="연결 오류">
    - `tokenlab.config.toml`의 `base_url`이 정확히 `https://api.tokenlab.sh/v1`인지 확인하세요
    - 네트워크 연결 상태를 확인하세요
    - 프록시 간섭이 없는지 확인하세요
  </Accordion>

  <Accordion title="인증 실패">
    Codex 0.149.0 이상으로 업그레이드한 뒤, 사용자 지정 제공자가 `auth.json`에만 의존하고 `requires_openai_auth`가 설정되지 않았거나 `false`이면 `API_KEY_REQUIRED` 또는 `401 Unauthorized`가 발생할 수 있습니다. 이 가이드는 `env_key`를 통해 `TOKENLAB_API_KEY`에서 키를 읽으므로 `auth.json`에 의존하지 않습니다. `requires_openai_auth`는 생략하거나 `false`로 유지하세요. 이 설정에서는 `true`로 변경하거나 `auth.json`을 덮어쓸 필요가 없습니다.

    - 실제로 사용하는 설정 또는 프로필에 `env_key = "TOKENLAB_API_KEY"`가 포함되어 있는지 확인하세요. 설정을 `tokenlab.config.toml`에 저장했다면 `codex --profile tokenlab`으로 시작하세요
    - Codex를 시작하는 터미널에 `TOKENLAB_API_KEY` 환경 변수가 설정되어 있는지 확인하고, 설정 후 해당 터미널에서 Codex를 다시 시작하세요
    - 키가 `sk-`로 시작하는지 확인하세요
    - TokenLab 대시보드에서 키가 활성화되어 있는지 확인하세요
  </Accordion>

  <Accordion title="모델을 찾을 수 없음">
    - 모델 이름이 정확히 일치하는지 확인하세요
    - [tokenlab.sh/en/models](https://tokenlab.sh/ko/models)에서 모델 가용성을 확인하세요
  </Accordion>

  <Accordion title="Responses-native 필드 거부됨">
    - 일부 필드는 선택한 모델 및 라우트에 대해 TokenLab가 해당 동작을 보장할 수 있을 때만 `/v1/responses`에서 사용할 수 있습니다
    - `unsupported_request_field`가 표시되면 해당 필드를 제거하거나 해당 필드에 의존하지 않는 워크플로로 전환하세요
  </Accordion>

  <Accordion title="/compact 또는 자동 압축 실패">
    - Codex CLI는 `/v1/compact`가 아니라 `POST /v1/responses/compact`를 호출합니다
    - 압축 요청은 현재 세션의 `model`을 사용하므로 해당 모델이 Responses 경로에서 사용 가능해야 합니다
    - `wire_api = "responses"` 및 `base_url = "https://api.tokenlab.sh/v1"`를 유지하세요
  </Accordion>
</AccordionGroup>
