## 개요

**OpenAI-API-compatible** 모델 공급자 플러그인으로 Dify를 TokenLab에 연결합니다. 모델 유형은 **LLM**, **Completion mode**는 **Chat**, **API Type**은 **Chat Completions API**로 설정합니다. 이 가이드는 Chat Completions를 사용합니다.


## 사전 요구 사항

- API 액세스가 가능한 TokenLab 계정
- Dify Cloud 또는 자체 호스팅 Dify

## 구성 단계

### 1단계: API 키 가져오기

1. [TokenLab 대시보드](https://tokenlab.sh/dashboard)에 로그인합니다.
2. [API 키](https://tokenlab.sh/dashboard/api)를 엽니다.
3. `sk-`로 시작하는 API 키를 생성하거나 복사합니다.

### 2단계: 공급자 구성

<Steps>
  <Step title="모델 공급자 열기">
    Dify에서 **설정(Settings)** → **모델 공급자(Model Providers)**로 이동합니다.
  </Step>
  <Step title="OpenAI-API-compatible 선택">
    **OpenAI-API-compatible**을 엽니다. 없다면 Dify Marketplace에서 이 모델 공급자 플러그인을 설치하세요. **Add model**을 선택하고 TokenLab 설정을 입력합니다.
  </Step>
  <Step title="TokenLab 설정 입력">
    다음 값을 사용하십시오:

    | 필드 | 값 |
    |-------|-------|
    | API Key | `sk-your-tokenlab-key` |
    | Model type | LLM |
    | Completion mode | Chat |
    | API Type | Chat Completions API |
    | API Base URL | `https://api.tokenlab.sh/v1` |
  </Step>
  <Step title="모델 추가">
    사용하려는 모델을 추가합니다. 예:
    - `gpt-5.4`
    - `gpt-5.4-mini`
    - `claude-sonnet-5`
    - `claude-opus-4-8`
    - `gemini-3.5-flash`
    - `gemini-3.1-flash-lite`
    - `deepseek-v4-flash`
  </Step>
</Steps>

### 3단계: 연결 테스트

1. `gpt-5.4-mini`처럼 추가한 모델을 선택합니다.
2. 테스트 프롬프트를 보냅니다.
3. Dify가 유효한 응답을 받는지 확인합니다.

## 지식 베이스를 위한 임베딩

RAG 및 지식 베이스 인덱싱을 위해 다음과 같은 임베딩 모델을 추가하십시오:
- `text-embedding-3-small`
- `text-embedding-3-large`

그런 다음 관련 지식 베이스 또는 애플리케이션 설정에서 기본 임베딩 모델로 설정합니다.

## 권장 모델 역할

| 사용 사례 | 권장 모델 |
|----------|------------------|
| 기본 채팅 | `gpt-5.4-mini`, `gpt-5.4`, `claude-sonnet-5` |
| 심층 추론 | `gpt-5.5`, `gpt-5.4`, `claude-opus-4-8`, `deepseek-v4-pro` |
| 빠름/저렴함 | `gpt-5.4-mini`, `gemini-3.5-flash`, `deepseek-v4-flash` |
| 임베딩 | `text-embedding-3-small`, `text-embedding-3-large` |

## 모범 사례

<AccordionGroup>
  <Accordion title="대안으로 OpenAI 플러그인 사용">
    별도의 **OpenAI** 플러그인은 해당 카탈로그에서 지원하는 모델에 사용할 수 있습니다. 사용자 지정 기본 URL은 `https://api.tokenlab.sh/v1`, **API Protocol**은 **Chat Completions**로 설정하세요. 기본값은 Responses일 수 있습니다. 이 플러그인은 OpenAI-API-compatible의 이전 이름이 아니며 모든 사용자 지정 모델 ID를 허용하지는 않습니다.
  </Accordion>

  <Accordion title="반복 작업 시 저렴한 모델 사용">
    반복 작업 중에는 `gpt-5.4-mini`, `gemini-3.5-flash` 또는 `deepseek-v4-flash`를 사용하고, 필요한 경우에만 더 강력한 모델로 전환하십시오.
  </Accordion>

  <Accordion title="이 설정은 Chat Completions를 사용합니다">
    이 설정에서는 **Completion mode = Chat**과 **API Type = Chat Completions API**를 유지하세요. Responses는 별도 API 옵션이며, 이 가이드에서는 해당 옵션이나 WebSocket 연결을 설정하지 않습니다.
  </Accordion>
</AccordionGroup>

## 문제 해결

<AccordionGroup>
  <Accordion title="연결 오류">
    - 기본 URL이 정확히 `https://api.tokenlab.sh/v1`인지 확인하십시오.
    - Dify가 슬래시를 중복 추가하는 경우 후행 슬래시를 제거하십시오.
    - Dify 서버가 공용 인터넷을 통해 TokenLab에 도달할 수 있는지 확인하십시오.
  </Accordion>

  <Accordion title="401 인증되지 않음">
    - API 키를 다시 확인하십시오.
    - TokenLab 대시보드에서 키가 활성 상태인지 확인하십시오.
    - Dify에 붙여넣은 값에 공백이나 줄 바꿈이 포함되어 있지 않은지 확인하십시오.
  </Accordion>

  <Accordion title="모델을 찾을 수 없음">
    - 모델 이름을 정확히 확인하십시오.
    - 공급자 UI가 이전 값을 캐시한 경우 모델 항목을 다시 추가하십시오.
    - TokenLab 문서나 대시보드에서 현재 모델 가용성을 확인하십시오.
  </Accordion>
</AccordionGroup>
