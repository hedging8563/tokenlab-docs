기존 계정, 설정, 도구 권한을 유지하면서 TokenLab을 이름이 있는 별도 제공자로 추가합니다.

## Agent에게 설정 맡기기

```text
다음 안내를 읽고 Hermes를 TokenLab에 연결해 주세요:
https://docs.tokenlab.sh/ko/integrations/hermes-agent
설치된 버전과 실제 설정을 먼저 확인하세요.
기존 계정, 제공자, 기본 모델과 권한을 유지하고 백업 및 변경 내용을 보여 주세요.
키는 제가 로컬에서 입력합니다. 채팅에서 요청하거나 출력하거나 붙여넣지 마세요.
설정 로딩을 먼저 확인하고 유료 요청은 별도로 설명한 뒤 제가 선택했을 때만 실행하세요.
```

## Hermes 설치 확인

[공식 설치 안내](https://hermes-agent.nousresearch.com/docs/getting-started/installation)를 참고하세요. Apple Silicon macOS와 Windows 데스크톱 설치 프로그램, Linux 및 네이티브 Windows CLI 설치 방법을 제공합니다. 시스템 요구 사항을 확인하고 이미 설치했다면 건너뜁니다.

## 선택 사항: 복원 가능한 자동 설정

공식 Hermes **0.21.3**에서는 TokenLab Skills **0.1.3**의 설정 도구를 사용할 수 있습니다. 변경을 미리 보고 백업한 뒤 이름이 있는 제공자만 추가합니다. YAML 주석, 계정, 기본 모델과 권한은 유지합니다. 먼저 [설정 안내](https://github.com/hedging8563/tokenlab-skills/blob/900de0c4e296c0d2ed00b5d842815ed89c403503/skills/tokenlab-api-integration/references/hermes_setup.md)를 읽으세요.

`SKILL_DIR`은 설치된 `tokenlab-api-integration` 폴더로, `HERMES_PYTHON`은 `hermes --version`에 표시된 설치 폴더의 Python으로 설정하세요. macOS/Linux는 `venv/bin/python`, Windows는 `venv\Scripts\python.exe`입니다. PowerShell에서는 `$SkillDir`과 `$HermesPython`을 사용합니다. 기존 환경을 재사용하며 전역 Python 패키지를 설치하지 않습니다.

```bash
"$HERMES_PYTHON" "$SKILL_DIR/scripts/configure_hermes.py" --model gpt-5.6-luna
"$HERMES_PYTHON" "$SKILL_DIR/scripts/configure_hermes.py" --model gpt-5.6-luna --apply
```

```powershell
& $HermesPython "$SkillDir/scripts/configure_hermes.py" --model gpt-5.6-luna
& $HermesPython "$SkillDir/scripts/configure_hermes.py" --model gpt-5.6-luna --apply
```

적용 후 아래 수동 병합은 건너뛰고 도구가 출력한 디렉터리와 로딩 명령을 따르세요. `active_profile`도 확인합니다. 설정 조회는 키의 유효성을 검증하지 않습니다. `--restore`로 복원을 미리 보고 `--apply`를 추가해 원래 바이트로 복원합니다. 이름 충돌, 후속 편집, 관리 설정 또는 WSL에서는 자동 설정이 중단됩니다. 기존 설정을 유지하고 수동 경로를 이용하세요.

## 별도 제공자 설정

`HERMES_HOME`이 있으면 해당 디렉터리를, 없으면 `~/.hermes`(Windows: `%LOCALAPPDATA%\hermes`)를 사용합니다. `config.yaml`을 백업하고 다른 설정을 유지한 채 아래 항목을 병합하세요. Chat Completions와 도구 호출을 지원하는 현재 모델을 선택합니다.

활성 구성을 백업하세요. TokenLab 항목만 추가하고 기존 제공자, 계정, 기본 모델 선택과 권한을 유지하세요. 이름이 이미 사용 중이면 다른 이름을 선택하고 명령도 바꾸세요. 되돌릴 때는 추가한 항목만 제거하거나 이전 백업을 복원하세요.

```yaml
providers:
  tokenlab:
    api: https://api.tokenlab.sh/v1
    key_env: TOKENLAB_API_KEY
    transport: chat_completions
    default_model: gpt-5.6-luna
```

[API 키](https://tokenlab.sh/dashboard/api?tab=keys)에서 키를 만든 뒤 Hermes 디렉터리의 `.env` 또는 Hermes를 시작하는 프로세스 환경에 `TOKENLAB_API_KEY`로 저장하세요. 키를 대화나 제공자 YAML에 붙여 넣지 마세요.

## 설정 확인 후 요청 보내기

`hermes config get providers.tokenlab.api`로 제공자를 확인하세요. `https://api.tokenlab.sh/v1`이 표시되어야 합니다. 기존 `model` 섹션은 유지하고 아래 제공자와 모델을 명시해 새 세션을 시작하세요. 이 옵션 없이 시작하면 이전 기본값을 사용합니다. 구성 확인은 키를 검증하지 않습니다.

```bash
hermes chat --provider custom:tokenlab --model gpt-5.6-luna
```

TokenLab 잔액을 사용할 준비가 되면 짧은 텍스트를 보내고 응답과 [요청 기록](https://tokenlab.sh/dashboard/runs?section=requests)을 확인하세요. 이후 읽기 전용 도구 작업을 시도합니다. 보조 모델과 선택적 도구는 별도 제공자나 키를 사용할 수 있습니다.

## 복구 및 문제 해결

알 수 없는 제공자 오류가 나면 버전과 [현재 설정 형식](https://hermes-agent.nousresearch.com/docs/integrations/providers)을 확인하세요. 인증 오류는 키를 출력하지 않고 환경과 키 상태를 확인합니다. 되돌리려면 이전 모델 선택을 복원하고 추가한 TokenLab 항목만 제거하세요.

MCP와 Skills는 별도 확장입니다. [MCP 안내](/ko/integrations/tokenlab-mcp-server)는 API 도구를, [Skill 안내](/ko/integrations/coding-agent-skill)는 통합 지침을 제공합니다. 이 제공자 설정에는 필수가 아닙니다.
